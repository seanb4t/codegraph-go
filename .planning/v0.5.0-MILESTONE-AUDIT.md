## Audit Method Notes

- Requirements were cross-referenced across three independent sources, not read from one.
- The integration checker ran on `haiku`, which this repo has a recorded reliability finding
  against (a prior run claimed files absent that were present and skipped 3 of 12 dimensions
  on premises disprovable by `ls`). It was therefore given an explicit grounding inventory and
  a rule that any absence claim must quote the command that produced it. Its two load-bearing
  claims — the cask `sha256` match and the `INSTALL_RECEIPT.json` location — were both
  **independently re-verified by the orchestrator** before being accepted into this report.
- One orchestrator self-error is recorded for the same reason: the first sha256 comparison used
  an `rg` lookahead that this build rejects, leaving the extracted variables empty and printing
  `✗ MISMATCH` on two hashes that are byte-identical. Re-run with `awk` extraction and a
  non-empty precondition. This is the second sighting of the shape already recorded as
  `A-BROKEN-ANCHOR-CAN-FAIL-LOUD-AND-WRONG` — a broken extraction can fail loudly and wrongly,
  which is more dangerous than failing quietly.
