<objective>
Make the two checks this phase depends on actually fire, once, and record what they
did — then correct the two planning artifacts that name a mechanism which does not
exist.

Purpose: BREW-05's whole point is that a broken cask is caught before a user hits it.
Everything up to now has argued that from Homebrew's own Ruby source: a hook command's
non-zero exit raises, the cask installer re-raises after rolling back, `brew install`
exits non-zero. The argument is correct and it is still an argument. This repository's
standing rule is that a gate is not trusted until it has been demonstrated RED against
a confirmed-applied mutation, and this plan is where that happens for the install gate.

The same applies to the credential. Criterion 5 claims the tap token can write the tap
and nothing else. An App installed on one repository makes that structurally true, and
structurally true is not observed. D-17 chose one recorded refusal over a standing CI
assertion, with the gap that leaves stated rather than glossed.

Then the correction. BREW-05 in REQUIREMENTS.md and ROADMAP criterion 3 both name a
cask `test:` block. Homebrew Casks have no `test` stanza — it is formula vocabulary,
`brew test` operates only on formulae, and the pinned GoReleaser cask struct exposes no
such field. Both artifacts have to say what the mechanism actually is. The order
matters: the amendment is written after the proof and cites it, because an amendment
written first would pre-satisfy the very criterion it amends.

Output: `03-EVIDENCE.md` with two recorded RED observations and one recorded refusal,
two corrected planning artifacts, and user-facing documentation carrying the install
path with its release-dependent claims explicitly marked pending.
</objective>
