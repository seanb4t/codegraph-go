<objective>
Move `internal/mcp`'s backend from `mark3labs/mcp-go@v0.56.0` to
`modelcontextprotocol/go-sdk@v1.7.0` behind the `Server` seam SDK-02 already
built, and prove the whole stdio path still works end-to-end.

Purpose: this is the phase's load-bearing change. Every other plan either
enables it (02-02), asserts a property of it (02-03), finishes it (02-04), or
reviews its wire output (02-05).

Output: a `serve --mcp` process whose `initialize`, `tools/list` and
`tools/call` responses are produced entirely by go-sdk, with `internal/mcp`'s
own test suite green.

**Migration shape (resolving CONTEXT's Claude's Discretion): replace in place,
not sibling.** The sibling option's stated benefit was "the before/after diff is
a one-command comparison" — but the before side is already on disk as Phase 1's
23 frozen transcripts, so a sibling implementation would buy nothing and cost a
duplicate 8-tool registration surface. `mark3labs/mcp-go` stays in `go.mod`
through this plan only because four test files outside `internal/mcp` still
import its client; plan 02-04 removes it.

**`BuildServer`'s return type (resolving the second discretion item):** it
becomes `*mcp.Server` (go-sdk's concrete type). It is not a production leak —
`internal/cli` reaches this package only through `NewStdioServer`/`Server`, and
`internal/cli/archtest` proves it. All call sites are `internal/mcp`'s own
package tests.

**The `annotations` hints (third discretion item): preserved exactly as frozen.**
`readOnlyHint:false, destructiveHint:true, idempotentHint:false,
openWorldHint:true` are carried over byte-for-byte. Correcting them would be a
semantic change no requirement in this phase asks for; CONTEXT's `<deferred>`
already routes that to Phase 3.
</objective>
