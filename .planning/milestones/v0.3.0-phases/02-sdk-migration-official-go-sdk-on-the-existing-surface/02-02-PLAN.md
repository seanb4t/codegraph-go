<objective>
Unblock the phase. `task check:transcript-freeze` is a **blocking** pull-request
gate that fails when a PR changes a frozen wire-oracle transcript together with
`internal/mcp/*.go` or the MCP dependency line in `go.mod` — which is exactly and
unavoidably what Phase 2 does.

Purpose: this was verified, not inferred. Run against the current branch:

    TRANSCRIPT_FREEZE_BASE=main task check:transcript-freeze

already exits 1 today, naming all 23 transcripts and eight `internal/mcp` files.
Phase 2 makes it strictly worse and impossible to avoid. The guard's own advice
("split this into two pull requests") is not available here: the wire-oracle test
job is a blocking PR leg too, so a migration PR without regenerated transcripts
is red on `TestFrozenTranscriptsMatch`, and a transcript-only PR without the
migration is red for the opposite reason. There is no ordering of two PRs in
which both are green.

`02-CONTEXT.md` § Canonical References already records the resolution in
principle: Phase 1's D-03 "CI cross-change guard still stands, its 'Phase 2 =
frozen, no exceptions' clause does not." This plan implements that supersession
as one narrow, self-expiring, source-level exemption — the same escape-hatch
shape `internal/mcp/archtest/protocol_version_test.go` already documents for
VRFY-02.

Output: a guard that lets the one-time SDK-01 swap through, loudly, and keeps
failing for everything else.

**Scope note:** `tools/transcriptfreeze` is a CI guard, not the wire-oracle
harness. ROADMAP criterion 2's "Phase 1's harness code is unmodified" covers
`test/wireoracle/`, which this plan does not touch.
</objective>

  <action>
Add an unexported predicate to `classify.go` that reads the same go.mod diff
string `MCPDependencyTouched` reads and reports true only when BOTH hold: some
line begins with a single `-` (excluding the `---` file header) and contains
`github.com/mark3labs/mcp-go`, AND some line begins with a single `+`
(excluding `+++`) and contains `github.com/modelcontextprotocol/go-sdk`. Reuse
`mcpSDKModulePrefixes`' entries by index or by named constants rather than
retyping the module paths, so the exemption can never name a module the guard
itself does not consider an MCP SDK.

Add a `SwapExemption bool` field to `Verdict`. In `Classify`, compute the
predicate once; when the collision condition
(`len(transcripts) > 0 && (len(serverChanges) > 0 || depTouched)`) holds AND the
predicate is true, set `SwapExemption` true, leave `Violation` false, and set
`Reason` to an exemption notice that names both sides of the collision that was
waived and states the three facts a reviewer needs: that this is SDK-01's
one-time mark3labs-to-go-sdk transition; that `02-CONTEXT.md` D-01/D-02/D-03
replaced byte-identity with semantic equivalence plus one human diff read, so
these transcripts are expected to move; and that the exemption is self-expiring
because once mark3labs is absent from `go.mod` no later diff can produce a
removal line for it.

In `main.go`, print the exemption notice to stderr and return 0 when
`SwapExemption` is true. An exempted run must be visible in the CI log, never a
silent pass — that is the difference between an exemption and a hole.

Do not add any environment variable, flag, or author-editable file that can
trigger the exemption. The go.mod diff shape is the only key, and it is a shape
this repository can produce exactly once.

Extend `classify_test.go` with one table case per bullet in `<behavior>`,
following the file's existing case-struct style. The three cases that must
still report `Violation: true` are the non-vacuity proof — without them the
exemption is indistinguishable from deleting the guard.
