<objective>
Build the `fragment-required` gate. A pull request whose changed files touch shipped code (`cmd/**` or `internal/**`, excluding `*_test.go` and anything under a `testdata/` directory) fails unless it adds a changelog fragment under `.changes/unreleased/` or carries a reasoned `changelog-exempt` marker. The gate fails closed whenever it cannot see the change (GATE-01…GATE-04).

All three tasks work on the milestone branch `gsd/v0.15.0-milestone`. Plan 04-03 cherry-picks this plan's code commits onto a branch off `main` (D-05, D-06), so every code commit stays free of `.planning/` paths and uses a `ci:` or `test:` subject.

The plan leads with a tracer. Task 1 is RED first. It wires one path through every layer this phase adds:
- the stdlib unittest suite,
- the verdict function and its gh-fetching `main()`,
- the `check:fragment-required` Taskfile target,
- the `pull_request_target` workflow,
- the shape-test fixture registration that puts the workflow under `TestWorkflowRunBodiesInvokeTask`.

Its end-to-end check runs `task check:fragment-required` against a stub `gh` on PATH, in both directions. The stub is our test double; nothing calls GitHub (D-01).

Two expansion tasks follow:
- Task 2 (TDD, RED then GREEN) adds the exemption marker (GATE-02), the three distinct fail-closed states (GATE-03), the completeness cross-check against the PR's `changed_files`, PR-context validation, and rename handling.
- Task 3 adds `check:fragment-policy` with its executed-count guard and wires it into ci.yml's `test` job (D-10, rule 84d1gfpywd).

TDD mode applies at task level. The tracer starts red, and Task 2 is a RED/GREEN task. Never gate on `gsd-tools check tdd-red-evidence`. RED evidence is the `test(04-01):` commit landing before its implementation, plus the pasted unittest `FAIL:` transcript (rule x1cjy9vyhq).
