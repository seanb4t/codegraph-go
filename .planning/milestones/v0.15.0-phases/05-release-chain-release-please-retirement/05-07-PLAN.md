Decisions this plan implements or makes (two-way doors):
- **Census as a recorded instrument, not a committed Taskfile target.** D-09 asks for "a plain grep census, positive-controlled". REL-14 is a one-time retirement proof, and its instrument is recorded verbatim in 05-CENSUS.md, so it can be re-run the way Phase 3 re-ran v0.14.0's. This follows the 04-02 precedent. A permanent CI target would be ceremony D-01 asks to avoid. RESEARCH's Wave 0 suggested a target; the reason for not adding one is stated here.
- **Exclusions: exactly REL-14's three clauses, no more (D-09, D-11).** D-09 asks for "exactly the requirement's exclusions": `.planning/`, `CHANGELOG.md` history, this milestone's own notes. `.changes/unreleased/` is not an added exclusion. D-11, the maintainer's decision at plan time (2026-10-14), records it as the concrete path of the third clause, "this milestone's own notes". Between releases, `.changes/unreleased/` holds exactly the fragments that `changie batch` turns into the next release's notes, which here are v0.15.0's: this milestone's own notes. Once batched, they become `.changes/v0.15.0.md`, which D-09 already counts as `CHANGELOG.md` history. Pathspec per clause: `.planning/` → `:(exclude).planning/`; `CHANGELOG.md` history → `:(exclude)CHANGELOG.md` and `:(exclude).changes/v*.md`; this milestone's own notes → `:(exclude).changes/unreleased/`. No other `.changes/` path is excluded (`.changes/header.tpl.md` stays in scope, D-11), and no other path anywhere is. D-11 reads the existing requirement clause, so REQUIREMENTS.md and ROADMAP.md are not amended for it, and Phase 5's closing fragment may name the retired tool. The positive control proves the boundary: a plant in `.changes/header.tpl.md` is found, a plant under `.changes/unreleased/` is not.
- **Instrument scope.** Tracked files only (`git grep`, `git ls-files`), plus an on-disk absence check for the three paths. Untracked local caches (for example a tool's `.boost/`) are not repository content and would make the result machine-dependent.

Risk named, not planned around (memory jc6h9cf1qm): until the milestone merges, the retired workflow stays live on `main`. If `main` cut a release during this phase, the main→milestone merge needs a verbatim seed `.changes/vX.Y.Z.md` in the same commit. Phase 6 begins at the milestone merge.
