<objective>
Make the installed package self-describing. A sidecar manifest next to SKILL.md
records which binary version wrote the package and a content hash for every
artifact it wrote, so "which version is installed" is observable from the
installed files rather than inferred, and so `codegraph upgrade` has something to
discover in Plan 04.

**Identity model decision (assumption-delta: pluralization).** The manifest is
plural by construction — one per (target, location) pair, physically sidecar to
the artifacts it describes. It is deliberately **not promoted** to a single
machine-global registry of everything codegraph ever installed. A per-tree
sidecar cannot go stale relative to the tree it describes, and it is discoverable
by two `os.Stat` calls against fixed paths rather than a filesystem walk. The
`location` field is kept inside the JSON even though the path already encodes it
(RESEARCH Open Question #2) so the record stays self-describing if discovery
logic ever moves somewhere without access to which candidate path matched.

Purpose: satisfy AGENT-03's version-observability half (D-03, D-04) and supply
D-05's drift signal, using one mechanism rather than two.
Output: a manifest written on install, removed on uninstall, and idempotent.
</objective>

  <action>
Create `internal/agents/manifest.go`.

Define the record as a Go struct with explicit JSON tags, so the on-disk schema
is readable from one place: `schema_version` (int, starts at 1),
`codegraph_version` (string), `installed_at` (string, RFC3339),
`location` (string), and `files` (map of relative artifact key to hash string).
Name the type `skillManifest`. Keep `location` even though the manifest's own
path already encodes it — it costs nothing, keeps the record self-describing for
any future `codegraph install --status` surface, and avoids a bug class where
discovery logic that no longer knows which candidate path matched has to
re-derive it.

Use three stable `files` keys, chosen so they read as artifact identities rather
than absolute machine paths: `skills/codegraph/SKILL.md`,
`hooks/session-nudge.sh`, and `settings.json#hooks.SessionStart`. The third key's
trailing fragment is deliberate — it names a *portion* of a file, because the
hooks registration is not a whole physical file that codegraph owns.

Add `hashContent(b []byte) string` returning `"sha256:"` followed by the
lowercase hex encoding of `sha256.Sum256(b)`, via `encoding/hex`.

Add `hashOwnedHookBlocks(blocks []any) (string, error)`: run the blocks through
`normalizeJSON`, marshal with `encoding/json` (whose map-key output is sorted, so
the byte sequence is deterministic for a given structure), and hash the result.
Hash only the codegraph-owned blocks — never the containing settings.json.
Hashing the whole file would report drift on every unrelated user edit, which
would make D-05's silent overwrite apply far wider than D-05's own rationale
intends, since D-05 is scoped to codegraph-authored package content and not to a
file shared with the user (RESEARCH Pitfall 5).

Add `readManifest(path string) (skillManifest, bool, error)` built on
`readJSONFileStrict`'s three-outcome contract: absent yields a zero manifest and
`false`; unreadable or undecodable yields the error; present and decodable yields
the manifest and `true`. Do not fall back to a zero manifest on a parse failure —
the same reasoning as the settings.json path applies, and a manifest codegraph
cannot read is a manifest whose recorded hashes cannot be trusted to decide
anything.

Add `writeManifest(path string, m skillManifest) (FileResult, error)`. Read the
existing manifest first. If it exists and its `schema_version`,
`codegraph_version`, and `files` map all match `m`'s, return `ActionUnchanged`
and write nothing — deliberately preserving the stored `installed_at` rather
than refreshing it. This is load-bearing: a manifest that stamped the current
clock on every run would make a second `install` produce a different file and
break AGENT-01's idempotency, and the timestamp's honest meaning is "when this
content was installed", not "when install last ran". Otherwise set `installed_at`
to the current time in RFC3339 and write via `writeJSONFile`, reporting
`ActionCreated` or `ActionUpdated`.

Add `ConfiguredSkillLocations(id TargetID) []Location` — exported, because Plan
04's CLI-layer refresh needs it. For `Claude`, probe exactly the two fixed
candidate manifest paths (`claudeManifestPath(LocationGlobal)` and
`claudeManifestPath(LocationLocal)`) with `readManifest` and return the locations
whose manifest read succeeded and returned present. Return nil for any other
target id, since this phase is Claude-only by scope. Do not walk the filesystem:
Claude-only scope makes discovery two stat calls, and anything more general is
unneeded generality for a phase deliberately narrowed to one agent.

In `internal/agents/claude.go`, add `claudeManifestPath(loc Location) (string, error)`
returning `claudeSkillDirPath(loc)` joined with `.codegraph-manifest.json`,
mirroring the existing global/local helper shape. The dot prefix keeps the file
out of any future recursive skill-content scan and signals "codegraph-internal,
not skill content" the same way `.codegraph/` itself does at the project root.

Record in the file's package-level comment that the manifest hash is a drift
signal only and is not a tamper-detection control — it protects a file any local
process can rewrite and carries no signature. This is the prohibition recorded in
this plan's `must_haves.prohibitions`; a later reader must not mistake the hash
for a security boundary.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk manifest → codegraph's decision logic | a file any local process can rewrite is read back and its recorded hashes influence reporting |
| shared `settings.json` → the manifest's hooks hash | only a fragment of a co-inhabited file is codegraph's own, and the hash must not overreach |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-02 | Tampering | `readManifest` over `.codegraph-manifest.json` | medium | mitigate | Built on `readJSONFileStrict`: an unreadable or undecodable manifest returns an error rather than a zero-valued manifest, so codegraph never acts on hashes it could not actually read. |
| T-07-07 | Repudiation | the manifest hash mistaken for tamper-evidence | low | accept | Documented in `manifest.go`'s package comment as an advisory drift signal only. Accepting this is deliberate: the file carries no signature and any local process can rewrite it, so a tamper-detection claim would be false. |
