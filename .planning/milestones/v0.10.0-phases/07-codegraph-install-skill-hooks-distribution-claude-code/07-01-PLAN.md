<objective>
Prove the whole Phase 7 vertical end-to-end on one path: the running binary's own
embedded copy of Phase 6's `.claude/` package reaches Claude Code's real read
locations through a single `codegraph install`, and a second install changes
nothing.

This is the tracer slice. It touches every layer the phase will modify — the
build-time embed, the location-aware path resolution, the strict read gate, the
array-scoped JSON merge, the atomic write discipline — with one entry point wired
through to the far end. Later plans expand out from it (uninstall, the read-error
matrix, the manifest, upgrade auto-refresh); none of them re-litigate the
architecture this slice proves.

**Identity model decision (assumption-delta: pluralization).** `hooks.SessionStart`
is an *array of independent peer blocks*, not a single named key like
`mcpServers.codegraph`. codegraph is **added alongside**, never **promoted** to
"the" SessionStart registration. Ownership identity is the pair (event,
command-string) — never (event, matcher), because a matcher value like `startup`
is not unique to codegraph and a user may legitimately own their own block under
it (RESEARCH Pitfall 1).

Purpose: catch an architectural dead-end after one commit rather than after four.
Output: a working, committed, production-quality install path for the Claude Code
skill package at both locations.
</objective>

**`internal/agents/shared.go` — three new helpers.**

`readJSONFileStrict(path string) (map[string]any, bool, error)` returns
(decoded object, file-existed, error) and distinguishes three outcomes where
`readJSONFile` collapses to two. Absent file: empty map, `false`, nil error.
Any other read failure: nil map, `false`, the wrapped error. Present but not
decodable as a JSON object: nil map, `true`, an error naming the path and telling
the operator to fix or remove it manually. This is deliberately the opposite
posture from `readJSONFile`'s documented empty-map fallback — that fallback is
correct for the MCP-entry and CLAUDE.md paths it already governs and wrong for
this phase's own roadmap success criterion 4. Model the switch on
`internal/githooks/githooks.go`'s read switch; do not modify `readJSONFile`
itself in this task.

`writeHookEntry(path, event string, ownBlocks []any, ownCommands []string) (FileResult, error)`
is the array-scoped analog of `writeMcpEntry`. It reads via `readJSONFileStrict`
and returns the error unwritten if the read failed. It locates the top-level
`hooks` object and the `hooks[event]` array, treating a missing one as empty. It
partitions the array into blocks codegraph owns and blocks it does not: a block
is owned when its `hooks` sub-array contains an entry whose `command` string
equals one of `ownCommands`. Never treat the block's `matcher` value as the
ownership key. If the owned partition already `jsonDeepEqual`s the normalized
`ownBlocks`, return `ActionUnchanged` and write nothing. Otherwise rebuild the
array as the unowned blocks in their original relative order followed by
`ownBlocks`, set it back, and write via `writeJSONFile`. Report `ActionCreated`
when the file did not exist, `ActionUpdated` otherwise. Every unrelated event key
and every unowned block under the same event is carried through untouched.

`atomicWriteExecutableFile(path, content string) error` calls
`fsatomic.WriteFile` and then `os.Chmod(path, 0o755)`. `fsatomic.WriteFile`
preserves an existing file's mode but defaults a brand-new file to `0o644`, so
the script written through the unmodified primitive would be non-executable and
Claude Code's SessionStart dispatch would fail with a permission error the user
is unlikely to notice — regressing Phase 6's NUDGE-01 for every fresh install
(RESEARCH Pitfall 3). Do not modify `internal/fsatomic`.

Also add `writeEmbeddedFile(path, content string, executable bool) (FileResult, error)`:
read the current bytes, return `ActionUnchanged` without writing when they already
equal `content`, otherwise write through `atomicWriteFile` or
`atomicWriteExecutableFile` and report `ActionCreated`/`ActionUpdated`. This is
what makes the non-JSON artifacts raw-byte idempotent.

**`internal/agents/claude.go` — path helpers and Install wiring.**

Add four location-aware helpers mirroring `claudeConfigPath`'s exact
global/local branch shape. `claudeSkillDirPath(loc)` resolves to
`.claude/skills/codegraph` for local and `<home>/.claude/skills/codegraph` for
global. `claudeSkillFilePath(loc)` is that directory joined with `SKILL.md`.
`claudeHooksScriptPath(loc)` resolves to `.claude/hooks/session-nudge.sh` for
local and `<home>/.claude/hooks/session-nudge.sh` for global.
`claudeHookCommand(loc)` returns the string written into settings.json: for
local, the literal `${CLAUDE_PROJECT_DIR}/.claude/hooks/session-nudge.sh`,
byte-identical to Phase 6's dogfooded fragment so
`TestHookRegistrationMatchesFragmentAndScript` stays green; for global, the
fully-resolved absolute result of `claudeHooksScriptPath(LocationGlobal)`. Use
the resolved absolute path rather than a literal tilde — RESEARCH Assumption A3
flags tilde expansion in a shell-form hook command as unverified against a live
session, and resolving it here costs nothing and removes the assumption entirely.
Copying Phase 6's project-relative command verbatim into a global install is
RESEARCH Pitfall 4: the registration would name a path that exists in no project
but this one.

Add `claudeSessionStartBlocks(loc Location) ([]any, []string, error)`. It decodes
the embedded hooks fragment with `encoding/json`, reads `hooks.SessionStart`,
and rewrites every `command` field whose value equals the fragment's literal
project-relative command into `claudeHookCommand(loc)`. It returns the rewritten
blocks and the single-element list of owned command strings that `writeHookEntry`
uses for identity. Deriving the blocks from the embedded fragment rather than
re-authoring them in Go is what keeps Phase 6's `.claude/` the canonical source
(Phase 6 D-04) — do not hand-write matcher literals.

Extend `claudeTarget.Install` with three new steps appended after the existing
AutoAllow step, each following the established
`resolve-path-or-append-error, then recordFile(&result, path, fr, err)` shape:
write the embedded SKILL.md to `claudeSkillFilePath(loc)`; write the embedded
script to `claudeHooksScriptPath(loc)` as executable; merge
`claudeSessionStartBlocks(loc)` into `claudeSettingsPath(loc)` under the
`SessionStart` event via `writeHookEntry`. Route every one of these through
`recordFile`/`recordAction` — never a bare `if err == nil` append — so an I/O
error can never present as a no-op (CR-01).

Per D-01 the new steps follow the existing `--location` flag with no
special-casing, exactly as the MCP entry and CLAUDE.md marker block already do;
no new CLI flag is added. Per D-02 no guard is added to suppress the skill in
unindexed repositories — that consequence is accepted, and Phase 6's own
runtime `.codegraph/` check inside the script plus SKILL.md's
decision-procedure-first structure are the whole mitigation.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| binary → user's `~/.claude/` and `./.claude/` | codegraph writes into directories owned by a third-party tool and co-inhabited by user-authored content |
| existing on-disk settings.json → codegraph's read-modify-write | untrusted-shape input (a file codegraph did not write and cannot assume is well-formed) crosses into a write path |
| embedded FS → installed artifacts | build-time content crosses into the user's runtime execution surface (a shell script Claude Code will execute) |

The permissive `readJSONFile` empty-map fallback is explicitly not reused here. Full {install,uninstall}×{read-error,malformed} matrix proven in Plan 02. |
