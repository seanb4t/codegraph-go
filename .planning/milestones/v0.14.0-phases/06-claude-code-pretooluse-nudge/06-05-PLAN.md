Planner notes:
- **Orchestrator amendment (2026-09-19, after 06-04):** 06-04 found that `isOwned` treats a block as owned when ANY of its handlers carries an own command, so the three-handler Bash block let a hand-edit of ONE handler be overwritten via its two unedited siblings — against NUDGE-06 "a hand-edited own entry duplicates rather than overwrites" and the `242ec0a` rule. Fix without touching ownership code: one handler per block (three Bash blocks). Claude Code dedup of same-command handlers across blocks is one of the five unconfirmed points; 06-06's live session exercises `rg` and `find`, not only `grep`, to settle it.
- Dogfood side effect (expected, harmless): once `.claude/settings.json` registers the guard, Claude Code
  sessions in this repository (including GSD executors) may run it. This repo is indexed, the checked-in
  guard is unrendered, so it falls back to the `codegraph` on PATH — today Homebrew v0.13.0, which has no
  `hook` subcommand, exits 1, and the guard still exits 0 silently. Once a release carrying this phase is on
  PATH, sessions here get the nudge at most once a minute per key — which is the dogfooding D-13 asks for.
- The `note:` goes to stderr, plain: printAgentResults already resolves colour once per RunE (Phase 4
  rule) and owns stdout's per-agent report and its goldens; an advisory about flag scope does not belong in
  either.
- The pre-existing `install --yes` discards an explicit `--target` todo (CONTEXT deferred) affects which
  targets resolve; these tests use explicit `--target` without `--yes`.
- TDD: Tasks 1 and 2 commit failing tests first; paste `--- FAIL:` lines. Sequential by design;
  GOTOOLCHAIN=go1.26.6 on every Go command.

Output: RED/GREEN pairs, the dogfood registration, regenerated reference, Family (e).
