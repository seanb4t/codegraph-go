new CI-only step that compares it against the live `protect-main` ruleset with exact set equality,
hard-failing on any API problem — and watch that step go RED against the divergence that exists today
(fixture asserts `goreleaser check`, live does not require it).

**What are we testing, and why?** We are testing that what this repo THINKS gates `main` is what
GitHub ACTUALLY gates `main` with, in both directions (D-05): a context required live but missing
from the fixture is an under-assertion; a context in the fixture but not required live (today's
`goreleaser check`) asserts a requirement that does not exist. RESEARCH found the two already
disagree — nobody had checked the second direction. We are NOT testing GitHub's API or `jq`; the
script's own positive control (a planted extra context must be reported) is what proves the
comparator can fail, and the live RED today is the incident shape.

this design removes (D-06). The D-08 ruleset change and the flip to 8 entries are plan 02-04's job;
this plan lands the mechanism RED and honest.
