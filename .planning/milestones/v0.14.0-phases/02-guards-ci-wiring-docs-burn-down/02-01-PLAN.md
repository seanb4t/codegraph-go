<objective>
Prove, with no code change, that `web:drift` already fails against the exact `98cd41dd` incident
shape on a clean checkout — the shape WINDOWS #29 claimed the gate was blind to — and reword the
requirement and roadmap criterion so the ledger's declined "paired assertion" fix cannot be
re-litigated.

**What are we testing, and why?** We are testing whether the committed gate, as CI runs it (clean
checkout, `find web/build` == the git tree), goes RED on the one real incident that ever fooled a
developer. We are NOT testing git staging hygiene: D-01 established that a `find`-vs-`git ls-files`
set assertion would only report that the developer forgot to stage what they built — a local
misread that costs one CI round trip, not a gate blind spot. A guard proven RED once against the
real incident is worth more than a new assertion that has never failed.

Purpose: GRD-09 is the milestone's headline "guard that could pass vacuously" item, and RESEARCH
Pattern 1 reproduced the RED live (exit 201, SOURCE half MATCH at 108 files, OUTPUT half 32-vs-22
with digests 8658e6fe… vs a76add11…). This plan turns that session-local observation into a
committed mutation-log entry and a corrected requirement text. It deliberately does NOT close
WINDOWS #29 itself: `.planning/WINDOWS.md` is tool-owned and has exactly one writer in this phase
(plan 02-07), so parallel wave-1 plans never race the ledger.

Output: `02-MUTATION-LOG.md` (Family (a)), the reworded GRD-09 requirement and ROADMAP criterion 1.
