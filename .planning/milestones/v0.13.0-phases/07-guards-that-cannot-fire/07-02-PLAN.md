<flagged_assumptions>
Surfaced from the spec-less probe fallback (§C). Three items belong to this plan (GRD-02 x3).

1. **GRD-02 / the two-scope split, and why it is not a weakening.** D-01 forbids `internal/query` from depending on the `internal/indexer` root. `internal/query/engine_test.go` is an **in-package** test file (`package query`) that imports `internal/indexer` today to build fixtures by running the real indexer. With `Tests: true` — the precedent's setting, and the setting that catches an import smuggled into a `_test.go` file — that package variant resolves the forbidden root, so a single-scope rule goes RED on day one for the wrong reason. CONTEXT.md's discretion clause anticipated exactly this and said to *document why rather than weaken the set*. The resolution taken here: the **wire-layer** set is enforced over **every** loaded variant including test variants (nothing legitimately reaches it, and a test-only wire import is precisely the smuggling case `Tests: true` exists to catch); the **indexer-root** rule is enforced over the **production compilation unit only**, with the reason recorded in the package doc naming `engine_test.go`. This is a scoping decision, not a set reduction — the forbidden path is not removed. **Flagged for the reviewer:** if the reviewer judges that scoping to be a weakening, the alternative is to rework `engine_test.go` to build its fixture store without the indexer, which is a test refactor outside this phase's boundary.
2. **GRD-02 / load pattern breadth.** The loader is assumed to load `github.com/seanb4t/codegraph-go/internal/query/...` rather than the whole module, since `NeedDeps` populates the transitive graph regardless of load breadth and a narrower pattern is materially faster. No source artifact specifies the pattern. The zero-package guard and the explicit "production `internal/query` package was found" assertion are what keep a mis-typed pattern from reading as a pass.
3. **GRD-02 / the transitive-depth witness.** `internal/parser` is asserted present-but-not-directly-imported as proof the walk went deeper than one hop. This is a chosen witness, not a specified one: if `internal/query` ever imports `internal/parser` directly, the assertion fires for a benign reason. The failure message must therefore tell the reader to pick another transitive-only witness rather than to delete the assertion.
</flagged_assumptions>
