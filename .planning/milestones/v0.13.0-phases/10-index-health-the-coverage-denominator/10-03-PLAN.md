<objective>
Give the `c/` namespace the same incremental lifecycle `f/` records already have: on every `Sync`, diff the freshly-discovered exclusion set against the stored namespace, upsert what is new or changed, prune what is gone, stamp `Meta.has_coverage` at both meta-write sites, and make an exclusion-only change count as a real change rather than a no-op — so a daemon-driven repo never reports a stale or unknown denominator after the first sync.

Purpose: D-07's "Sync upserts per path and prunes paths no longer present" is what keeps the recorded reasons TRUE across a long-running daemon; without it the tracer's from-scratch write would rot on the first incremental cycle, and a pre-Phase-10 graph would stay "unknown" forever unless fully re-indexed.

Output: `synccoverage.go` (pure diff + stage helpers), `sync.go` wired at both write sites with the no-op gate extended, and two test files proving upsert, prune, backfill, mtime-refresh preservation, and the true no-op.
</objective>
