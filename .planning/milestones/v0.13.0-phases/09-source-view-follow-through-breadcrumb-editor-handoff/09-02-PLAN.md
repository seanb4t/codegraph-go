<objective>
Make the editor link work with NO flag: at `codegraph ui` startup, look for the user's editor on PATH
and in the platform's application directories — VS Code, then Cursor, then the JetBrains family — and
select the first hit's preset as the server default, with provenance the picker can show. Discovery
runs exactly once, probes only, never launches, and never blocks startup when nothing is found.

the box. D-14 makes discovery the third rung of the precedence chain plan 09-01 already built; this
plan supplies the rung and re-points one argument.

`internal/cli/editordiscovery.go`. Package doc states D-15 in its own words: startup-time discovery in popularity order, `exec.LookPath` and `os.Stat` ONLY (SRV-03 — discovery is a probe, never a launch), run once before `uiserver.Listen` and never per request, and never fatal (not-found is a normal answer, the server starts and answers NO_TEMPLATE). Declare `editorLaunchers` as the ordered slice `code, cursor, idea, goland, webstorm, pycharm, rider, clion, phpstorm, rubymine` — this ordering is a committed fact the ordering test pins; `jetbrainsLaunchers` is the set of the last eight. `code-insiders` and `codium` are deliberately not probed (they are allowlisted schemes for a custom template, not presets — CONTEXT.md Claude's Discretion). Declare `editorProbes{lookPath, stat, goos, getenv}` so every environment touch is injectable.

`macAppBundles` maps each launcher to its bundle names: code → `Visual Studio Code.app`; cursor → `Cursor.app`; idea → `IntelliJ IDEA.app`, `IntelliJ IDEA CE.app`; goland → `GoLand.app`; webstorm → `WebStorm.app`; pycharm → `PyCharm.app`, `PyCharm CE.app`; rider → `Rider.app`; clion → `CLion.app`; phpstorm → `PhpStorm.app`; rubymine → `RubyMine.app`. On darwin each bundle is stat'ed under `/Applications` and then under `filepath.Join(getenv("HOME"), "Applications")`. `linuxAppDirs(launcher, getenv)` returns `/opt/<launcher>` plus `<dataHome>/JetBrains/Toolbox/apps/<launcher>` where dataHome is `getenv("XDG_DATA_HOME")` or `filepath.Join(getenv("HOME"), ".local/share")` — for the JetBrains launchers only; for code and cursor on Linux, PATH is the only probe (their package installers all place a launcher on PATH). No Windows branch: state in the doc comment that native Windows support was dropped at v0.4.0 (WSL2 only, quick task 260807-gho), so the `%LOCALAPPDATA%` probe D-15 mentions has no host to run on and is omitted deliberately. Any other goos gets PATH probing only.

`discoverEditorWith(p editorProbes)`: for each launcher in order — `p.lookPath(launcher)` first; on success return immediately; else stat each app-dir candidate for that launcher in order and return on the first nil error. A stat or lookPath error of any kind is treated as "not here" and never surfaced. Return `(discoveredEditor{}, false)` after the last launcher. `templateForLauncher` composes the result: code → `("vscode", presets["vscode"].Template)`, cursor → `("cursor", presets["cursor"].Template)` where presets is read from `uiserver.EditorPresets()`, JetBrains launchers → `("jetbrains", launcher + "://open?file={path}&line={line}")` — the IDE-side handler form (see editorpresets.go's [ASSUMED] note; the discovered template inherits that tag). `discoverEditor()` is the production binding: `editorProbes{lookPath: exec.LookPath, stat: os.Stat, goos: runtime.GOOS, getenv: os.Getenv}`. The file imports `os/exec` for `LookPath` only and must contain no process-spawning call; the verify gate counts the call-shaped tokens (name followed by an open paren), so describe the probe-only property in prose without writing those call forms in comments (Phase 8 tripped its own substring gates three times on comment text).
