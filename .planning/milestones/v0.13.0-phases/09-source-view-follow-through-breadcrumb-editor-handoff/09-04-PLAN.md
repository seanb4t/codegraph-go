<objective>
Put the editor handoff in front of the user: an "Open in editor" link in `SourcePane`'s header (file
view at line 1, single-def at the node's start), line-number gutter cells that become click targets
when a link is buildable, and a small popover picker beside the header link where a developer chooses
VS Code, Cursor, JetBrains or a custom template for THIS browser only — stored in localStorage, sent as
the request's template, validated by the server on first use, cleared by "Use server default".

Purpose: BRW-11's "node detail and source views offer an open-in-editor link" and BRW-12's
"overridden per browser in the UI", built on the per-line rows plan 09-03 already landed and the rpc
plan 09-01 already proved. The header link is a resolved `<a href>` from a load-time probe so the
browser's transient user activation is never at risk on the primary path; the gutter pays one rpc
per click and navigates with `location.assign`.

Output: `editor-prefs.ts`, `EditorLinkPicker.svelte`, the editor surfaces in `SourcePane.svelte`, jsdom
coverage, the live gate extended with three editor-link phases, and a rebuilt `web/build/`.

(exports declared returning `null`/`undefined` in the `test(09-04)` commit). Tasks 2 and 3 are

<assumption_delta_decision>
**add-alongside.** The editor-link template gains a second source of truth in this phase: the server
default (flag → env → discovery, frozen at `Listen`) and a per-browser override that "replaces it for
that browser only". D-06 and D-18 fix the relationship as add-alongside by design — the override rides
every request as `GetEditorLinkRequest.template`, the server stays stateless and read-only by
construction (no Set/Put/Save rpc may exist, SRV-03), nothing is persisted server-side and nothing
needs resetting. The noun is *editor-link template resolution source*; the client resolves both through
ONE code path (`templateForRequest` is the only function that turns a stored preference into the
request field, and both the probe and the gutter click go through it — the suggested invariant test is
`web/tests/editor-prefs.test.ts`'s "probe and click send the same template for the same override"
case). What would force a later *promote* to a single server-owned source: a config-file template
source (deferred in 09-CONTEXT.md) or a multi-user server (the Team Scale milestone), either of which
would make "per browser" an insufficient scope for the preference. Advisory; never blocks.
</assumption_delta_decision>
