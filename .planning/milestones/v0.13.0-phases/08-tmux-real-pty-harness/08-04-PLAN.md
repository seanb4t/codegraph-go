<objective>
Prove all four of this phase's assertion classes can actually fail, by watching each one go RED against
a real, confirmed-applied, byte-cleanly-reverted mutation of shipped product code — and record every
demonstration in `08-MUTATION-LOG.md` following `07-MUTATION-LOG.md`'s shape.

Purpose: this milestone exists because v1.0 Phase 7's human UAT caught two defect classes that both a
full piped suite and a deep multi-agent code review had missed. A new assertion that has never been
watched fail is exactly the untrusted gate that produced them. D-06 deliberately extends RED coverage
past the two families the ROADMAP success criteria name, so TTY-05 and TTY-06 do not ship having never
been watched fail.

Output: `08-MUTATION-LOG.md` with four family entries, and three production files byte-identical to
their pre-phase state.

**Commit discipline (Phase 7 precedent, 07-04's key-decisions).** The RED/GREEN framing inverts in this
phase: the deliverable IS the test, so there is no separate production implementation to add after a
compile-time RED, and each test task in plans 01-02 lands as a single `test(08-NN): ...` commit rather
than a test/feat split. The RED that matters is precisely this plan's mutation demonstrations — an
assertion failing against a deliberately broken product — not a compile-time RED against the harness's
own new code. That is the same call 07-04 made and stated, and it is being carried forward
deliberately rather than rediscovered.
</objective>
