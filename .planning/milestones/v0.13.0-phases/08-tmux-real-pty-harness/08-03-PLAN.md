<objective>
Wire the harness into CI: a `tmux-e2e` job on `ubuntu-latest` that installs tmux and runs
`task test:tmux` in strict mode, plus the same-commit fixture edit that keeps the repo's own
workflow-shape guards honest, plus the deliberate bootstrap of the pinned tmux version string.

Purpose: without this the harness is a build-tagged package that nothing ever runs. TTY-07 is what
turns the whole phase from documented intent into a gate — and the design deliberately makes "a runner
without tmux", "a misspelled build tag" and "one case silently skipping" all fail the job rather than
pass it empty.

Output: a CI job whose two run bodies are bare task calls, a matching `inScopeJobs` entry, and either
a real pinned tmux version or an explicitly-recorded, self-describing bootstrap state.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI job → GitHub status API | The check's green/red is the only signal most readers consume; it cannot by itself distinguish "asserted and passed" from "never reached". |
| GitHub-hosted runner → distro package archive | `apt-get install tmux` pulls a binary the job then trusts to be a faithful terminal emulator. |
| repo fixture → external GitHub ruleset | `requiredCheckNames` mirrors a ruleset that lives outside this repository and can drift silently. |

## STRIDE Threat Register

ASVS level 1, block on `high`. Package-legitimacy gate not applicable: no npm/pip/cargo dependency is
added by this phase (08-RESEARCH.md § Package Legitimacy Audit).

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|

The job carries no `continue-on-error` and no `if:`, so it cannot skip its own assertion. Task 2's `<human-check>` requires the count line to be read out of a real job log before the phase is called done. |

</threat_model>
