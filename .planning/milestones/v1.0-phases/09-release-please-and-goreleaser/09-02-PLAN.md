<objective>
Make `release.yml`'s asset publish idempotent against a release-please-created GitHub Release (D-04) — create-if-absent, else upload-with-clobber — and prove both branches with a stubbed `gh` before changing the workflow.

This is the single highest-risk edit in the phase: it touches the LOCKED file, and getting it wrong either hard-fails every automated release or silently replaces release-please's changelog with generated notes.

Purpose: let release-please own the Release object and its notes while `release.yml` continues to own the signed binaries, without breaking the manual `rc`-tag path.
Output: a create-vs-upload branch in one shell step, and a Go test that executes that exact shell against a recording `gh` stub across five cases.

- Modified `.github/workflows/release.yml` — the body of the `Publish GitHub release` step only
</objective>

## Identity-model delta (assumption-delta detector: `detected: true`, three `pluralization` signals)

**Primary noun (the generalized identity):** the **release ref shape** — `refs/tags/v[0-9]*` — NOT the actor that pushed the tag.

**Decision: `no-change`.** The identity model already names the right noun. `releaseWorkflowRefPattern` is anchored to the ref, not to who created it. The genuine pluralization in this phase is that `release.yml` gains a *second* tag-producing actor (release-please's App token) where it previously had exactly one (a human `git tag`), and D-03 contemplates a third (`workflow_dispatch` at a tag ref). Because the primary key is the ref and not the actor, adding actors is safe by construction — this is precisely *why* D-02's App-token approach preserves `codegraph upgrade` while engram's branch-push approach would break it.

**Accepted-debt note:** none. Nothing is being added alongside a still-required singular assumption.

**Companion invariant test (accepted):** `TestReleaseWorkflowFileMatchesPattern` and `TestReleaseWorkflowTriggerIsTagPushOnly` (plan 09-01, `internal/upgrade/release_workflow_shape_test.go`) double as this invariant test. They go red the instant a future phase reintroduces an actor-specific or branch-shaped signing assumption — the trigger guard in particular fails on any second trigger key, which is the only way a branch-shaped ref could enter the signing path.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tag ref -> release.yml signed build | the tag is what binds the cosign OIDC identity; the file's shape is the contract every shipped binary checks |
| assemble job -> GitHub Releases API | the job holds `contents: write` and mutates a public artifact set |
| `$TAG` / `$REPO` workflow context -> publish-step shell | a crafted tag name is attacker-influenced text entering a shell interpreter |
| release-please's Release body -> end users | the changelog users read is written by release-please and must not be silently replaced |
