<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process → git subprocess | git rev-parse output is used to derive a filesystem write target (the hooks dir); a spoofed/hostile --git-path result could redirect writes |
| projectRoot argument → path resolution | projectRoot originates from the CLI targetRoot helper (filepath.Abs of cwd or a user path), not from network input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-02 | Spoofing | HooksDir (--git-path output redirects the write target) | medium | mitigate | HooksDir degrades to "" on any error/empty output (never assumes a value); downstream (05-03) only ever writes to filepath.Join(hooksDir, <one of 3 fixed hook names>), so a spoofed dir cannot reach an arbitrary attacker-named file |
| T-05-02b | Denial of Service | IsGitRepo/HooksDir on a hung git | low | mitigate | 5s context timeout (gitTimeout) + cmd.Stdin = nil so git can never block on an interactive prompt (inherited worktree.go contract) |

_No package installs in this plan (stdlib only) — no supply-chain (T-05-SC) checkpoint applies._
</threat_model>
