<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Measurement environment -> perf verdict | The machine a benchmark runs on is part of the measurement; comparing across machines produces meaningless numbers that read as meaningful |
| Reproducibility gate -> release trust | This gate is the only independent evidence that the release build is deterministic |
| Namespace runner -> both gates | Both required checks now execute on third-party runner infrastructure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-06-01 | Repudiation | `internal/bench.CheckRegression` runner blind spot | high | mitigate | Refuse the comparison outright when runner identities differ or either is empty, before any tolerance arithmetic runs, naming both values. Demonstrated against the real committed baseline and in a real CI run with a deliberately wrong label, not only in a unit table. |
| T-10-06-02 | Tampering | Reproducibility double-build scripts moved into `Taskfile.yml` | high | mitigate | Ported character-for-character with an explicit diff recorded; the blocking linux/amd64 leg and the reported-only arm64 leg stay separate steps with separate dispositions; both legs demonstrated detecting an injected non-determinism. |
| T-10-06-03 | Repudiation | `check:reproducibility:arm64` silently not running locally | medium | mitigate | A `preconditions:` check on `zig` with an actionable message; the leg is non-blocking in CI, so a local silent skip would be the only remaining signal and must fail loud instead. |
| T-10-06-04 | Tampering | Namespace runner producing the reproducibility verdict | medium | accept | The gate is a self-comparison — two builds in the same job compared by hash — so a compromised runner would have to produce identically-tampered output twice to pass, and the release pipeline's SLSA provenance is generated on separate infrastructure (D-07). |
| T-10-06-05 | Denial of Service | Perf gate red for the whole window between plan 10-04's baseline commit and this plan | medium | mitigate | The window is explicitly recorded in plan 10-04's SUMMARY as expected, with the reason, so it is not misread as a regression; this plan closes it. |
| T-10-06-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no npm, pip, or cargo package and adds no new module dependency. |
