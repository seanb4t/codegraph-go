<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Contributor machine -> perf baseline | Anything that can write `baseline.json` can silently redefine what "no regression" means |
| CI runner class -> measured throughput | The measurement environment is part of the measurement; a change in it invalidates comparison |
| Benchmark artifact -> committed authority | An artifact downloaded from a workflow run becomes the repository's perf authority |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-04-01 | Tampering | `tools/bench/baseline.json` | high | mitigate | No task target exposes the rebless flag (D-13, asserted in Task 2's acceptance criteria); the file is replaced byte-for-byte from the machine-written artifact and never hand-edited; a blocking maintainer checkpoint precedes the commit; the commit contains nothing else. |
| T-10-04-02 | Repudiation | Runner-class change invisible to the platform guard | high | mitigate | The `runner` field is added and populated from the workflow's own label BEFORE any baseline is recorded, so the recorded artifact self-describes its measurement environment. Comparison of the field lands in plan 10-06 once a runner-labelled baseline exists to compare against. |
| T-10-04-03 | Spoofing | Mixed-runner trial aggregation | medium | mitigate | Aggregation refuses a trial set whose `Runner` values differ, with both values named — mirroring the existing `GOOS`/`GOARCH` category-error refusal rather than inventing a second convention. |
| T-10-04-04 | Denial of Service | Namespace runner unavailable when a baseline must be recorded | medium | accept | The rebless job is manually dispatched and not on any critical path; an unavailable runner blocks re-blessing, which is a visible failure, not a silent one. |
| T-10-04-05 | Tampering | Cache Volume contents influencing measured throughput | medium | accept | The benchmark builds a deterministic, network-free synthetic corpus; module/build cache state affects build time, not the measured index/query throughput. Accepted and recorded so a future triage does not chase it. |
| T-10-04-SC | Tampering | npm/pip/cargo installs | low | accept | `bench.yml`'s head-to-head job installs the TypeScript reference binary from npm — a **pre-existing** step this plan does not touch, at a pinned version (`codegraph@1.3.1`). No new npm/pip/cargo install is introduced, so no legitimacy checkpoint is added. |
</threat_model>
