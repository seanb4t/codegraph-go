DISCARDS the caller's start path after resolving the index root — that is the
load-bearing plumbing change of this phase (D-14). Detection needs BOTH sides.

worktree awareness in one commit, per the ROADMAP note.

into a live value, and expose the one accessor + one notice helper that plans
02-05/02-06/02-07 consume.
Output: `Engine.startPath`, `Engine.WorktreeMismatch()`, `Engine.UseDetector()`,
live `StatusResult.WorktreeMismatch`, and `query.WorktreeNotice` /
`query.WorktreeWarningBlockquote`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI `--path` / MCP `path` arg → `Engine.startPath` → `gitmeta` `cmd.Dir` | Caller-supplied directory reaches a git subprocess's working directory |
| `Engine.repoRoot` (resolved index root) → detection + warning text | The upward-walk result is echoed back to the caller in the warning |
| `StatusResult.WorktreeMismatch` → `--json` and MCP output | Absolute host paths cross to a caller that may be an AI agent processing attacker-influenced content |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-16 | Denial of Service | git subprocesses on the read path | medium | mitigate | Three layers: `gitmeta`'s 5s per-subprocess bound (plan 02-01), the Engine's `sync.Once` (at most one detection per Engine, so `Status()` plus any render path never re-spawn within a request), and the injected `CachingDetector` (at most one detection per `startPath\x00indexRoot` for the MCP server's lifetime). |
