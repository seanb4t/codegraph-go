<objective>
Port TS's TWO distinct query tokenizers (H1 + H2) as pure functions — the foundation of EXPL-01. RESEARCH's central tokenizer pitfall: these are NOT one function. `extractSymbolsFromQuery` (H1, context/index.js:64-145) extracts exact identifiers for named-symbol seeding and filters via a ~90-word `commonWords` set; `extractSearchTerms` (H2, search/query-utils.js:189-242) extracts stopword-filtered FTS terms and filters via the SEPARATE `STOP_WORDS` set. Both feed different pipeline stages; port both, do not conflate them or assume one covers EXPL-01.

TDD: the RED test asserts concrete input->output token sets (extracted verbatim from RESEARCH §1-2) before either function exists. This is a pure-string algorithm with fully defined I/O — ideal TDD.

Security (V5, WR-05): both tokenizers must return an EMPTY slice for an empty/whitespace-only query — a tokenized-empty query must never silently become "match everything" (RESEARCH Security Domain). The RED test includes this case.

Purpose: today `explore` takes a single arg and 0-matches multi-word queries; the tokenizers are the first stage of the real TS pipeline.
Output: internal/query/tokenize.go + test.

Artifacts this plan produces: tokenize.go with H1, H2, STOP_WORDS, commonWords.
</objective>
