<objective>
Port TS's ContextBuilder hybrid gather — heuristics H3-H6 (RESEARCH §C.2, context/index.js) — the multi-channel candidate-gathering that REPLACES the naive lexical matchNodes as explore's input construction (RESEARCH Pitfall 1: the subgraph into RWR is a much larger hybrid gather, not a rerank of matchNodes). D-10 requires the full stack; this plan lands the three scoring channels + the merge.

Heuristics (constants VERBATIM from RESEARCH §C.2):
- H3 Channel 1 — exact-name lookup + co-location boost: `+20 * (distinctSymbolsInFile - 1)` when >1 query symbol co-occurs in a file; trim to searchLimit*2.
- H4 Channel 2 — titlecase definition-prefix search: class/interface/struct/trait/protocol/enum/type_alias kinds; `+15 + brevityBonus` where `brevityBonus = max(0, 10 - (nameLen - prefixLen)/3)`; stem variants.
- H5 Channel 3 — FTS text search, multi-term merge: per-term search, `+5 * (termHits - 1)`; imports excluded unless an explicit kind filter is set.
- H6 Merge — max-score-wins: dedup by node id, keep the max score from any channel.

Consumes the plan-03 tokenizers (extractSymbolsFromQuery feeds H3/H4; extractSearchTerms feeds H5). Pure function over a graphstore.Reader, unit-testable against a small synthetic index — Wave 2, fully TDD.

Purpose: the candidate set + per-channel scores are the substrate the whole ranking pipeline operates on.
Output: internal/query/gather.go + test.
</objective>
