<objective>
Build `internal/watch`: a native, debounced filesystem watcher (SYNC-01) on
`github.com/fsnotify/fsnotify` (the mandated cross-platform primitive; NO polling default —
REQUIREMENTS out-of-scope + CLAUDE.md "What NOT to Use"). fsnotify does not recurse, so the watcher
walks the tree at startup and re-adds any newly-created directory on a `Create` event (D-04). A
burst of events debounces (default 2000ms, tunable via `CODEGRAPH_DEBOUNCE_MS`) into ONE sync over
the union of changed paths.

The watcher agrees with the indexer on the file set by calling `indexer.ShouldSkipDir` (exported in
Plan 04-03) as its directory-skip predicate — so `.codegraph/`, `vendor`, and dot-dirs are excluded
identically and the two never silently diverge. Full re-parse of changed files (not tree-sitter
incremental reparse) is the v1 choice (RESEARCH A4).

Purpose: the write path's front door — turn OS file events into bounded, coalesced Sync triggers
without exhausting fd/watch limits or leaking goroutines (leak-freedom proven in Plan 04-09).
Output: `internal/watch` with a watcher loop and a debouncer, both built for `context`-cancellation
lifecycle (owned goroutines joined on shutdown, per D-07), plus the fsnotify dependency.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem event → watcher | fsnotify delivers raw event paths; a symlinked/`..` path could resolve outside the repo root |
| edit storm → debounce buffer | An adversarial burst / pathological recursive-add could exhaust fd/watch limits or unbounded memory |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05-01 | Tampering | addRecursive / event path handling | high | mitigate | Confine watching to the repo root; use indexer.ShouldSkipDir so `.codegraph/`/vendor/dot-dirs are excluded; do not follow symlinks that resolve outside the watched root before handing a path to Sync (Sync re-validates against repoRoot, T-04-03-02) |
| T-04-05-02 | Denial of Service | debounce pending set / fsnotify watch count | medium | mitigate | The pending set is keyed by path (deduplicated — bounded by distinct changed files, not event count); the Errors channel is drained (Pitfall 6) so ErrEventOverflow/removed-watch surfaces as a logged error, never a silent stall; per-OS watch/fd limits (inotify max_user_watches, kqueue fd-per-file) documented in the watcher's error path |
| T-04-05-03 | Denial of Service | leaked/late-firing debounce timer | medium | mitigate | AfterFunc callback checks ctx.Err(); shutdown calls timer.Stop(); goroutine ownership joined via context+WaitGroup (D-07) — soak-verified in Plan 04-09 |
