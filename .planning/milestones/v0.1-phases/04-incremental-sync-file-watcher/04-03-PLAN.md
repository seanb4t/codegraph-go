<objective>
Build `internal/indexer.Sync(repoRoot, storeDir string, opts Options) (Stats, error)` — the
incremental indexing entry (INDX-03) that reuses the existing extract/resolve/symbolindex/discover
internals rather than a second pipeline (D-01). One routine, three callers: `codegraph sync`
(Plan 04-08), the debounced daemon cycle (Plans 04-05/04-07), and MCP-reconnect reconcile
(Plan 04-06).

Two load-bearing RESEARCH findings shape this (do NOT design around them):
- **Store-seeded symbol index (finding 1 / Pitfall 1):** `newSymbolIndex(results)` only sees the
  batch handed to it. Calling `Resolve()` with a subset silently breaks resolution for every
  reference into/out of an UNCHANGED file. Sync MUST seed its index from the stored graph
  (`IterateNodes()` + `importPathFor`) and overlay only the reparse batch.
- **Dependents need Pass-1 re-EXTRACTION (finding 2 / Pitfall 2):** `Unresolved` refs are never
  persisted. A dependent whose caller must re-resolve has to be re-extracted (even though its own
  hash is unchanged) to regenerate its in-memory `Unresolved` list. The batch stays bounded by
  (changed files) ∪ (their direct reverse-adjacency dependents), never the whole repo.

Purpose: keep one indexing code path and preserve Phase-2's byte-identical determinism through
incremental update. Full re-parse of changed files (NOT tree-sitter incremental reparse) is the v1
choice (RESEARCH anti-pattern / A4) — the determinism gate depends on it.
Output: `Sync()` plus the store-seeded index seam, the resolve idx-injection refactor, the
`shouldSkipDir` export, and mtime/size stamping on every File write.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → Sync | Discovered/changed file paths flow into os.Stat/os.ReadFile and into key encoders; must stay confined to repo root |
| changed source → CGo parser | Reparsed arbitrary/edited files go through the tree-sitter CGo parser (crash-isolation caveat) |
| stat → hash → reparse → commit | A file changing mid-sync must not produce a torn/partial graph |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03-01 | Tampering | Sync stat/hash/reparse → commit | high | mitigate | All prune-deletes + batch-writes stage on ONE Writer and land in a single atomic Commit() (single-writer invariant INDX-05); a file changing between stat and commit at worst re-syncs next cycle, never leaves a half-written graph |
| T-04-03-02 | Tampering | path confinement (os.Stat/os.ReadFile) | high | mitigate | Reuse Discover's repo-root-confined WalkDir + shouldSkipDir exclusions for the file set; join/validate any candidate path against repoRoot before reading; never follow a symlink out of the tree |
| T-04-03-03 | Denial of Service | CGo parser on adversarial/oversized source | medium | mitigate | Reparse honors parser.MaxSourceBytes (existing ceiling); a single bad file is recorded in File.Errors and skipped (Stats.Skipped) — it does not abort the batch or corrupt the commit |
| T-04-03-04 | Tampering | dependent recomputation correctness | medium | mitigate | Dangling edges prevented by re-EXTRACTION + re-resolve of dependents (D-02a) — an edge to a gone symbol simply is not regenerated; the sync-equals-reindex determinism gate (Plan 04-04) is the acceptance evidence |
| T-04-03-SC | Tampering | dependencies | low | accept | No new package-manager installs this plan (uses existing indexer + the 04-02 query import); no [ASSUMED]/[SUS] packages |
</threat_model>
