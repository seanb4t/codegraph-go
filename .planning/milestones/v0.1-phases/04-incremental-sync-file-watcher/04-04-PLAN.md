<objective>
Prove INDX-04's acceptance gate: file renames, deletes, and moves prune stale symbols and edges
with NO orphaned nodes and NO dangling edges, verified by a fixture suite (ROADMAP success
criterion 2), and prove INDX-03's determinism bar: an incremental `Sync` that touches every file
lands a graph byte-identical to a from-scratch `index` (Phase-2's byte-identical property must
survive incremental update — CONTEXT Specific Ideas).

Rename/move is modeled as delete(old path) + add(new path) at the file level (D-03). Because node
ids are content-hashes (Phase-2 D-02a), a symbol whose content is unchanged keeps a stable
n/id, so a pure move does not churn inbound edges. This plan is validation-first: it exercises the
prune paths built in Plan 04-03 and fixes any prune bug they surface in sync.go.

Purpose: this fixture suite IS the INDX-04 acceptance gate; the determinism property test IS the
INDX-03 correctness bar. Neither is an afterthought.
Output: an extended testdata/gofixture corpus, the prune fixture suite, the sync-equals-reindex
property test, and any prune correctness fix in sync.go they surface.
</objective>
