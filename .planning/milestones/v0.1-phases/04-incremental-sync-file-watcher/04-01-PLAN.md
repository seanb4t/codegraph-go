<objective>
Build the file-owned secondary index (`x/` namespace) inside `internal/graphstore` so a
file's scattered, content-hash-keyed nodes and outgoing edges can be pruned by path in
O(subgraph) time. This is the load-bearing INDX-04 hook: `keys.go:104-120` already documents
`DeleteFileSubgraph` as pruning only the `f/` record and names extending it to node/edge
records as *the Phase-4 hook* (D-02).

Because node ids are content-hashes of `(kind, qualifiedName, filePath)` — NOT file-clustered
(Phase-2 D-02a) — a contiguous `DeleteRange` over `n/`+`e/` is impossible. Instead this plan adds
an additive `x/<path>/…` index (itself one contiguous, range-deletable region) that the Sync
prune step (Plan 04-03) scans to find the exact `n/`/`e/` keys to point-delete.

Purpose: make subgraph pruning tractable and correct without a full-graph scan per sync, entirely
behind the `GraphStore`/`Reader`/`Writer` interface (archtest boundary — this index lives inside
`internal/graphstore`, D-02).
Output: `x/` key builders, three new interface methods, an iterator, and a `PutEdge` ownerPath
parameter — all additive, `SchemaVersion` stays `1` (a new key namespace is not a record-format
break, per `internal/schema/meta.go`).
</objective>
