<objective>
Build `codegraph upgrade [version] [--check]` (CLI-02): a signature-verified self-update that downloads the target-platform binary from GitHub Releases, verifies its cosign-keyless signature/provenance IN-PROCESS via sigstore-go (never shelling to a cosign CLI — D-12), and only then atomically replaces the running binary (D-11, D-13). `--check` reports upgrade availability without downloading. This is the phase's security-critical surface: the primary mitigation against a tampered/MITM'd release is the mandatory verify-before-swap step (Pitfall 7).

Per D-14, verification is built REAL against fixtures this phase (not stubbed); the production release-URL + signing-identity are named constants Phase 8 finalizes. Pin `github.com/sigstore/sigstore-go` in go.mod here (the crypto dep, distinct from 06-01's agents-format dep).

Purpose: Deliver a self-update the user can trust — no unverified binary is ever swapped in.
Output: internal/upgrade package (release/verify/swap/orchestrator) + upgrade command + fixture-based verify-reject test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| codegraph → GitHub Releases (network) | Downloads a candidate replacement binary + its signing bundle over the network — the highest-value attack surface in the phase |
| codegraph → Sigstore public-good infra | Read-only TUF/Fulcio/Rekor verification inputs |
| upgrade → the running binary on disk | The self-replace target; a partial write would brick the install |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-06-01 | Tampering / Spoofing | MITM or compromised GitHub Releases serves a malicious binary | high | mitigate | Mandatory in-process sigstore-go keyless verification (Fulcio cert identity pinned to the repo's GH-Actions OIDC workflow, D-12/D-14) BEFORE swap; HTTPS transport alone is explicitly insufficient. Task 2 test asserts a tampered artifact is rejected. |
| T-06-06-02 | Tampering | download→swap→verify-after ordering (verification bypass) | high | mitigate | Orchestrator structured verify-before-swap, fail-closed: a verify error is fatal and never falls through to swap (Pitfall 7); Task 3 test asserts the swap seam is never called on a tampered download. |
| T-06-06-03 | Denial of Service | partial binary swap on crash/interrupt bricks the install | medium | mitigate | Atomic swap only: download+verify fully into a temp file, os.Rename (POSIX) / rename-aside (Windows) is the sole step touching the final path; Task 1 test asserts the original survives a failed swap. |
| T-06-06-04 | Tampering | downgrade attack — swapping in an older signed release | medium | mitigate | --check and the orchestrator compare against the current version.Info().Version; a bare `upgrade` targets latest and an explicit older `upgrade <version>` is user-initiated. Report current-vs-target so a downgrade is never silent. |
| T-06-06-05 | Elevation / Access Control | writing over a binary the current user shouldn't | low | mitigate | Writability precheck refuses a non-writable target with a clear error, no partial state (D-13, V4); Task 1 test covers it. |
| T-06-06-SC | Tampering | go.mod dependency addition (sigstore-go + its ~20-module subtree) | low | accept | RESEARCH Package Legitimacy Audit verified sigstore-go v1.2.2 (official Sigstore org, High reputation, 93.12 benchmark) against proxy.golang.org; the transitive subtree is all official Sigstore/crypto/protobuf modules; verdict OK/Approved. minio/selfupdate ([SUS], stale) explicitly NOT adopted — swap hand-rolled per D-13. Pinned to an exact version. |
</threat_model>
