<objective>
Implement **Pass 1 (parallel extract)** of the two-pass pipeline (D-04): turn each discovered Go file into an in-memory intermediate of `(nodes, intra-file edges, unresolved cross-file references)`.

Two seams:
1. **`goextract` (the Go-specific tree-walk, LANG-01):** map tree-sitter-go CST node types to the codegraph vocabulary — `function`/`method`/`struct`/`interface`/`type_alias`/`constant`/`variable` nodes (golden `nodesByKind` parity), `contains` edges (file→symbol, struct→method), and **unresolved references** for cross-file work (calls, imports, struct/interface embedding). This is the load-bearing LANG-01 engineering. Ground the mapping in `testdata/golden/corpus/weft-go/`.
2. **`extract` (the Pass-1 pool, D-04):** run `goextract` over the `DiscoveredFile` list inside an `errgroup` capped at `runtime.NumCPU()`, one `cgo.NewGoParser()` per worker (never per file, never shared — tree-sitter parsers are not goroutine-safe), writing results index-addressed by pre-sorted position so Pass 2's input order is independent of goroutine scheduling.

Purpose: LANG-01 structural extraction and the RES-01 unresolved-ref stream both originate here. Determinism starts here (index-addressed results); per-file error containment (Pitfall 4) is what lets success-criterion-4 survive one bad file in a real repo.

Output: `internal/indexer/goextract` package (Extract + FileResult/intermediate types); `internal/indexer/extract.go` (the pool).
</objective>

// package goextract
type ExtractedNode struct { Node *schema.Node }          // fully-formed node (id via nodeid.NodeID)
type IntraEdge     struct { Edge *schema.Edge }          // file->symbol / struct->method contains edges (both ids known now)
type UnresolvedRef struct {
    FromID     string   // node id of the enclosing symbol (or file id) the ref originates from
    Name       string   // referenced identifier (e.g. "Alpha") or selector name
    PkgAlias   string   // for selector calls pkg.Fn — the local package alias; "" for unqualified
    Kind       string   // "calls" | "imports" | "embeds"
    Line, Col  int32    // call-site coordinates (D-04)
}
type FileResult struct {
    ImportPath string
    RelPath    string
    Language   string   // "go"
    Nodes      []ExtractedNode
    IntraEdges []IntraEdge
    Unresolved []UnresolvedRef
    Imports    map[string]string // local alias -> import path, parsed from the file's import_spec list
    ContentHash string          // sha256 hex of the file bytes (File.content_hash, D-02a)
    Err        error            // non-nil if this file was skipped (e.g. parser.ErrSourceTooLarge)
}

// Extract(p parser.Parser, importPath, relPath string, src []byte) (FileResult, error)

Phase-1 contracts to honor (internal/parser/parser.go, parser_cgo.go):
- p.Parse(src, nil) enforces parser.MaxSourceBytes and returns parser.ErrSourceTooLarge for >4 MiB.
- Every returned *parser.Tree MUST be Close()'d exactly once; unwrap via tree.Inner().(*tree_sitter.Tree).
- Each worker: p, _ := cgo.NewGoParser(); defer p.Close()  (once per goroutine, not per file).

tree-sitter-go node types (RESEARCH §Code Examples, verified via Context7):
- method_declaration.receiver = parameter_list → one parameter_declaration → type is type_identifier
  (value receiver) or pointer_type wrapping type_identifier (pointer receiver).
- struct embedding: a field_declaration inside struct_type with a type child but NO field name child.
- interface embedding: entries in the interface_type's type_list (sibling of method_declaration_list).
- calls: call_expression; selector_expression (pkg.Fn) vs bare identifier.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02 | Denial of Service | internal/indexer/extract.go | high | mitigate | `parser.Parse` enforces `MaxSourceBytes` (4 MiB) BEFORE any C parse (Phase-1 contract, threat T-01-03); the extractor relies on this ceiling and never bypasses it |
| T-02-03 | Denial of Service (self-inflicted) | internal/indexer/extract.go, goextract.go | medium | mitigate | Per-file error containment: `ErrSourceTooLarge`/parse errors set `FileResult.Err` and are recorded (later on `File.errors`), never aborting the whole run — so one bad file cannot deny indexing of a real repo (success-criterion-4) |
| T-02-04 | Denial of Service | internal/indexer/goextract/goextract.go | medium | mitigate | Walk the CST with tree-sitter's cursor API using an explicit cursor/stack, not unbounded Go recursion, so a pathologically deep AST (already size-bounded by MaxSourceBytes) cannot blow the Go stack |
| T-02-06 | Tampering (crash isolation) | internal/parser/cgo (consumed here) | low | accept | A C-scanner segfault in a grammar is in-process and NOT recover()-able (parser.go contract, T-01-01) — documented-accepted for Phase 2; the extractor does NOT design recovery around Go `recover()`. Subprocess isolation remains a Phase-2+ option if the risk proves unacceptable |
