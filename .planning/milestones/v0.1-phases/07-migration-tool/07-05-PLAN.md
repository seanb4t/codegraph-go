  <behavior>
    - Happy reconcile: for a store populated from VariantHappy, reconcileCounts finds migrated nodes == source nodes row count, migrated files == source files row count, migrated edges == source DISTINCT(source,kind,target) count; Report carries all pairs; no error.
    - Edge-dedup tolerance: given a source with two edge rows sharing (source,kind,target) but differing (line,col), the migrated store has ONE edge for that triple; reconcile passes because it compares against the distinct-triple count (a raw-row comparison would wrongly fail).
    - Count mismatch: if migrated node count < source node count (simulated shortfall), reconcile returns a loud error naming the table and both counts.
    - Referential integrity happy: every non-file: edge endpoint in the store resolves to a node in the node-id set; VariantHappy (whose only "dangling-looking" sources are file:-prefixed contains edges) passes with zero dangling.
    - file: exemption: an edge whose source is `file:cmd/weft/main.go` (no such node record) is NOT counted dangling; isFileEndpoint returns true for `file:`-prefixed ids.
    - Dangling fail-loud: a store containing an edge whose (non-file:) target id is absent from the node set → validate returns an error whose report lists the dangling edge; the store is unchanged (default dropDangling=false).
    - --drop-dangling: same store with dropDangling=true → the dangling edge is deleted (DeleteEdge via a Writer) and logged in Report.Dropped; validate returns nil error; a re-scan finds zero dangling.
  </behavior>

If `dropDangling` → open a Writer, `DeleteEdge(source,kind,target)` each dangling edge (and `DeleteFileIndexEdge` for its owner if applicable — or note x/ entry was never created for a dangling edge since ownerPath was ""), Commit, record the dropped count.
