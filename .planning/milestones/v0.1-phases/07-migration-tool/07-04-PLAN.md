    - Fresh target (does not exist): atomicSwapDir(tmp, target) renames tmp into target; target now holds tmp's contents; tmp no longer exists.
    - Existing non-empty target: atomicSwapDir renames the existing target aside (target+".old"), renames tmp into target, removes target+".old"; final target holds the NEW contents and the .old is gone.
    - Restore-on-failure: if the rename-in step fails after the aside step, the original is restored to target from the .old path and BOTH errors are reported (no state where target points at nothing) — assert via an injected/simulated rename failure or a same-fs precondition test.

Implement `siblingTempDir(targetDir string) (string, error)` via `os.MkdirTemp(filepath.Dir(targetDir), ".codegraph.migrate-tmp-*")` so the temp store shares the target's parent (never `os.TempDir()` — EXDEV, Pitfall 1). Implement `atomicSwapDir(tmpDir, targetDir string) error` as the three-step directory swap: (1) if targetDir exists, `os.Rename(targetDir, targetDir+".old")`; (2) `os.Rename(tmpDir, targetDir)`; (3) `os.RemoveAll(targetDir+".old")` — a step-3 failure is logged/returned as a non-fatal wrapped notice, never swallowed. On a step-2 failure after step-1, attempt `os.Rename(targetDir+".old", targetDir)` to restore the original and, if that restore also fails, return an error naming the `.old` path as the manual recovery location (the WR-04 discipline from upgrade/swap.go, reporting both errors). Add the `runtime.GOOS == "windows"` weaker-guarantee note in a doc comment (rename-onto-existing not guaranteed atomic on Windows; temp+rename still bounds the torn window).
