<objective>
Implement the typed, prefix-namespaced keyspace (D-03) that the Pebble-backed store builds on: `meta/`, `n/<node-id>`, `e/<src>/<kind>/<dst>` (ordered by source for range-scannable callers/callees/impact), `f/<path>` (file records + content hash), and a reserved `a/` annotation namespace for post-v1 embeddings/communities (ARCH-01 physical slot). Crucially, harden the segment encoding so a crafted path or identifier containing key-delimiter or control bytes cannot corrupt range-scan/range-delete boundaries across namespaces (Security Domain V5 input-validation / Tampering threat).

Purpose: These encoders are the single source of key construction for the whole store — no other code builds a raw `[]byte` key. Isolating them here (Wave 2) de-risks Plan 01-06's store implementation and gives the security-critical key-injection guard focused TDD treatment. Part of INDX-05's "behind a GraphStore interface" boundary.
Output: `internal/graphstore/keys.go` (encoders) and `internal/graphstore/keyenc_test.go` (injection + boundary tests).
</objective>

  <behavior>
    - `nodeKey(id)` produces a key under the `n/` namespace; distinct ids never collide.
    - `edgeKey(src, kind, dst)` sorts primarily by `src` then `kind` then `dst`, so iterating the prefix for a given `src` yields all its outgoing edges in order (range scan).
    - `fileSubgraphPrefix(path)` returns a prefix whose `[start, end)` range covers exactly that file's records and nothing from an adjacent file/namespace.
    - A path/id containing a delimiter byte (`/`) or a `0x00`/`0xff` boundary byte is encoded so it cannot escape its segment — `nodeKey("a/b")` and `nodeKey("a") + sep + "b"` never produce the same or overlapping keys, and no crafted input makes a node key fall inside another namespace's range.
  </behavior>
  <action>
    Create `internal/graphstore/keys.go` per RESEARCH Pattern 1: single-byte prefix constants for meta (`m`), node (`n`), edge (`e`), file (`f`), and a reserved annotation prefix (`a`) with a comment naming its post-v1 purpose (embeddings, community assignments — ARCH-01). Implement key builders for each namespace. For the security requirement (RESEARCH §"Security Domain", Tampering): do NOT concatenate raw id/path strings with a literal `/` separator — instead length-prefix each variable segment (e.g. a varint length followed by the segment bytes) or apply an unambiguous escape, so a crafted segment cannot inject a delimiter and cross a namespace or file boundary. Preserve edge range-scan ordering (D-03): the `src` segment must be the primary sort key of an edge key (length-prefixing must not break the property that all edges from a given `src` form a contiguous range). Provide `fileSubgraphPrefix(path)` plus a helper returning the exclusive upper bound for a single Pebble `DeleteRange` over a file's records (RESEARCH Code Examples range-delete pattern). Per RESEARCH Pitfall 2 / Open Question 3: include a documented comment on `edgeKey` stating that line/col are intentionally NOT part of the edge key in v1 (collapsing multiple call sites between the same src/kind/dst is the current behavior) and that Phase 2 extractor design must revisit this if an edge kind needs call-site multiplicity — the `Edge` record already carries line/col (Plan 01-02). Keep comments free of any literal token a negative-grep gate checks for.
