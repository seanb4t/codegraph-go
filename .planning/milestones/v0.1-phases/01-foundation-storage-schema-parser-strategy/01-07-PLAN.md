<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adversarial source → parser backend | The spike deliberately feeds malformed/adversarial input to measure crash isolation (Security Domain V5 / DoS) |
| C scanner ↔ Go host (CGo arm) | No memory isolation; a C segfault kills the host (uncatchable by recover) |
| WASM guest ↔ Go host (wazero arm) | A guest trap becomes a recoverable Go error — the isolation benefit being measured |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Denial of Service | CGo C-scanner segfault on adversarial input | high | mitigate (measured) | The spike's crash-isolation dimension (`crashisolation_test.go`) is precisely the measurement of this risk (RESEARCH Pitfall 5); PARSER-DECISION.md records whether the CGo host survives. The narrow interface (D-05b) preserves the option to switch to the isolation-providing wazero backend if the risk proves unacceptable. |
| T-01-03 | Denial of Service | pathological/oversized input during benchmark | high | mitigate | Both arms honor `MaxSourceBytes` (Plan 01-03 contract); the spike also feeds oversized input as a deliberate test case |
| T-01-14 | Tampering | spike/decision blocking a false conclusion | medium | mitigate | Human-verify checkpoint ratifies the recorded decision; Assumption A1's informal ~2x figure must be replaced with measured data (or the wazero-blocker documented), preventing a prejudged outcome |
| T-01-SC | Tampering | wazero dependency (spike scope) | low | accept | Tetrate-backed, widely adopted, Approved in RESEARCH §"Package Legitimacy Audit"; may be removed from go.mod if Option A is selected |
</threat_model>
