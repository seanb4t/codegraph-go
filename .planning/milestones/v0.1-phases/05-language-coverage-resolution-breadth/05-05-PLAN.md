## Plan assumption (Pitfall 5 — surfaced, not silently resolved)

C#'s `partial class` allows one logical type across multiple files (common in ASP.NET `.Designer.cs` scaffolding). This plan ADOPTS scheme (b) from RESEARCH Pitfall 5 unless the executor finds it infeasible: key the type-declaration node by `(qualifiedName, namespace)` only (no filePath), attach each partial fragment's methods via `contains` edges into that shared node, and point the node's FilePath/StartLine at the FIRST fragment by file-path sort order (deterministic tie-break mirroring collapseEdges). If the executor determines (b) is out of budget, fall back to scheme (a) — document `partial class` as an explicit, named gap in the D-11 C# matrix entry (methods become separate FILE-scoped nodes). Either way, the choice MUST be written down in the SUMMARY and the D-11 matrix; do not ship an undocumented collision.
