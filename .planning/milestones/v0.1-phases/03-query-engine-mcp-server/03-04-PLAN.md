<objective>
Implement call-graph traversal (D-04): `Engine.Callees` (forward, direct `IterateEdges(srcID)`), `Engine.Callers` (reverse), `Engine.Impact` (depth-bounded reverse BFS blast radius), and `Engine.Affected` (query-time test-impact derivation, D-07). Reverse traversal builds an in-memory reverse-adjacency map from one full `IterateEdges("")` scan per invocation — no persisted reverse index (deferred to Phase 8), no cache (would go stale once Phase 4 adds writes — Pitfall 2).

Purpose: QRY-04/05/06. `callers`/`impact`/`affected` are all reverse-adjacency reads; `callees` is a forward read. `affected` deliberately derives test impact at query time from `calls` edges + a `_test.go`/`Test*`/`Benchmark*` heuristic instead of persisting a "test-coverage edge type" (D-07 divergence from QRY-06's literal wording — user-facing behavior preserved, mechanism is query-time; see the D-07 confirmation checkpoint (Task 3) and Verification note).
Output: traversal methods + reverse-adjacency builder + JSON shaping, tested against the fixture and the golden impact/callers/callees arithmetic; plus a non-blocking D-07 confirmation checkpoint.

**Not autonomous:** this plan carries a non-blocking D-07 confirmation checkpoint (Task 3), so `autonomous: false`. The checkpoint surfaces the affected-derivation tradeoff for visibility but does not hold up a pre-approving executor.
