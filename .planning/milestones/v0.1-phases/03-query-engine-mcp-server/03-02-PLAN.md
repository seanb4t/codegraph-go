<objective>
Establish the read-only `internal/query` engine foundation and its Wave-0 test scaffolding. This plan creates the `Engine` type over `graphstore.Reader`, the shared nearest-`.codegraph/` resolution walk (D-01a), the input-validation clamps and the `ValidateKind` guard (V5, ASVS L1), and the `engine_test.go` harness (copyFixture-backed) that every subsequent query plan extends. It implements no query verbs yet — those land in 03-03/03-04/03-05/03-06.

Purpose: One engine, two front-ends (D-08b). `OpenAt` centralizes the D-02 fresh-snapshot-per-invocation discipline so CLI commands and MCP tool handlers share exactly one read path — the reason MCP-04 parity holds without a second code path. The validation clamps close the in-scope security surface this phase has (unbounded `--depth`/`--limit`/`--max-files` → DoS; the V5 threat model previously clamped the numeric flags but left `--kind` unvalidated — `ValidateKind` closes that gap so 03-03's `query`/`search --kind` reject unknown kinds against the known node-kind set before any scan).
Output: Engine scaffold + resolver + validators + a compiling, exercised test harness.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI/MCP flags → query engine | `-p/--path`, `--depth`, `--limit`, `--max-files`, `--kind` are untrusted numeric/string input crossing into traversal + filesystem resolution |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02-DoS | Denial of Service | clampDepth/validateLimit/validateMaxFiles | high | mitigate | Clamp `--depth` to `MaxDepth`; reject `--limit`/`--max-files` above documented ceilings with a clear error before any allocation/traversal (V5, Pitfall 4) |
| T-03-02-Kind | Tampering | ValidateKind (--kind input) | low | mitigate | Reject an unknown `--kind` against the known node-kind set (V5 — the V5 model previously clamped only the numeric flags; `ValidateKind` closes the `--kind` gap) so a garbage kind fails fast with a clear allowed-set error instead of silently scanning to an always-empty result; the allowed set is sourced from the goextract kind constants so it cannot drift from the extractor vocabulary |
| T-03-02-Path | Tampering / Information Disclosure | ResolveCodegraphDir | medium | mitigate | Resolve/clean `-p` via `filepath.Abs`; the upward walk stops at the filesystem root and only ever stats a `.codegraph` subdir — no user string is concatenated into an unbounded read path |
| T-03-02-Leak | Information Disclosure | ErrNotInitialized message | low | accept | Error text names the resolved directory only; consistent with the existing cli ErrNotInitialized convention for a local dev tool |
| T-03-SC | Tampering | package installs | low | accept | No dependency added here; `mcp-go` install is isolated to 03-07 (pre-audited OK) |
</threat_model>
