<objective>
The tracer for Phase 3: one production-quality path wired end to end through every
layer this phase touches, verified before any expansion task builds on it.

The path: a URL carrying a file target, parsed by a shared grammar module, turned into a
`GetNodeDetail` call, whose failure modes are classified by a shared error mapper and
whose success renders syntax-highlighted verbatim source in the browser. That single
slice exercises the URL layer (NAV-01), the RPC layer, the degrade layer (NAV-04), the

wrong, it is wrong after one commit instead of after ten.

extends: `browse-url.ts` is the ONE place later phases add parameters (D-13),
`rpc-errors.ts` is the ONE Connect-error translation Phases 4/5/6 reuse (D-04), and
`highlight.ts` is the single rendering path for repository bytes. The functionality is
deliberately narrow; the architecture is complete.

Purpose: the remaining browse plans (search, neighbours, source-pane depth, status gate)
all attach to these seams. Getting them wrong later means reworking five files instead
of one.

Output: the four shared modules, the source pane, a filled-in `/browse` route, a Go
set-equality guard binding the highlighter's language coverage to the indexer's own
registry, and the JS tests for all of it.

(b) `web/src/lib/browse-url.ts` — the ONE URL grammar (D-13). Export a `BrowseParams`
type and a `BROWSE_PARAM_KEYS` ordered list covering exactly the parameters this phase
uses: `symbol`, `file`, `line`, `depth`, `limit`, `q`. These names are deliberately the
same as `GetNodeDetailRequest`'s own fields (`symbol`, `file`, `line`) so the URL-to-RPC
mapping is identity and cannot drift (D-10).

`parseBrowseParams` reads SHAPE only: it checks that `line`/`depth`/`limit` parse as
base-10 integers and drops them when they do not. It never checks a range, never bounds a
value into one, and never substitutes a default for an out-of-range value. Out-of-range integers pass through
untouched for the server's own `validateLimit`/`MaxLimit`/`validateFilesDepth` to judge,
whose refusal becomes a named UI state through `rpc-errors.ts` (D-12).

Unknown parameters are preserved on the parsed object and re-emitted by
`serializeBrowseParams`, never rejected — a strict reading would make an older cached
shell reject a newer phase's link, the stale-shell failure Phase 2's `no-store` rule
exists to prevent. `serializeBrowseParams` emits keys in `BROWSE_PARAM_KEYS` order,
then any unknown keys in sorted order, so the same state always serializes to the same
string. Round-tripping must be idempotent.

Represent the unknown parameters as an ORDERED LIST OF PAIRS, not as a plain object.
Cycle-1 review (Codex, LOW) is right that "preserved" is a stronger promise than
"ignored", and an object silently collapses `?a=1&a=2` to one entry — so a link a future
phase authored with a repeated parameter would come back through the round trip as a
DIFFERENT link, which is precisely the failure the round-trip guarantee exists to
prevent. `URLSearchParams` itself is a multimap; keep that shape. Serialize the unknown
pairs sorted by key, and by original position within a repeated key, so ordering stays
deterministic. An empty-valued unknown parameter (`?futureThing=`) is preserved as an
empty value, not dropped — dropping it would also change the link.

(c) `web/src/lib/rpc-errors.ts` — the ONE Connect-error translation (D-04). Export a

`classifyRpcError(err: unknown): RpcFailure`. Detect the indexing case by checking the
`unavailable` error's typed details for the generated `IndexingInProgress` message, not
by string-matching the message text. Never throw from this function: it is the last line
between a server error and a blank pane.

ALSO export `HIGHLIGHT_COVERAGE`: a flat, sorted, string-literal-only array holding the

`highlightSource(code, language)` returns `hljs.highlight(code, { language }).value` when
the identifier is registered. When it is NOT registered, return the input ESCAPED AS

Never build the markup by concatenation, never pre-template the input, and never add or
import any HTML pass-through plugin: the input is verbatim third-party repository content
and this helper is the only thing standing between a script tag in an indexed file and
the browser. The plaintext branch's escaping must go through a single small escape
function in this module, not through string templates at the call site.
