<objective>
Close SRV-05's actual gap: the proof, not the behaviour.

The confinement gate itself already exists and is already shared. `internal/query/node.go:33-79`'s
`resolveSourcePath` implements four layers — empty path, absolute path, `..`-prefixed
path, and a post-`EvalSymlinks` re-check comparing resolved-root to resolved-path (its
own `WR-03` comment names the macOS `/tmp` → `/private/tmp` case). `readSourceFile`
(`node.go:85`) is the shared primitive both the MCP path and the UI path go through,
and `internal/uiserver/handlers.go:117` already sits behind it. The UI RPC path
inherits confinement by construction.

What does NOT exist is any assertion of that at the wire. `internal/uiserver/*_test.go`
has zero occurrences of `confinement` or `escapes the repo root`; the refusal is tested
only one layer down, in `internal/query/errors_test.go:45,139`.

Purpose: this makes the test design load-bearing rather than decorative. A test that
only asserts "`../etc/passwd` is refused" would pass today against an empty change set —
a guard green before any Phase 3 code exists proves nothing. So the refusal cases are
paired, in the same test, with a legitimate in-repo path that returns real source, and
with an assertion that no refusal leaks the host checkout path.

Output: `internal/uiserver/confinement_test.go`, a wire-driven regression test with a
positive control.
</objective>
