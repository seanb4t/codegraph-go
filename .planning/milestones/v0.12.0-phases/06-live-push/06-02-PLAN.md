<objective>
Build the server-side engine of live push: a store watcher that learns a re-index happened,
a change detector that decides whether that is worth telling anyone, and a bounded,
coalescing fan-out registry that hands the news to every open stream without letting a slow
reader hurt a fast one.

Purpose: this is where criterion 5 is won or lost. `pebble.Open` holds an EXCLUSIVE directory
lock for the store's whole open lifetime (`internal/graphstore/pebble_store.go:67-80`), so a
publisher that holds the store open would not merely slow a concurrent `codegraph daemon`
sync — it would deny it the store outright. Open, read, close, on every wake.

Output: `livepublish.go` and its goleak-guarded test file, with no HTTP or Connect
dependency of any kind — the handler in `06-04` consumes this, not the other way round.
</objective>

    ## Arming the watch — an explicit state machine, not "start idle"

    A non-recursive fsnotify watch only sees changes to entries of a directory it is ALREADY
    watching. So "if `.codegraph` does not exist, start idle" means nothing is watched, which
    means the store's later creation can never produce an event, which means a UI opened
    before the first index is permanently deaf — the exact opposite of "must still go live
    when one appears". Design the transition instead of asserting the silence.

    Define the path CHAIN, shallowest to deepest:

    1. `repoRoot` — the publisher's own configured repo path, resolved with `filepath.Abs`.
       This always exists: `codegraph ui` resolved it before constructing the server.
    2. `codegraphDir` = `repoRoot/.codegraph`. Prefer `query.ResolveCodegraphDir(repoPath)`
       when it succeeds, so an invocation from a subdirectory watches the same directory the
       query engine will open; fall back to `repoRoot/.codegraph` when it returns
       `query.ErrNotInitialized` (`internal/query/resolve.go:18`, `:44`), which is exactly the
       un-indexed case.
    3. `storeDir` = `codegraphDir/store`, using the store subdirectory name (`store`, per
       `internal/query/engine.go:20`) — never a hard-coded path from the repo root.

    Implement one small idempotent function, called `armWatches`, holding this rule:

    - Let `deepest` be the deepest path in the chain that currently exists (`os.Stat` +
      `IsDir`). Ensure `deepest` is watched.
    - Ensure `deepest`'s immediate parent is watched too when it exists and is in the chain.
      The parent is what observes a `Remove` or `Rename` OF the watched directory — an index
      rebuild that replaces `store/` by rename silently invalidates a watch on `store/` alone,
      and without the parent the publisher goes permanently deaf with nothing to wake it.
    - Drop (`Remove`) any watch on a path SHALLOWER than that parent, so once `store/` is
      being watched, ordinary source-file churn at the repository root stops waking the
      publisher.

    That yields exactly three reachable states, at most two watches each:
    `{storeDir, codegraphDir}` · `{codegraphDir, repoRoot}` · `{repoRoot}`.

    Call `armWatches` (a) once at construction, (b) on every debounced flush, and (c)
    immediately on any raw `Create`, `Remove` or `Rename` event before that event is handed to
    the debouncer. It is three `os.Stat` calls and a set comparison — cheap enough to run on
    every wake, and running it on every wake is what makes re-arming automatic rather than a
    special case someone has to remember. `fsnotify.Watcher.Add` on an already-watched path is
    a no-op, so idempotence costs nothing.

    This is a deliberate, bounded exception to "do NOT copy `watch.Watcher`": what is rejected
    is that package's RECURSIVE walk and its re-`Add`-every-created-subdirectory machinery,
    which `.codegraph/store/` (a flat directory, 11 entries, zero subdirectories) does not
    need. A three-element fixed chain is not a recursive walk.

    Construction never fails because a directory is missing: `codegraph ui` must remain
    startable against an un-indexed repository, which is a shipped behaviour of `GetStatus`'s
    degrade path. It fails only if fsnotify itself cannot be created.

    Run the detector ONCE at construction so the publisher holds a `current` state before any
    subscriber arrives (Task 2's `Subscribe` seeds from it). Against an un-indexed repository
    that current state is a legitimate `initialized=false, store_exists=false` event at
    generation 1; the first real index then produces generation 2.

    Feed every filesystem event into the `Debouncer`, sized by `DebounceDuration()` (2000ms
    default, `CODEGRAPH_DEBOUNCE_MS` override). Pebble's directory is genuinely noisy —
    compactions, WAL rotation, MANIFEST churn and OPTIONS rewrites all touch it on their own
    schedule, independent of any re-index — so the debounce is an efficiency measure that
    keeps unnecessary open/read/close cycles off the store. Per D-01 the last-sync comparison
    from Task 1, not the debounce, is the correctness filter.

    On each debounced flush, run Task 1's detector and, when it reports a change, publish
    through Task 2's registry. Expose a constructor that takes a context and the repo path
    and returns a started publisher with a `Stop` that joins cleanly (debouncer `Stop` then
    `Wait`, then the fsnotify watcher's `Close`), so `Server.Serve`'s shutdown path can own
    the lifetime. Never write to stdout from this file.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem -> UI process | Untrusted, high-volume event source; another process (the daemon, a manual index) is the writer |
