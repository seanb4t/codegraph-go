<objective>
Close the root-cause glob bug that makes live file search return nothing for any
nested path. `FilesOptions.Pattern` today uses a matcher whose `*` never crosses a
`/` and which has no recursive wildcard, so a bare-term search pattern only ever
matches root-level files — found live during Phase 3's UAT, not assumed
(STATE.md, Phase 03 decision log).

This is not a UI-local defect. `Engine.Files` has three callers —
`internal/cli/files.go:46`, `internal/mcp/tools.go:512` and
`internal/uiserver/handlers.go:433` — and the fix lands once, for all three, by
adopting `github.com/bmatcuk/doublestar/v4` (D-14).

The verified fact this plan is built on: `doublestar.Match("**/*claude*",
"claudeassets.go")` returns `true`. `**` matches ZERO path segments as well as
crossing `/`, so root-level search — which works today — is preserved. That was
confirmed by executing a real Go program during research; this plan re-proves it
as a committed test carrying BOTH directions, because a nested-only test would
pass while root-level search silently regressed.

Purpose: WRK-02's multi-file picker (04-06) is unusable until file search works at
depth, and CLI/MCP users get the same fix for free.
Output: a recursive-glob-capable `Engine.Files`, a two-direction regression test,
and one folded todo closed with a resolution record.
</objective>

<feature>
  <name>Recursive glob matching for Engine.Files</name>
  <files>internal/query/files.go, internal/query/files_status_test.go</files>
  <behavior>
    Given an indexed corpus containing both `term.go` (root level) and
    `internal/foo/term.go` (nested):
    - `Pattern: "**/*term*"` returns BOTH entries.
    - `Pattern: "*term*"` returns only the root-level entry — existing
      non-recursive behavior for existing patterns is unchanged.
    - `Pattern: "internal/**/*.go"` returns the nested entry and not the root one.
    - `Pattern: "**/*.{go,ts}"` returns entries of both extensions.
    - `Pattern: "["` (malformed) returns a `FilesResult{}` and an error whose
      message begins `query: invalid pattern "["` — refused before the store is
      scanned.
    - `Pattern` composed with `Filter`, `Dir` and `Depth` narrows exactly as it
      does today; the glob change is orthogonal to the other three narrowings.
  </behavior>
  <implementation>Swap the matcher at both existing call positions in internal/query/files.go and update the exported option's doc comment. No new option, no new call site, no signature change.</implementation>
</feature>
