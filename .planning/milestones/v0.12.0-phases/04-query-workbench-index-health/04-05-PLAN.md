<objective>
Fill the `/health` placeholder so a developer can tell at a glance whether the
index they are reading is worth trusting.

Two facts shape this view. First, the verdict is NOT new work: Phase 3 already
produces a five-member `StatusVerdict` from `classifyStatus`, and
`StatusBanner.svelte` already renders it application-wide. D-04 reuses it
unchanged and forbids a second verdict function — two verdict functions over one
index can disagree, and the banner contradicting the health page about staleness
is precisely the repudiation failure HLT-02 exists to prevent. Second, every raw
number now arrives from one `GetHealth` call (04-03).

HLT-02's "above the raw numbers" and HLT-03's "impossible to miss" both look like
visual judgments and are not. Document order is a `compareDocumentPosition`
property; a loaded style hook is a `getComputedStyle` property. Phase 3 already
established that "requires a human" is a testable claim rather than a category —
two of its three `why_human` justifications turned out to be false. Both are
asserted in code here.

Purpose: HLT-01, HLT-02 and HLT-03 become true.
Output: a filled `/health` route with a trust verdict above the numbers, a loud
worktree warning, per-language file counts, and node and edge counts by kind.
</objective>
