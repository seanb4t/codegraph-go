<objective>
Lock GRF-01's pass condition as a committed artifact, then build the server-side
half of the file/package graph: `Engine.FileGraph()`'s aggregated rollup and the
cycle detector that rides with it.

Two things must be true before anything can be rendered, and this plan makes both
true. First, the pass condition GRF-01 is judged against must exist in git before a
single number is measured — a threshold chosen after seeing results can always be
made to endorse a pre-existing preference, and the ROADMAP names that ordering as
the point of the whole gate. Second, the spike needs real data at corpus scale to
render, and that data is `Engine.FileGraph()`.

Neither task is renderer work. `Engine.FileGraph()` is ENG-03 as written (D-05:
`BuildReverseAdjacency`'s fresh-per-call full-scan discipline, no precomputed
projection, no new record kind, no re-indexing), and cycle detection is locked
server-side by D-06 precisely so its correctness survives any renderer swap. Both
are therefore safe to build before GRF-01 resolves.

Purpose: make the blocking gate's pass condition auditable, and supply the spike
with real aggregated data.
Output: `corpora/graph-render-threshold.json`, `Engine.FileGraph()` in
`internal/query/traverse.go`, an iterative strongly-connected-component detector in
`internal/query/filegraph_cycles.go`, and Go coverage for both.
</objective>

<assumption_delta_decision>
**Signal.** The deterministic detector fired `{"kind":"chosen","term":"chosen"}` on
CONTEXT.md's phrase *"the renderer chosen by recorded measurement rather than by
assumption."*

**Noun examined:** `graph`. The `chosen` family means a derived value has become a
configuration parameter. Here "chosen" describes a *process* — a renderer selected
by measurement — not an identity-model change, so the literal trigger is shallow.
The substantive question the orchestrator raised is whether this phase pluralizes
`graph`: does introducing a file/package rollup alongside the existing symbol-level
graph make a singular noun plural?

**Decision: `no-change`.**

**Rationale.** It does not. ENG-03 forbids exactly the thing that would make it a
pluralization: *"no precomputed projection, no new record kind, no re-indexing."*
The rollup is a read-time derivation over the one stored graph, structurally
identical in kind to `BuildReverseAdjacency`'s reverse view
(`internal/query/traverse.go:31`) and `edgesByKind`'s per-kind tally
(`internal/query/status.go`) — neither of which pluralized `graph` when it landed,
and for the same reason. There remains exactly one persisted graph, one store, one
snapshot per call. What this phase adds is a second *view* at a second granularity,
which the codebase already models as a function return type, not as an identity.

Had this phase stored the rollup, minted a `filegraph` record kind, or given a
repository more than one indexable graph, `promote` would be the honest answer. It
does none of those, and the requirement that forbids it is the one this plan
implements.
</assumption_delta_decision>
