## Scope boundary: which expansion this plan owns

Two different expansions exist in this phase and conflating them is the specific
mistake this section exists to prevent.

| | Owned by | What happens |
|---|---|---|
| **directory → file** | **this plan** | The collapsed default shows a node per directory. Selecting one reveals the files inside it, as children of that directory. No request is issued: every file and every edge already arrived in the first response. |
| **file → symbol** | **05-07** (with 05-06's rpc) | Selecting a FILE fetches that file's symbols and reveals them as children of the file. Its three-click contract — expand, collapse to zero without a request, re-expand from cache, cumulative request count exactly one — was verified across review cycles and is not touched here. |

**In this plan, selecting a file node does nothing.** No handler, no stub, no
placeholder, no fetch.

**The shared seam, named explicitly.** Both expansions manipulate the same compound
parent/child relationship and both need an expansion state model. This plan builds that
model as a *pure recomputation*: `rollupToElements(response, expandedDirs)` returns the
complete element set, the route holds the expanded-directory set, and `GraphCanvas`
applies whatever element array it is handed to the live instance and re-runs the layout
without reconstructing anything. 05-07 extends that by adding a **second input** — a map
from file path to its already-fetched symbol list — to the same function, and by routing
its file expansions through the same ceiling check. It does not add a second mechanism
and it does not mutate the renderer instance directly.
