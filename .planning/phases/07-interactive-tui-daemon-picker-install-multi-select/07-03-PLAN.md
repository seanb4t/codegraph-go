<objective>
Add the PPID watchdog: a small joined poll goroutine that cancels the daemon/watcher ctx when the supervising host/agent process dies, so a daemon never outlives its parent (DMON-03).

Purpose: Per D-07 the watchdog captures the original ppid and treats reparenting (getppid changing away from that captured value — robust to subreapers per RESEARCH Pattern 5) as parent death; it is build-tag split (`watchdog_posix.go` / `watchdog_windows.go`) mirroring the existing `procstart_linux.go` / `procstart_other.go` precedent, but split POSIX-vs-Windows. Per D-08 it lives in charm-free `internal/daemon`, does nothing but cancel ctx, and follows `daemon.Run`'s exact `wg.Wait()` join discipline so the package's goleak gate stays clean. 07-05 wires `startWatchdog` into `daemon.Run`.

Output: watchdog files + tests, x/sys promoted to a direct require (Windows file imports it), and the CI Windows `go vet` gate extended to `./internal/daemon/`.
</objective>

    - The returned stop func() blocks until the goroutine has actually returned (join), whether the goroutine exited via ctx.Done() or via detecting a reparent.
    - With an injectable ppid source, a simulated reparent (source returns a value != original) causes cancel() to fire within a bounded time; ctx cancellation causes the goroutine to exit without calling cancel().
    - No goroutine survives after stop() returns (goleak-clean).
