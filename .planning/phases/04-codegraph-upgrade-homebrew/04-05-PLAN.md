<objective>
Close the download-then-execute hazard in `verify:self-upgrade`, and make the repository's
several restatements of its own release-identity policy provably agree with the one the
upgrade path actually enforces.

Purpose: `verify:self-upgrade` downloads a prior release's raw binary, `chmod +x`es it, and
executes it, with no signature check anywhere in between. That is the identical ordering
hazard this milestone already fixed for `verify:notarized-suite` (T-02-19). Leaving it
unremarked three targets away in the same file reads as ignorance rather than a scoped
decision. The certificate-identity regex is currently restated by hand in four places with
nothing asserting they agree with the compiled pattern — exactly the "second policy that can
drift" the phase context warned against.

**Requirement linkage, stated rather than fudged:** this plan carries `UPGR-01` because
`verify:self-upgrade` is the CI target that exercises `codegraph upgrade` end to end — the
same command whose brew-refusal branch UPGR-01 defines. The work itself is a folded todo,
not a direct requirement deliverable, and this SUMMARY should say so.

Output: a cosign gate above the chmod in `verify:self-upgrade`, and a shape test proving
every identity literal in the repository is behaviourally identical to
`releaseWorkflowRefPattern`.
</objective>
