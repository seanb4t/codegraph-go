<objective>
Build the two status renderers. TS ships TWO structurally different status
renderings and we need both (D-17):

- **CLI** (`bin/codegraph.js` ~900-985) — padded columns: `Index Statistics:` /
  `  Files:     1,234` / `  DB Size:   1.23 MB`, with `padEnd(15)` breakdowns.
  This is D-09's target.
- **MCP** (`mcp/tools.js` ~3890-3945) — bolded-key bullet lists:
  `**CodeGraph Status**`, `**Files indexed:** N`, `**Database size:** X.XX MB`,
  `**Nodes by Kind:**` + `- kind: count`, `**Languages:**` + `- lang: count`.

D-16's first draft assumed MCP `status` was already markdown. It is not — it
emits JSON today via `MarshalStatusJSON` (`tools.go:339-343`). Only 2 MCP tools
are markdown (`explore`, `node`); 6 are JSON. D-12's blockquote-warning
requirement is meaningless prepended to a JSON blob, so the MCP renderer is
latent scope D-12 already demanded, not a new capability.

Purpose: the sections, fields, ordering, and wording. Phase 6 (TUI-02) paints
them — do not introduce `charm.land`/lipgloss imports here.
Output: `internal/query/render_status.go` + its unit tests.

★ `MarshalStatusJSON` is NOT touched — the CLI `--json` path still uses it, same
additive rule as SURF-06.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| indexed language/kind names → rendered breakdown rows | Map keys originate in the indexer's language specs and third-party source |
| `StatusResult.WorktreeMismatch` absolute paths → both rendered forms | Host paths reach CLI stdout and MCP tool output |
| `projectPath` argument → `RenderStatusText`'s `Project:` line | A caller-supplied path is echoed back |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-19 | Information Disclosure | the warning's absolute `worktreeRoot`/`indexRoot` in both renderings, and `Project:` in the CLI form | medium | accept | Same accepted exception as T-02-14, documented in `StatusResult`'s decision table by plan 02-04. The CLI's `Project:` line is printed to the operator's own terminal about the operator's own repo and mirrors TS exactly. The paths appear ONLY in the mismatch case; a clean tree renders nothing extra. |
| T-02-20 | Denial of Service | unbounded breakdown row count | low | accept | Row counts are bounded by the number of distinct node kinds (a fixed schema vocabulary) and registered language specs (a compile-time list) — neither scales with repo size or attacker input. `sortedCounts` sorts a map whose cardinality is single-digit-to-low-double-digit in practice. |
| T-02-21 | Tampering | a symbol/language name containing markdown control characters distorting the MCP rendering | low | accept | Language and kind keys come from the indexer's own fixed vocabularies, not from arbitrary source text — an attacker-authored file cannot inject a new language key. The existing `RenderExplore`/`RenderNode` renderers already emit far less constrained third-party strings into markdown. |
| T-02-22 | Tampering | a future edit collapsing the two renderers into one, silently breaking D-12's blockquote or D-09's columns | medium | mitigate | Prevented by construction and by test: both renderers carry doc comments naming their single owning surface, and Task 1's Test 10 asserts `RenderStatusMarkdown` does NOT contain the CLI's `Index Statistics:` header — a collapse fails that assertion immediately. |
