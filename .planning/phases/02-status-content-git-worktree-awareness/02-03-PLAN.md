<objective>
Add the five markdown renderers SURF-06 needs, as SIBLINGS of the existing
`Marshal*JSON` helpers — never as replacements (D-16). This plan creates the
renderers and their unit tests only; plan 02-06 changes the `internal/mcp`
call sites that use them.

Purpose: the 5 JSON-shaped MCP read tools currently pay parser tax with no
parser — nothing unmarshals MCP text content, which is model-facing. Markdown
closes a TS divergence (TS returns markdown from every MCP tool), cuts `files`
from 28,506 to ~16,835 bytes (-41%, measured on this repo's index), and lets
all 7 non-status read tools take one uniform notice mechanism.
Output: `internal/query/render_results.go` + its unit tests.

★ THE HIGHEST-RISK RULE OF THIS PLAN (D-16, verified by exhaustive grep):
**every `Marshal*JSON` helper is SHARED with the CLI `--json` path** —
`MarshalCallersJSON` is called from `internal/cli/callers.go:41` AND
`internal/mcp/tools.go:248`; `search` has no helper and inline-marshals on
both surfaces. Those bodies are simultaneously the CLI contract and the golden
parity oracle. SURF-06 is strictly ADDITIVE: **never modify a `Marshal*JSON`
body.** This plan does not touch `traverse.go`, `files.go`, or `search.go`
except to read them.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| indexed symbol names / file paths → rendered markdown | Names originate in third-party repo source and flow into text a model consumes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-10 | Tampering | markdown table rows built from indexed symbol names | low | accept | A symbol name containing a pipe or backtick can visually break a table cell. This is cosmetic, not a trust boundary crossing: the identical strings already flow verbatim into `RenderExplore`/`RenderNode` markdown today, and into the `--json` payload. The consumer is a model reading a read-only report with no action surface. Escaping would diverge from the existing `formatNodeRef` convention for zero security gain. |
| T-02-11 | Information Disclosure | rendered paths | low | accept | Renderers emit only the repo-relative `FilePath`/`Path` values already present in today's JSON output. No absolute host path is introduced by this plan. |
| T-02-12 | Tampering | accidental mutation of a `Marshal*JSON` body breaking the CLI contract and the golden oracle simultaneously | high | mitigate | Structurally prevented: `Marshal*JSON` bodies live in `traverse.go`/`files.go`/`search.go`, none of which appear in this plan's `files_modified`. Enforced by the `git diff <those files>` empty-check in every task's acceptance criteria. RESEARCH notes this hazard is LOUD, not silent — 7 CLI tests across 3 files would catch it instantly — but the diff check makes it impossible rather than merely detectable. |
| T-02-13 | Denial of Service | unbounded rendered output for a large result set | low | accept | Every renderer's row count is bounded by the result slice the Engine already produced under its own `limit`/`depth` validation (`validateLimit`, `validateFilesDepth`, `MaxDepth`). Markdown is strictly SMALLER than the JSON it replaces (-41% measured on `files`), so this plan reduces rather than increases payload size. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable — zero new dependencies (stdlib `fmt`, `strings` only). `go.mod`/`go.sum` must be unchanged by this plan. |
</threat_model>
