<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `--path` flag / cwd → `resolveStartPath` → `Engine.startPath` → git subprocess | Operator-supplied directory reaches a subprocess working directory |
| CLI stdout → the operator's terminal, and any `jq`/script pipeline consuming `--json` | Rendered text and JSON cross to downstream tooling |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-31 | Tampering | the notice line corrupting `--json` output for `jq`/script/CI consumers | high | mitigate | The print is gated strictly inside each command's human-output branch, after the `if jsonOut { ...; return }` early return — TS's own `status --json` branch returns before its `warn()` call, the precedent for this. Enforced by Task 1's Test 9, by the placement criterion in Task 3, and structurally by `query_cli_test.go`'s four untouched `json.Unmarshal` guards, which would fail instantly on a stray prefix. |
| T-02-32 | Information Disclosure | `Project:` and the warning's absolute paths on stdout | low | accept | The CLI prints the operator's own repo path to the operator's own terminal, exactly as TS does. This is a strictly weaker exposure than the MCP case (T-02-25), which is itself an accepted, documented exception. Note the CLI surface has no untrusted consumer — unlike MCP, there is no agent boundary here. |
| T-02-33 | Elevation of Privilege | `--path` pointing anywhere on the host | low | accept | Intentional and pre-existing: the CLI is invoked by the operator, who already has shell access. `confineToRepoRoot` exists specifically for the MCP surface, where the caller may be an agent processing attacker-influenced content — it is deliberately not a CLI concern, and this plan does not change that asymmetry. |
| T-02-34 | Denial of Service | git subprocesses added to every read command | low | accept | The CLI is one-shot: at most one detection per invocation, `sync.Once`-guarded on the Engine (plan 02-04) and bounded by `gitmeta`'s 5s per-subprocess timeout. Worst case adds under 5s to a command that already opens a Pebble store and scans a graph; typical case is a few milliseconds. The per-invocation `CachingDetector` is free precisely because there is nothing to amortize. |
| T-02-35 | Tampering | a silent false negative from an unabsolutized relative `--path` | medium | mitigate | `resolveStartPath` returns the raw `--path` value unresolved; plan 02-04's `filepath.Abs` in `OpenAt` is the fix (Pitfall 3). Task 1 guards it by passing a RELATIVE `--path` in at least one notice row — a regression surfaces as a failing assertion rather than a silently missing warning, which is the dangerous shape here. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable — zero new dependencies; only the existing `internal/query` import is used. `go.mod`/`go.sum` must be unchanged by this plan. |
</threat_model>
