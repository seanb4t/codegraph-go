<objective>
Prove on the wire that a client which opts into `subscriptions/listen` actually
receives `notifications/tools/list_changed` when Phase 3's per-request catalog
re-check mutates the tool set mid-session — and assert the one silent-failure
mode that makes the difference between a live subscription and a dead one.

Purpose: SPEC-09 is the milestone's last open requirement, and 05-CONTEXT D-01
establishes that nearly all of it already works. Criterion 1 is already true in
all 27 frozen transcripts. `subscriptions/listen` already acknowledges and
returns a `subscriptionId`. Phase 3's `AddTool`/`RemoveTools` re-check already
fires `changeAndNotify`. The single unproven claim — the one this plan exists
for — is that those two halves are actually connected for an opted-in Modern
stream. Nobody has observed it. This plan observes it, freezes it, and makes it
fail loudly if it ever stops being true.

Output: one new frozen wire transcript, two new harness fields that make a
long-lived notification stream capturable without sleeps, three hand-authored
spec anchors that hold against a fresh capture, and two recorded RED
demonstrations.
</objective>
