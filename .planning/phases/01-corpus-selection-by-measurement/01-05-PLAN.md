<objective>
Build the measurement pipeline: the typed record split into generated observations and curated
selection, the tool that produces observations by driving this repository's own indexer and
query engine in-process, and the pure renderer that turns both committed files into the
human-readable document.

Purpose: FIXT-01 requires a committed record naming every candidate actually indexed with real
per-kind edge counts and per-language file counts. D-06 fixes the shape: JSON as source of
truth, prose generated. This plan builds the machine; Plan 01-06 runs it and makes the
selection.

## Why the record is TWO files, not one

The first draft of this plan had `-mode measure` reconstruct a single `corpora/measurements.json`
containing both the measured observations AND the curated selection metadata — thresholds, the
threshold rationale, the locked set, the rejected-candidate ledger, the per-kind supplier map.
Plan 01-06 then hand-added that metadata and re-ran `task corpora:measure`.

**That design silently destroys the curated half on every regeneration.** Nothing preserved it,
because the generator owns the file and rebuilds it from indexing. D-15 requires the chosen
threshold N to be frozen *with its rationale recorded*; a rationale that a routine re-measure
deletes does not satisfy that, and the drift guard D-07 exists to run would start passing
against a record whose policy fields had quietly emptied.

The fix is ownership, not merge logic:

- **`corpora/observations.json`** — generated. Fully reconstructed by `task corpora:measure`.
  Contains only what indexing measured. Never hand-edited.
- **`corpora/selection.json`** — curated. Written by a human (Plan 01-06). Contains only policy:
  per-kind thresholds, the threshold rationale, the locked set, the rejected-candidate ledger,
  and any synthetic declarations. **The tool never writes this file**, so no regeneration can
  erase it.

Two files with one owner each beats one file with a merge step: a merge is code that can be
wrong, whereas "the generator has no write path to that file" cannot be. It also makes the
drift guard's job honest — Plan 01-07 derives the coverage claim by reconciling policy against
evidence, which is only meaningful when the two are separable.

Output: `internal/corpora/record.go`, `tools/corpora -mode measure` with a `-repos` scope,
`tools/corpora/prose.go`, and the `corpora:measure` target — smoke-proven end-to-end against
one real fetched corpus before Plan 01-06 does the sweep.

    - `ComputeThresholds(obs Observations, eligible []string) map[string]int64` — for each
      `query.RankEdges` kind, let `best` be the highest count for that kind across the ELIGIBLE
      measured candidates (every candidate with an observation, regardless of lock state), and
      return `min(max(2, best/2), best)` using integer division.

      The universe is deliberately **all measured eligible candidates, not the locked set.** An
      earlier draft computed `best` across the locked candidates while the locked set was itself
      chosen to satisfy the resulting thresholds — each input required the other, multiple fixed
      points could exist, and nothing proved which one was reached. Sourcing `best` from the full
      measured universe breaks the cycle: thresholds depend only on observations, and selection
      then depends on thresholds, in one direction.

      The outer `min(..., best)` is what makes every threshold SATISFIABLE BY CONSTRUCTION. Without
      it, a kind whose best observed count is `1` yields `max(2, 0) = 2` — a bar no measured
      repository supplies, so the guard would fail permanently on a kind that genuinely IS covered.
      That case is not hypothetical: `overrides` and `type_of` are the two at-risk kinds this whole
      search exists for, and a count of one is entirely plausible for them. With the clamp,
      `best == 1` yields a threshold of `1`, which equals the roadmap's non-zero floor — D-14's
      tightening is arithmetically unavailable for a kind with a single observed edge, and the
      honest response is to say so in the record rather than to invent a bar nothing can clear.

| Boundary | Description |
|----------|-------------|
| Third-party corpus source → this repository's indexer | Arbitrary, occasionally adversarial third-party code is parsed |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05-01 | Information Disclosure | committed measurement artifacts | medium | mitigate | `StripVolatile` removes both path fields, the worktree-mismatch object, the staleness flag and every key the golden policy names, before anything is written. | T-01-05-02 | Tampering | curated policy destroyed by regeneration | high | mitigate | **The reason the record is two files.** The generator has NO write path to `corpora/selection.json`, so no regeneration can erase the threshold, its rationale, the locked set or the rejected ledger. | T-01-05-03 | Denial of Service | indexing arbitrary third-party source | medium | accept | The indexer parses untrusted third-party code through CGo tree-sitter grammars whose external C scanners can in principle crash the host process.
