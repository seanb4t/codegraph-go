<objective>
Build the measurement-record pipeline: the typed record, the tool that produces it by driving
this repository's own indexer and query engine in-process against a fetched corpus, and the
pure renderer that turns the committed JSON into the human-readable document.

reports real per-kind edge counts and per-language file counts. D-06 fixes the shape: JSON as
source of truth, prose generated. This plan builds the machine; Plan 01-06 runs it and makes
the selection.

Output: `internal/corpora/record.go`, `tools/corpora -mode measure`, `tools/corpora/prose.go`,
and the `corpora:measure` Taskfile target — all smoke-proven end-to-end against one real
fetched corpus before Plan 01-06 does the full sweep.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Third-party corpus source → this repository's indexer | Arbitrary, occasionally adversarial third-party code is parsed |
| Local machine state → committed measurement artifacts | The tool runs on a developer or CI machine and writes files that are committed and published |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05-01 | Information Disclosure | committed measurement artifacts | medium | mitigate | `StripVolatile` removes both path fields, the worktree-mismatch object, the staleness flag and every key the golden suite's existing volatile policy names, before anything is written. Asserted by a table-driven test covering each key individually plus a nested case, and by an acceptance criterion checking the produced record directly. |
| T-01-05-02 | Denial of Service | indexing arbitrary third-party source | medium | accept | The indexer parses untrusted third-party code through CGo tree-sitter grammars, whose external C scanners can in principle crash the host process. This is the documented, already-accepted CGo exception recorded in `PARSER-DECISION.md`; the measurement tool runs offline in a developer or CI context, not as a service, so a crash is a loud failure rather than an availability incident. No new exposure is introduced by this phase — the same grammars already index user repositories. |
| T-01-05-03 | Tampering | measurement record determinism | high | mitigate | A record that reorders itself between runs would make Plan 01-07's drift diff meaningless and would train reviewers to ignore it. Mitigated by sorting map keys and using stable indentation before writing, and verified by an acceptance criterion requiring two consecutive runs to produce byte-identical files. |
| T-01-05-04 | Repudiation | silently omitted corpus | high | mitigate | A measurement that skipped an unavailable corpus would produce a coverage claim with nothing behind it while still exiting zero. The tool fails loudly and non-zero on a missing corpus directory, and the acceptance criteria assert both that behaviour and the absence of any skip call in the tool. |
| T-01-05-SC | Tampering | dependency surface | low | accept | Zero new `go.mod` entries and no package-manager install; the npm/pip/cargo Package Legitimacy Gate does not apply. |
</threat_model>
