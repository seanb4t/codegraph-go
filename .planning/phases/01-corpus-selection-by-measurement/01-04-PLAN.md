<objective>
Create the corpora manifest as the sole pin authority, the typed Go package that loads and
strictly validates it, and the Taskfile targets that fetch a pinned corpus reproducibly into
an out-of-tree cache without vendoring anything.

Purpose: FIXT-02. There is no existing fetch-at-pinned-SHA path in this repository, and the
only current corpus resolution (`golden_parity_test.go`'s `resolveWeftCorpus` and
`resolveColbymchenryCorpus`) does a runtime clone and then skips the test on failure. That
self-skipping behaviour is precisely the failure mode this phase's fetch target exists to
retire, so nothing written here may copy it.

**CI caching, however, is NOT new here** — CONTEXT.md D-13, RESEARCH.md and PATTERNS.md all
state it is, and all three are wrong: they grepped for the literal string `actions/cache`
(genuinely zero hits) rather than enumerating every `uses:` line. The repository already
caches with `namespacelabs/nscloud-cache-action` in nine places across `ci.yml` and
`bench.yml`. Plan 01-07 carries the full correction and the mechanism decision. What it means
for THIS plan is one concrete design constraint: that action has no cache-key input, so the
content-addressing D-13 wanted must come from `Entry.Dir`'s SHA-bearing destination path.
That makes the path scheme below load-bearing rather than cosmetic.

Output: `corpora/manifest.json`, `internal/corpora`, `tools/corpora`, and three Taskfile
targets. The manifest is seeded with every candidate this phase will measure, all marked
unlocked — Plan 01-06 flips the locked flags on the set the measurement actually justifies.

**Candidate seeding, and a gap this plan surfaces.** The roadmap's shortlist is `gohugoio/hugo`,
`nestjs/nest`, `google/guava`, `apache/arrow`, and it is explicitly a starting point rather
than a decision. RESEARCH live-verified that `apache/arrow` contains **zero C#**, so it does
not solve the C# gap it was nominated for and is disqualified before measurement. Removing it
opens a **second** gap RESEARCH did not call out as loudly: with arrow gone the shortlist
contains **no Python source at all**, and criterion 2 requires a non-zero Python file count.
Both gaps are seeded here as candidate entries.

    `corpora:fetch-one` — fetches exactly the entry named by the `CORPUS_REPO` and
    `CORPUS_SHA` environment variables. Steps, in order:

    1. Refuse with an error-annotated message and a non-zero exit if either variable is unset
       or empty.
    2. Re-validate both before any interpolation: the sha must be exactly 40 characters drawn
       only from lowercase hex; the repo must contain exactly one slash and otherwise only
       letters, digits, dots, underscores and hyphens. Use shell pattern matching against a
       negated character class, not a substring search, and quote every expansion throughout.
       This duplicates the Go-side allowlist deliberately — the Go program is the source of
       truth, and this is the last line of defence at the actual interpolation point.
    3. Resolve the destination as the corpus root joined with the slug, an at-sign and the
       sha, obtaining the root from the tools program rather than re-deriving it.
    4. If the destination already exists and its checked-out HEAD equals the pinned sha,
       print that it is already present and exit zero. This is what makes the target
       idempotent with no force flag.
    5. Otherwise remove any stale sibling partial directory, create a fresh one, and inside it
       run the four-step shallow fetch: initialise a repository, add the origin remote for the
       validated repo, fetch at depth one for the pinned sha, and check out the fetched head.
       Keep the real git directory — a tarball download is explicitly rejected by D-11 because
       it would leave the gitmeta and worktree-mismatch code path unexercised across every
       corpus.
    6. Assert the staged tree's checked-out HEAD equals the pinned sha, and only then rename
       the partial directory onto the destination. The rename is the commit point: an
       interrupt at any earlier step leaves only a partial directory, which step 5 deletes on
       the next run, so a later run can never mistake an interrupted fetch for a complete one.

    `corpora:assert-one` — the positive assertion, run on BOTH the cache-hit and cache-miss
    legs in CI. Given the same two environment variables it asserts the destination exists,
    contains a git directory, has a checked-out HEAD equal to the pinned sha, and tracks a
    non-zero number of files; it prints that file count. It exits non-zero if any of those is
    false. It must never print a success line without having established all four facts — a
    guard that only reports absence of failure passes vacuously the moment its subject stops
    existing (rule `84d1gfpywd`).

    `corpora:fetch` — loads the locked entries from the tools program and invokes the
    single-entry fetch for each. It exits non-zero with an error-annotated message when the
