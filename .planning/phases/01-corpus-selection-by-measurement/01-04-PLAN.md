## An existing pinned-corpus manifest — and why this phase builds a second one anyway

**`tools/bench/realcorpus/manifest.go` already is a pinned-SHA corpus manifest.** Both
`01-RESEARCH.md` and `01-PATTERNS.md` assert that no manifest of this shape exists, and
`01-PATTERNS.md` files it under "No Analog Found". **That premise is wrong and is corrected
here.** What exists:

`tools/bench/realcorpus/` (`manifest.go`, `manifest_test.go`), consumed by
`tools/bench/runner/main.go`:
`Entry{Name, SourceURL, Tag, CommitSHA, License, SelectionRule, QueryTerms, EnvVar, SiblingDir}`,
`Corpora()`, `Entry.Resolve()`, `ErrNeedsClone`, `repoRootDir()`. Three pinned entries:
`weft-go` (Apache-2.0), `colbymchenry-codegraph` (MIT), `cockroachdb-pebble` (BSD-3-Clause).
Its package doc already settles things this plan re-derives — "Every entry MUST carry a commit
SHA — never just a branch or tag name", and the V5 clause "no attacker-controlled or unpinned
ref is ever resolved into a subprocess argument", which is the same threat authored below as
`T-01-04-01`.

**Decision: build `internal/corpora` as a separate package. Four reasons, none of them
"we didn't look".**

1. **Its resolution model is the opposite of what FIXT-02 needs.** `Entry.Resolve()` is path
   *discovery* — env var, then sibling directory, then `ErrNeedsClone` — and its package doc
   promises "This package performs no network I/O", pushing every fetch onto the caller.
   FIXT-02 requires a Taskfile target that *fetches reproducibly*. Extending `realcorpus` means
   either breaking that stated no-network contract or leaving the fetch outside it anyway,
   which is what this plan already does.
2. **The licence policies conflict structurally.** `realcorpus` deliberately carries
   BSD-3-Clause (`cockroachdb-pebble`); FIXT-01 requires every candidate be MIT or Apache-2.0,
   so `corpora.Validate` must REJECT BSD-3-Clause. Sharing one type would force a
   policy-parameterised validator, or invalidate the benchmark corpus, or silently widen
   FIXT-01's licence bar. All three are worse than two manifests.
3. **`realcorpus` is Phase-6-owned and is about to be dismantled.** Its package doc opens: "the
   pinned real-repo manifest for the PERF-01 head-to-head benchmark: the freshly-built Go
   `codegraph` binary vs the installed TS `codegraph@1.3.1`." BENCH-01 retires those numbers,
   BENCH-02 removes the comparison runner, and FIXT-04 deletes the `weft-go` and
   `colbymchenry-codegraph` corpora — two of its three entries. Building Phase 1's load-bearing
   manifest on a structure Phase 6 is taking apart would couple the *blocking* spike to the
   *last* phase of the milestone, inverting the dependency direction the roadmap set up.
4. **Different lifecycle.** `realcorpus` is a compile-time Go literal; changing a pin is a code
   change. This manifest must be readable by bash and by a CI path derivation without compiling
   Go.

**What Phase 6 inherits, stated explicitly so it is not a surprise:** after this phase the
repository has TWO pinned-corpus manifests. Phase 6 already has to touch `realcorpus` for
BENCH-01/02, and reconciling them — most likely by reducing `realcorpus` to whatever survives
the head-to-head removal and pointing it at `internal/corpora` — belongs there, with the
benchmark rewrite, not in a blocking spike. **This is a recorded hand-off, not a deferral of
something Phase 1 should have done.**

**What this plan takes FROM `realcorpus` rather than reinventing:** its `EnvVar`-then-
`SiblingDir` resolution shape is the precedent `CODEGRAPH_CORPUS_DIR` follows; its
`SelectionRule` field already records "entire repo at CommitSHA", which is D-10's whole-repo
rule with a precedent; and `manifest_test.go`'s `TestCorporaProvenanceComplete` (every field
required) is the analog for this package's own round-trip test.

**And one defect it hands us as a warning.** `tools/bench/runner/main.go:482`'s `pinnedAt()`
validates an existing local checkout by `git rev-parse HEAD` alone, then trusts the tree. That
is exactly the weakness the cross-AI review flagged in this plan's first draft. The hardened
four-part check below is written so Phase 6 has a stronger pattern available when it
reconciles — the fix belongs in the new code first, not as a drive-by edit to a benchmark path
this phase does not otherwise touch.
