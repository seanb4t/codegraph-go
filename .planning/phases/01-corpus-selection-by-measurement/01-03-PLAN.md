<objective>
Re-freeze the one wire-oracle transcript that D-02's change invalidates, and add the two
positive assertions that prove the new keys are reachable through the real MCP and golden
surfaces rather than only through renderer unit tests.

Purpose: FIXT-01's measurement record is produced by `codegraph status --json` directly, and
D-02 accepted that Phase 1 owns the resulting transcript re-freeze. This is deliberately its
own reviewed diff: the milestone's ordering rationale states that a change must be
attributable to one named cause, and the repo's established discipline (v0.3.0 Phase 3's
consolidated pass, v0.10.0 Phase 8's 38-transcript re-freeze) is that a feature diff and a
transcript diff never share a commit.

Output: a re-frozen `call-status.golden`, a D-05 sparsity assertion driven through the real
MCP server, and golden-parity presence assertions for `edgesByKind` and `filesByLanguage`.

**Two corrections this plan carries, both verified against the tree:**

1. CONTEXT.md names `resources-read-status.golden` as the re-freeze target. That is wrong.
   The transcript embedding live `StatusResult` data is `call-status.golden` — the
   `codegraph_status` TOOL CALL, whose result is `query.RenderStatusMarkdown`'s output.
   `resources-read-status` reads the static documentation resource and does not change.
2. RESEARCH's Open Question 1 and VALIDATION.md's Wave-0 list both record the transcript
   re-freeze mechanic as unknown, possibly requiring a new capture helper. **It exists.**
   `test/wireoracle/cmd/wireoracle` is the purpose-built human-redirect capture entrypoint;
   its own package doc states it prints only the normalized transcript to stdout and that
   freezing is "a deliberate, reviewable, human-run `> file` redirect, never an automated
   regeneration path." No new tool is needed and none should be written.

   **The missing update flag is a LOCKED design decision, not a gap to fill.** v0.3.0 Phase 1
   chose "no-regenerate-flag plus a CI cross-change guard" deliberately, and recorded that when
   goldens are regenerated, an approved reviewed diff is the only control. That is why
   `tools/transcriptfreeze` is an anti-regeneration guard rather than a writer, and why
   `TestFrozenTranscriptsMatch` simply fails on mismatch. A future reader who encounters the
   absent flag should read it as the decision it is. Do not add one, here or later, without
   revisiting that decision explicitly.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Live capture output → committed `.golden` oracle | Bytes produced by a locally built binary become the frozen regression baseline every later CI run compares against |
| MCP server → agent client | The argument-less `codegraph_status` response crosses to an untrusted-consumer surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03-01 | Tampering | `call-status.golden` re-freeze | high | mitigate | A re-freeze rewrites the oracle, so a real regression captured during the freeze would be frozen AS correct. Mitigated by three controls: the diff is read and confined to the one expected insertion before the move; the positive count assertion requires exactly one transcript file to change; and the freeze lands as its own commit so the reviewed diff contains nothing else to hide behind. |
| T-01-03-02 | Tampering | capture-to-golden redirect | medium | mitigate | Capturing straight onto the golden path truncates the oracle before the capture runs, so a capture failure destroys it. The action requires capture to a temp path, a non-empty and marker-bearing check, then a move — never a direct redirect. `statFrozenTranscript`'s existing zero-byte refusal is the backstop, not the primary control. |
| T-01-03-03 | Information Disclosure | frozen transcript content | low | accept | `normalize.go`'s existing substitution rules already replace the repo directory and the server version with placeholders before comparison, which is why a locally built binary's transcript is committable at all. No new host-specific field enters the transcript through the edges-by-kind block, which carries only kind identifiers and counts. |
| T-01-03-SC | Tampering | dependency surface | low | accept | Zero new `go.mod` entries and no package-manager install; the npm/pip/cargo Package Legitimacy Gate does not apply. Notably, no new capture tool is introduced either — the existing entrypoint is used. |
</threat_model>
