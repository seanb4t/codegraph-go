<objective>
Land the opt-in dense mode and the `Edges by Kind` section on all four `status` render
surfaces, deriving the dense key set from `query.RankEdges` rather than restating it.

Purpose: D-04's whole point is to make "absent" and "measured zero" un-confusable, which
FIXT-01 criterion 3 depends on — `overrides` and `type_of` are the two kinds this
repository's own idiomatic Go produces zero of, and a spike that cannot tell a missing
measurement from a measured zero cannot lock a corpus set on evidence. The measurement run
in Plan 01-06 uses the dense flag. D-04 also requires the key set be derived, so a future
tenth edge kind is measured automatically instead of silently dropped.

Output: `DenseEdgesByKind`, an unfiltered counts sorter, the new section in
`RenderStatusText` / `RenderStatusMarkdown` / `present.RenderStatus`, and the `--all-kinds`
CLI flag. RESEARCH found a **fourth** render surface CONTEXT.md's "all three surfaces"
framing undercounts — `internal/cli/present/status.go`, a package-local duplicate renderer
used only on a real TTY. Missing it would make a TTY user see different output than a piped
or CI user; Task 3 exists specifically to close that.
</objective>
