<objective>
Wire the two top-level Cobra commands that drive the agent registry: `codegraph install` and `codegraph uninstall` (D-02). Each resolves `--target auto|all|none|<csv>` (default auto) and `--location global|local`, resolves the absolute binary path via `os.Executable()` once (D-04, what makes the drop-in swap real), iterates `internal/agents` targets, and prints per-agent status. With a TTY and no `--target`, `install` presents an interactive multi-select prefilled with detected agents (extending the `confirm()` idiom); with no TTY / `--auto` / CI it falls back to `auto` without prompting (D-03). `uninstall` reports per-agent `removed` / `not-configured` / `unsupported`, never erroring on an unconfigured agent (D-08).

These commands contain NO agent-specific logic — all quirks live in the per-agent target files (06-02, 06-03). This plan is the thin-CLI delegation layer plus a live-agent verification checkpoint.

Purpose: Give users the `install`/`uninstall` entrypoints that make the 8-agent drop-in swap real and reversible.
Output: install.go + uninstall.go + root registration, CLI-level orchestration tests, and a human-verify checkpoint confirming a live agent sees codegraph_explore after install.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user CLI invocation → agent config filesystem | install/uninstall drive writes across many external config files under the user's home/project (via the per-agent targets) |
| CLI flag input → target selection | --target csv and --location are user input that select which files get written |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-04-01 | Tampering | An unknown/typo'd --target id silently doing nothing or writing to the wrong agent | medium | mitigate | ResolveTargetFlag surfaces an unknown csv id as a clear error and writes nothing (no partial write); a test asserts it. |
| T-06-04-02 | Denial of Service | Interactive prompt blocking a non-interactive/CI run forever | medium | mitigate | The no-TTY / --auto path never prompts — it falls through to auto (install) / all (uninstall) per D-03/D-08; a test asserts non-TTY resolution does not read stdin. |
| T-06-04-03 | Spoofing | MCP config pointing at a PATH-guessed `codegraph` a shadowing binary could hijack | low | mitigate | install records the absolute os.Executable() path (D-04), not a bare command, so the agent launches the exact binary install ran from. |
| T-06-04-04 | Elevation | install writing outside intended per-agent config paths (path traversal via agent id) | low | mitigate | Target selection is restricted to the fixed registry (no user-controlled path interpolation); each target owns fixed path resolvers (from 06-02/06-03). |
</threat_model>
