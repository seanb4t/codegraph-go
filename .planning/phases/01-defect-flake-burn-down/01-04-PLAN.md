<assumption_delta_decision>
**noun:** prior-store state (what `priorCoverageGeneration` classifies before a `--force` rebuild)

**decision:** `promote` — the three-way classification becomes the primary model. `ErrNotFound`
(never indexed → silent floor 0), `ErrStoreLocked` (a live holder → REFUSE before `RemoveAll`), and
corrupt/other (→ WARN, floor 0, then rebuild) are three distinct states, not one. The pre-existing
"tolerate everything to 0" collapse is demoted from the whole model to just the `ErrNotFound` case.

**rationale:** D-10 and D-11 require the locked and corrupt states to produce different, observable
outcomes (a non-zero exit before any destructive call vs. a warning followed by a rebuild), which a
binary readable/unreadable model cannot express; WINDOWS #36 / T-10-16 is exactly the harm of reading
a live holder as "never indexed" and wiping the store under it.

**suggested (not required) invariant:** a test asserting that every non-`ErrNotFound` classification
is distinguishable from never-indexed at the `--force` decision point — i.e. that the never-indexed
path is the only one that is both silent and destructive.
</assumption_delta_decision>

<objective>
Make `codegraph index --force` refuse to wipe a store that a live process is holding, and warn
rather than wipe silently when the prior store is unreadable for some other reason.

Purpose: `priorCoverageGeneration` collapses every `Open`/`Snapshot`/`GetMeta` failure to
`return 0`, and its caller then runs `os.RemoveAll(storeDir)` regardless. A daemon holding the
store therefore reads as "never indexed" and gets its store deleted underneath it — WINDOWS #36 /
T-10-16, accepted below the `high` gate at v0.13.0 Phase 10 with the fix named. This plan
implements the named fix and pins it with the lock-collision regression test WINDOWS #36 describes.

Output: an error-returning `priorCoverageGeneration`, a three-way classification at the call site,
and `internal/cli/index_lock_test.go`.

**TDD note:** Go tests are not TAP, so GSD's `tdd-red-evidence` parser cannot read them.
RED→GREEN is carried by this plan's Go-native verify gates plus pasted transcripts.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a live daemon/serve process holding the store → an independently-invoked `codegraph index --force` | two processes contend for the same on-disk store with no shared coordination other than the pebble LOCK; the CLI's read of that lock is the only thing standing between the holder and a `RemoveAll` |
| an outstanding client page token → the coverage generation stamped after a rebuild | a wiped store restarts at generation 1, which can alias onto a generation a still-live client's page token already carries (T-10-16) |
