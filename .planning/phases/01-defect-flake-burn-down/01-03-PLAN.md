<objective>
Give `CheckRegression` the corpus-identity guard it has never had, so a throughput comparison
across two different synthetic corpora refuses instead of silently producing a meaningless
verdict.

Purpose: GH #16 is open because `CheckRegression` compares GOOS/GOARCH, Runner and ScratchFS
but not `Repo` — the one field that says WHAT was measured. Pitfall 16 warned a naive guard
could false-positive on a legitimate corpus rename; RESEARCH.md § Investigation 5 read all
three write sites and confirmed the only values reaching this call path are the deterministic
`synthetic-seed{N}-count{M}` ids, so strict equality is correct and normalisation is
unnecessary — and the reason must be written down so a future refactor that routes
publish-mode metrics here sees the assumption.

Output: a fourth category-error guard in the same shape as the existing three, a `repoString`
degrade-empty helper, and four new subtests in the existing table.

**TDD note:** Go tests are not TAP, so GSD's `tdd-red-evidence` parser cannot read them.
RED→GREEN is carried by this plan's Go-native verify gates plus pasted transcripts.
</objective>
