Purpose: this is the phase's acceptance mechanism. `02-CONTEXT.md` D-03 chose it

a wire oracle proven still able to fail against the new backend.

## Two conflicts this plan resolves in the open

**1. One harness constant must move, and criterion 2 says harness code must not.**
`test/wireoracle/scenarios.go:155` declares `legacyOmittedVersionCoercion =
"2025-03-26"`, and `oracle_test.go` asserts the `legacy-omitted-version`
scenario's session line and `protocolVersion` anchor against it. Under go-sdk,
`negotiatedVersion("")` falls through to `2025-11-25` (`02-RESEARCH.md` Q4,
empirically confirmed). The suite cannot pass without that constant moving.

This is not "relaxing to make the suite pass" — the constant is a hand-authored
mirror of a transcript byte, which is exactly the category `02-CONTEXT.md`
D-01/D-02 permit to move with a named cause. The mechanism (`capture.go`,
`normalize.go`, `anchors.go`, `oracle_test.go`, `main_test.go`,
`normalize_test.go`) is untouched, and Task 3 proves it with a diff. Recorded
here so a verifier reading ROADMAP criterion 2 literally sees the reasoning
rather than an unexplained edit.

**2. The `legacy-unsupported-2026-07-28` rename is DEFERRED, deliberately.**
`02-CONTEXT.md` `<specifics>` suggests renaming it, since go-sdk does recognize
`2026-07-28`. It is not being done in this phase. A rename changes a scenario
`Name` — real harness code, plus a `.golden` filename — for a purely cosmetic
gain, against a criterion that asks harness code to stay unmodified, in a phase
whose calibration note says to cut anything that is assurance on top of
assurance. Phase 3 legitimately regenerates transcripts as its own reviewable
pull request (Phase 1 D-03's own note) and is the cheaper place to carry it.
Flagged, not silently dropped.
