<objective>
Close SDK-04 with one small test, not a framework.

Purpose: `mark3labs` turned a handler's bare `return nil, err` into a
protocol-level JSON-RPC error; go-sdk turns it into a tool-visible
`isError: true` result. The Go type signature is `error` in both cases, so
nothing in a compile or a code review surfaces the difference. Today's handlers
never took that path — every one of them called `mcp.NewToolResultError` — but
plan 02-01 deleted that boilerplate in favour of `return nil, nil, err`, which
means the difference now matters on every failure path in the product.

REQUIREMENTS.md SDK-04 asks for this to be "explicitly audited and asserted...
covered by an explicit test, not inferred from the unchanged Go type signature."
This plan is that test.

Output: `internal/mcp/error_mapping_test.go`, four assertions, one demonstrated
RED.

**Recalibration, recorded honestly:** `02-CONTEXT.md` D-08's sibling observation
applies here too. `02-RESEARCH.md` Q5 read `toolForErr`'s wrapper line by line
and then ran the real SDK, confirming the conversion produces the identical
shape `mcp.NewToolResultError` produced. So the expected finding is "no
divergence", and the test's job is to make that a checked fact with a live
failure mode rather than a conclusion in a document.
</objective>
