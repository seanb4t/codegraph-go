Build the `GraphStore` interface and its pebble/v2-backed implementation — the single most consequential design output of Phase 1 and the enforceable form of INDX-05 and the export half of ARCH-01. Expose snapshot-based lock-free reads, batched writes (one Batch per file-change/debounce window), range-scan iterators (callers/callees/impact/files), and a bulk graph export that re-imports losslessly. Prove the concurrency model with a `-race` many-readers/one-writer test, prove export/reimport with a round-trip test, and enforce the "no package bypasses the interface" boundary (D-04a) with a `go/packages` import-graph test.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller packages → GraphStore → Pebble | The interface is the only legal path to the engine; a bypass would break the concurrency and schema guarantees |
| concurrent readers ↔ single writer | Multiple snapshot readers run alongside one writer without locks |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Tampering / Elevation | a sibling package importing pebble/v2 directly, bypassing the interface | high | mitigate | `TestNoPackageBypassesGraphStore` (go/packages import-graph) fails the build if any non-graphstore package imports pebble/v2 (D-04a); enforced at test time |
| T-01-12 | Tampering (data integrity) | torn/partial reads during concurrent write | high | mitigate | Reads go through Pebble snapshots (consistent point-in-time); writes commit as one atomic Batch; `TestConcurrentReadersSingleWriter` proves `-race` cleanliness |
| T-01-02 | Tampering | key construction in the store paths | high | mitigate | Store constructs all keys via Plan 01-05's length-prefixed encoders — inherits the delimiter-injection guard; no raw `[]byte` keys in the store |
| T-01-13 | Denial of Service | per-symbol writes at monorepo scale | medium | mitigate | Batched writes (one Batch per file-change/debounce window) per D-04; plain Batch (not IndexedBatch) per RESEARCH anti-pattern |
</threat_model>
