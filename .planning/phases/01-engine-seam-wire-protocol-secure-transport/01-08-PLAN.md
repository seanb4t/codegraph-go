<objective>
Expand the UI's read surface from the tracer's single method to the seven reads whose
Engine results are already structured, and complete ENG-04's data path onto the wire.

Purpose: plan 01-01 proved one path end-to-end. Everything after it is expansion along a
shape that is already known to work. Seven of the Engine's reads — `Status`, `Search`,
`Files`, `Callers`, `Callees`, `Impact`, `Affected` — already return structured results, so
their mapping is mechanical and they can ship before the two seams plans 01-04 and 01-05
extracted. `GetNodeDetail` and `Explore` follow in plan 01-09.

Two of the mechanical mappings are less mechanical than they look. `Status` needs the
commit SHA, which only reaches this layer through plan 01-06's `(*Engine).IndexMeta` — the
data path whose absence made the previous version of this plan unachievable. And `Files`
returns a union: exactly one of a flat entry list or a nested directory tree is populated
per the requested format, so a single shared `FileEntry` message is not sufficient and the
tree shape has to be modelled too.

Each task in this plan adds proto rpcs and their handler implementations together. The
generated handler interface is a compile-time completeness check, so splitting proto from
handlers would leave the tree unbuildable between tasks.

Output: seven working read RPCs, one lifecycle seam, one error-classification function, and
a Status response that carries the indexed commit.
</objective>
