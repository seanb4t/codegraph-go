<objective>
Build the byte-identity oracle that ENG-01 and ENG-02 lean on — and that does not exist
today.

Purpose: 01-CONTEXT.md's D-04 was decided believing the 26 frozen goldens already act as
an output-regression net. Verified in source, they do not: `TestReFrozenGoldensValid`
checks only that each golden file exists, is non-empty, starts with `{`, parses as
`goldenCapture` and has a non-empty `Output`; it never re-invokes the Engine.
`TestCorpusBehavior_Go`'s own doc comment states it asserts named behavioral properties,
"not byte-diffs against a frozen golden". So ROADMAP success criterion 1's "every frozen
golden covering them passes unchanged" is, as written, satisfiable WITHOUT the output
being unchanged — exactly the vacuous shape rule `84d1gfpywd` names. Until this oracle
exists, D-04's mutation-proof has nothing to turn RED and plan 01-04's extraction cannot
be proven safe.

This plan runs BEFORE any extraction, against unmodified `Node()`/`Explore()`, so the
oracle's own correctness is established while the code under test is known-good.

Output: a shared capture-spec package, and a counted, non-vacuity-proven byte-diff
comparison over all 26 golden pairs.
</objective>
