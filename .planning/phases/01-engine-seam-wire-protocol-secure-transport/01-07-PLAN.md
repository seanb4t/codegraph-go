<objective>
Give both protobuf surfaces a codegen drift guard that reports what it compared, cannot
destroy a developer's work while doing it, and has been watched fail against each surface
independently.

Purpose: BLD-04 closes a gap that predates this milestone. There was no proto codegen drift
guard in this repository and no regeneration task in `Taskfile.yml` — no `go:generate`
directive, no Makefile target, no CI step. `internal/schema/roundtrip_test.go` tests
serialization round-tripping, not codegen currency. So the guard must cover the
pre-existing `internal/schema/graph.proto` as well as the new UI schema, which is exactly
why plan 01-01 had to absorb a one-time generated-header restamp on `graph.pb.go` before
this guard could be honest about what "no diff" means.

Two design choices are load-bearing and both come out of the cross-AI review. The guard
regenerates into a temporary tree and byte-compares rather than regenerating in place and
asking git what changed: in-place regeneration on a worktree that already contains a
developer's edit to a generated file overwrites that edit before reporting on it, which
turns a diagnostic into a data-loss event. And the guard reports a positive count of files
compared, because a drift guard that enumerated nothing is precisely the vacuous shape
rule `84d1gfpywd` names, and this repository already carries that defect class more than
once.

Output: `proto:drift`, its companion Go shape guards, a CI step, and the recorded RED
evidence for each surface.
</objective>
