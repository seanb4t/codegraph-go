<objective>
Extract the structured `NodeDetail` seam from `internal/query`, leaving `Node()`
byte-identical — including which candidates it reads from disk and which it does not.

Purpose: the UI must be a third consumer of `internal/query.Engine`, never a second
implementation of it. Eight of the Engine's ten read methods already return structured
results; `Node` and `Explore` are the two that return rendered markdown. `Node()` already
computes structured intermediate data before rendering — `fetchCalls`/`fetchCalledBy` for
the single-definition path, and a `fetch` closure over a shared reverse-adjacency map for
the multi-definition path. This plan exposes those pieces as a new method that stops
BEFORE the existing render call.

The multi-definition path is where a naive extraction goes wrong, and the design here is
shaped by that. `RenderNodeMultiDef` does not receive gathered candidates; it receives a
`fetch` callback and calls it lazily, only for matches below `nodeMultiDefHardCap`, with
the body-budget decision interleaved into the same loop. A flat struct with one `Node`,
one `Calls` and one `CalledBy` cannot hold per-candidate data at all, and an eager gather
over every match would perform I/O the current code never performs — surfacing a
`readSourceFile` error for a candidate today's code never touches. So the multi-definition
shape is modelled as what it actually is: a lazy per-candidate protocol.

Output: `NodeDetail` as a sum shape, one builder per shape, a counted reverse-adjacency
seam, and `Node()` reduced to a thin wrapper.
</objective>
