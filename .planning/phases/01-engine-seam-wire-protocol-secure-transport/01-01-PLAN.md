## Gate conventions (phase-wide canon — byte-identical in all eleven plans, and checkable)

This section is replicated verbatim across `01-01-PLAN.md` … `01-11-PLAN.md`. The claim is
checkable rather than merely asserted — one command, run from the phase directory, prints
**one** distinct digest if the eleven copies agree and more than one if any has drifted:

```
for f in 01-*-PLAN.md; do sed -n '/^## Gate conventions/,/^<tasks>$/p' "$f" | shasum; done | sort -u | wc -l
```

A future planner editing one copy must edit all eleven, and this is how a reviewer catches it
if they do not. (Nothing at execution time changes this section, so no `<automated>` gate owns
it — the drift risk is at planning time, which is where the check belongs.)

**`--- PASS` counting.** `go test -v` prints one `--- PASS:` line for the parent test
function AND one for every `t.Run` subtest, including nested ones. Every PASS floor in this
phase counts BOTH: a test function with three subtests contributes FOUR lines, so
`rg -o -e '--- PASS' | wc -l` over `go test -v` output equals
`len(test functions) + len(all subtests)`. Derive every floor that way and show the
arithmetic in the acceptance criterion that states it, so a reviewer can check the floor
instead of re-deriving it.

**Echo label.** Every gate prints `PASS lines:` — never `PASS tests:`, never
`PASS subtests:`. The label names what is counted, and what is counted is lines.

**The conjunction (D-04 as corrected in `01-CONTEXT.md`).** A gate passes only when the
test command's exit status is 0 AND the `--- PASS` floor is met. Neither is sufficient
alone: `go test -run PATTERN` exits 0 when the pattern matches nothing, and a shell
pipeline's `$?` is the LAST command's, so a bare count passes with N passing subtests plus
one `--- FAIL`. The single scoped exception is a deliberate-mutation RED observation, where
a non-zero exit IS the expected evidence and the observation is scored by `--- FAIL` /
`--- PASS` counts rather than by status.

**The five vacuity shapes cycle 3 found in this phase's own gates.** Each is a prohibition
in `must_haves.prohibitions`. They are restated here together because they are one class —
a guard that reads green against a file it never opened:

1. `git status --porcelain <path>` exits 0 with empty stdout on a MISSING or typo'd path
   (the warning goes to stderr). Always prefix `test -d <path> &&`.
2. A zero-count gate positive-controlled against a DIFFERENT file proves nothing about the
   guarded file: `rg` prints nothing for a nonexistent path too. Control on the SAME file.
3. `rg -q 'compared [0-9]+ generated files'` accepts `compared 0 generated files`. Capture
   the number; assert the floor numerically.
4. An unanchored identifier grep (`\bgather[A-Z]`) is satisfiable by a trailing or `/* */`
   comment that `rg -v '^\s*//'` does not strip. Anchor to the declaration form.
5. An unranged `git diff` is empty by construction at verification time under
   atomic-commit-per-task. Assert over `<phase-base>..HEAD`.

**The scope shape cycle 5 found, which none of the five above reaches.** The five shapes are
all about how a gate is WRITTEN. A gate can satisfy every one of them and still be vacuous
because of what it is SCOPED to: if its floor is already cleared by test functions belonging
to an EARLIER plan that happen to share the selection pattern, then the pattern matching none
of this task's own tests costs nothing — `go test` exits 0 on a pattern that matches nothing,
and the inherited tests supply the count. The sixth prohibition in `must_haves.prohibitions`
closes it with two requirements: every gate carries at least one leg scoped to tests THIS task
declares with a floor derived from that leg alone, and every behavior bullet has a named home
in the derivation. Both are checkable by reading the plan, which is where the defect lives.
