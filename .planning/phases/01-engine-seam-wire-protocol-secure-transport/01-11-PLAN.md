<objective>
Make the degraded states legible: a locked store reads as "indexing in progress", an
uninitialized repository reads as "not initialized", and `Status` answers in both cases.

Purpose: SRV-04's degrade path does not exist today. `Engine.Status()` runs only after a
successful `Engine` construction, and `query.OpenAt` fails outright when the store is
locked past `graphstore.Open`'s retry budget — so `Status()` never even runs in the exact
case the requirement describes. This is new plumbing at the RPC layer, not a reuse of an
existing fallback.

The first review of this phase corrected two things about how that plumbing gets proven,
and both corrections are built into this plan rather than left as notes. A test that
accepts "succeeded or degraded" has no failing input and proves nothing, so each test here
names the single outcome it must see — and which outcome that is depends on whether the
holder releases inside `graphstore.Open`'s budget, which is a property the test controls.
And a repository cannot be simultaneously uninitialized and lock-contended: if no
`.codegraph/` exists there is no store directory whose lock could be held. The precedence
rule is still worth encoding, so it is tested where it is actually decidable — at the
classifier, driven with an error that satisfies both conditions — with the filesystem
impossibility recorded rather than papered over.

Output: a typed degrade, a `Status` that answers when things are wrong, a counted proof
that no second retry layer exists, and recorded evidence from real concurrent processes.
</objective>
