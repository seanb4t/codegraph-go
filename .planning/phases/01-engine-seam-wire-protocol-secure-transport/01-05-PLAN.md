<objective>
Give the graph a commit identity and give both protobuf surfaces a codegen drift guard.

Purpose: `schema.Meta` records no commit SHA today. A GitHub permalink that matches what
the UI just showed must point at the *indexed* commit, not at whatever HEAD happens to be
when the link is clicked — so `BRW-09` in Phase 3 is gated on this field existing. It is
sequenced here, with the protobuf work, so it inherits the same additive-only discipline
(D-02a) rather than being invented alongside a UI feature.

And BLD-04 closes a gap that predates this milestone: there is no proto codegen drift
guard in this repository and no regeneration task in `Taskfile.yml`.
`internal/schema/roundtrip_test.go` tests serialization round-tripping, not codegen
currency. So the guard must cover the pre-existing `internal/schema/graph.proto` as well
as the new UI schema — and this plan is the first time `graph.pb.go` gets regenerated in
anger, which is exactly when a latent drift would surface.

Output: `Meta` field 8, a populated commit SHA at every write site, and a counted,
RED-proven drift guard over both surfaces.
</objective>

## Flagged Assumptions (unresolved edge probes)

The spec-less edge probe classified two of this plan's requirements as `unclassified`.
Per the probe's rules they are not auto-resolved into `must_haves`; they are surfaced here
as open assumptions:

- **ENG-04 / unclassified** — assumed: "the indexed commit" means `HEAD` of the working
  tree at index time, resolved once per index run. A repository indexed mid-rebase, in a
  detached-HEAD state, or with uncommitted changes records the SHA of whatever `HEAD`
  pointed at, with no dirty-tree marker. `Engine.WorktreeMismatch` is the existing,
  separate mechanism for the dirty case, and this field deliberately does not duplicate
