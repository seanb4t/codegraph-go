<objective>
Give the graph a commit identity, and give that identity a real path out of
`internal/query` to the wire.

Purpose: `schema.Meta` records no commit SHA today. A GitHub permalink that matches what
the UI just showed must point at the *indexed* commit, not at whatever HEAD happens to be
when the link is clicked — so `BRW-09` in Phase 3 is gated on this field existing. It is
sequenced here, with the protobuf work, so it inherits the same additive-only discipline
(D-02a) rather than being invented alongside a UI feature.

The field alone is not enough, and the first review of this phase caught why. `Engine.Status`
returns a `StatusResult` projection that has no commit field; `Engine.reader` is unexported;
`graphstore.Reader.GetMeta()` is unreachable from `internal/uiserver`; and a second
in-process `graphstore.Open` on the same directory is lock-refused. Adding the field
without adding an accessor would leave plan 01-09's "the Status response carries the commit
SHA" unachievable. So this plan ships both halves: the field, and
`(*Engine).IndexMeta` — an accessor that reads the metadata the Engine already reads,
placed deliberately outside `status.go` so D-06's "the CLI stays untouched" stays true and
visibly so.

Output: `Meta` field 8, one HEAD resolution per operation threaded to all three write
sites, an exported metadata accessor, and a recorded proof that `codegraph status`'s bytes
did not move.
</objective>

## Flagged Assumptions (unresolved edge probes)

The spec-less edge probe classified ENG-04 as `unclassified`. Per the probe's rules it is
not auto-resolved into `must_haves`; it is surfaced here as an open assumption:

- **ENG-04 / unclassified** — assumed: "the indexed commit" means `HEAD` of the working
  tree at the START of the index run, resolved once. A repository indexed mid-rebase, in a
  detached-HEAD state, or with uncommitted changes records the SHA of whatever `HEAD`
  pointed at then, with no dirty-tree marker, and a HEAD that moves during the run is
  deliberately ignored rather than re-read. `Engine.WorktreeMismatch` is the existing,
  separate mechanism for the dirty case, and this field deliberately does not duplicate
  it. If Phase 3's permalink needs a dirty-tree signal, it composes the two rather than
  extending this field.
