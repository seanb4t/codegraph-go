<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| indexed repo content → styled terminal output | file paths / language names / symbol strings (from an arbitrary, possibly untrusted repo) flow into the new pretty renderer bound for a human's real terminal |
| CLI RunE → stdout stream | the isTTY decision must reference the real os.Stdout, while product output goes to cmd.OutOrStdout() (decoupled by design, D-06) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-04 | Tampering | terminal escape-sequence injection via untrusted repo-derived strings (file paths/symbol names containing raw control bytes) rendered by the new pretty path | low | accept | Pre-existing risk class identical to the plain renderers today (RESEARCH Security Domain) — Phase 6 does not worsen it. Design discipline: lipgloss styling wraps only structural CHROME (headers, labels, borders); repo-derived data is passed to Style.Render() which composes SGR codes AROUND the string but does not interpret its bytes as new escape sequences. CONTEXT does not scope control-char stripping; a stripping pass would be new scope requiring discuss-phase confirmation. Accepted as pre-existing, consistent with the plain path. |
| T-06-05 | Tampering | pretty path re-deriving content and diverging from the plain/golden bytes (byte-identity break) | high | mitigate | D-02 reuse-not-rederive (Tasks 1-2 consume StatusResult/FilesResult read-only) + the byte-identity integration test (Task 3) + golden corpus staying green |
| T-06-06 | Information Disclosure | ANSI leaking into piped/agent output by relying on lipgloss auto-degrade | high | mitigate | D-04 explicit non-TTY plain-branch bypass (Task 3); zero-ANSI assertion in the byte-identity integration test |
</threat_model>
