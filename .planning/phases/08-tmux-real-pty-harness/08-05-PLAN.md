<objective>
Close G-08-1: `TestDaemonEmptyRegistryLeaksNoModeQueryBytes` (TTY-03) fails 3/3 on a cold macOS
machine because `pollUntilStable`'s two-sample byte-equality check converges on the pre-output frame
whenever the spawned binary's first exec takes longer than `stabilityPollInterval` (1s) — and the cold
first exec of a freshly built 80MB binary measures 1.1-1.6s in-pane. `capture.go:16-27` claims the
interval "exceeds the measured worst case" so the two samples cannot both land pre-output; that claim
was made from a warm-binary measurement and is false on the cold path.

**Chosen mechanism — fix direction 2 from the debug session, generalized.** The root cause is
structural, not numeric: a pre-output frame IS a stable frame, and no two-sample equality check can
tell "settled after output" from "settled before output". The fix gives `pollUntilStable` a required
readiness predicate: convergence is `ready(capture) && capture == predecessor`. TTY-03 anchors on
`no running daemons`; every other call site anchors on the content or tmux state its own next assertion
already requires (`Running daemons`, `[ ]`, `[x]`, alt-screen off). Two of the three directions are
deliberately NOT taken: raising the interval moves the cliff rather than removing it, and warming the
binary in `TestMain` would hide the defect while also removing the only genuine cold first exec the suite
has — every future run would be the debug session's invalidated experiment.

**This amends D-14's contract and says so.** D-14's bounded poll, byte-identical consecutive captures,
non-convergence-is-a-failure, and single-wait-primitive properties all stand. What changes is the
definition of "converged": stable AND ready, where the caller states what ready means. 08-01's
`must_haves` truth on the poll is amended in the same plan so no artifact carries a false guarantee.

Purpose: the harness exists so that a real-terminal defect class cannot ship unobserved. A wait
primitive that can converge on the wrong frame turns the phase's tracer assertion into a machine-
dependent flake, and a header comment asserting a false guarantee is exactly the trusted-but-untested
gate this milestone was created to eliminate.

Output: an anchored `pollUntilStable` with a truthful header comment, a deterministic self-test that was
watched RED against the pre-fix primitive, `TMUX_EXPECTED_TESTS` at 6, cold-arm evidence in the SUMMARY,
and 08-01's poll truth reworded to what is now actually guaranteed.

**Commit discipline.** Unlike 08-01 (where the deliverable WAS the test), this plan has a real
behavioral RED followed by a real implementation change, so the textbook split applies: Task 1 lands the
failing self-test together with the `TMUX_EXPECTED_TESTS` bump as one `test(08-05)` commit (the same-
commit rule for the constant is absolute); Task 2 lands the primitive change, the ten call-site anchors,
and the comment rewrite as one `fix(08-05)` commit; Task 3 lands the 08-01 wording amendment as a
`docs(08-05)` commit. The tmux-e2e job is red at exactly one intermediate commit on this branch, by
design, and green at the branch tip.
