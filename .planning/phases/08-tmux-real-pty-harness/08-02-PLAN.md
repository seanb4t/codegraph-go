`seedRunningDaemon(t, home, repo)`: first run `<binPath> init <repo>` synchronously with
`HOME=<home>` and `USERPROFILE=<home>` in the env and `t.Fatalf` on failure — `daemon start` refuses an
uninitialized repo with a message telling you to init first, verified in 08-RESEARCH.md Pattern 2.
Then build `exec.Command(binPath, "daemon", "start", "--path", repo, "--quiet")` with the same env,
call `Start()`, and — before returning and before anything that could `t.Fatal` — register a
`t.Cleanup` that sends `syscall.SIGTERM` to `cmd.Process` and then calls `cmd.Wait()`. The signal
handler in the daemon deregisters through a deferred call, so SIGTERM plus Wait is a graceful
teardown; a bare `Kill` would leave the record behind. Return the `*exec.Cmd`. The launched process's
own pid is the registered pid — there is no fork or double-fork — so no pid discovery is needed.

`waitForRegistryRecord(t, home)`: poll the daemon registry directory under the throwaway home on the
same interval `pollUntilStable` uses until at least one record file is present, with the same bounded
deadline. On deadline, `t.Fatalf` naming the directory it watched and what it found there. This is a
bounded poll with a convergence condition, not a fixed pause — the same discipline D-14 imposes on
frame capture applies to process readiness.

Implement it in pure Go with `filepath.WalkDir` plus `crypto/sha256`, not by shelling out. The research
verified the shell form, but `sha256sum` does not exist on darwin — this repo ships a darwin binary and
contributors run this target locally, so a shell-out here would make the test pass on Linux and fail on

agent targets are registered. Return the hex digest. Add a doc comment recording that the picker's
