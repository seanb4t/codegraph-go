<objective>
Make removal as safe as writing. `codegraph uninstall` takes back exactly the
three artifacts install wrote and leaves everything else — unrelated hook blocks,
unrelated events, unrelated keys, user-authored files in the same directory —
byte-untouched. Then prove the read-error invariant across the full
{install, uninstall} × {read-error, malformed} matrix, and close the split-posture
hazard Plan 01 created by giving the two steps that read `.claude/settings.json`
one shared reader.

That last part is not scope creep. Plan 01 put a fail-loud hooks step into the
same file as the pre-existing fail-silent AutoAllow step. Left as is, a single
`codegraph install --auto-allow` against a malformed settings.json would have the
hooks step correctly refuse to touch the file while the permission step
overwrites it with only codegraph's own content — destroying the very file the
other step protected. That is the data-loss shape v1.0 Phase 5 converged this
invariant to prevent, newly reachable because of this phase.

Purpose: satisfy AGENT-02 and roadmap success criterion 4 by measurement.
Output: a byte-invariant install→uninstall round-trip and a four-cell error matrix.
</objective>

to `internal/agents/shared.go` as the exact mirror of `writeHookEntry`. Read via

  <action>
Create `internal/agents/claude_readerror_test.go` with the table-driven matrix
described in `<behavior>`.

Build the malformed fixture as a truncated JSON object — content that is
unambiguously not a decodable JSON object, so `encoding/json` fails rather than
succeeding into an unexpected shape. Capture the fixture's exact bytes before the
operation and compare raw bytes afterward; use raw byte comparison here rather
than `jsonDeepEqual`, because the whole point is that the file was not parsed and
therefore not re-serialized.

Build the read-error fixture with `os.Chmod(path, 0o000)` and restore the mode in
a `t.Cleanup` so the temp directory can be torn down. Guard the read-error cells
with a skip when `os.Geteuid() == 0`, because a root-owned test process bypasses
the permission bit and the cell would pass vacuously; state that reason in the
skip message so a future reader does not mistake the skip for flakiness.

Assert on both halves of the invariant in every cell, never just one: the error
must surface *and* the bytes must be unchanged. A surfaced error with a destroyed
file, or an intact file with a swallowed error, are both failures — the first is
the v1.0 Phase 5 data-loss shape, the second is the CR-01 swallowed-error shape.
Assert the error's message contains the settings path, so an unrelated failure
elsewhere in `Install` cannot satisfy the assertion.

For the non-vacuity guard, run the same four operations against a well-formed
fixture and assert `len(result.Errors) == 0` and that the file's bytes did change
for install. This is the same guard-the-guard discipline
`TestHookRegistrationMatchesFragmentAndScript_ComparisonDiscriminates` already
applies in this package — a matrix that would pass against any implementation is
not a gate.
