<objective>
Close AGENT-03's second half. Today `codegraph upgrade` swaps the binary and
stops, so a user who upgrades keeps running the previous binary's skill package
until they happen to re-run `codegraph install`. D-06 makes the roadmap's literal
wording — "refreshed BY `upgrade`" — true: after a successful swap, upgrade
re-invokes `Install()` for every location that already carried a manifest, with
the new binary's embedded content.

D-07 governs what happens when that second step fails. The binary swap is atomic,
independently verified, and independently load-bearing; a config-file write
hiccup afterward must not make `codegraph upgrade` report that the upgrade did
not work, because the binary genuinely did update. The refresh failure surfaces
as its own warning naming `codegraph install`, and upgrade's own exit code is
unchanged.

Purpose: make the installed package move with the binary, without conflating two
independent outcomes into one exit code.
Output: a post-swap refresh step with an injectable test seam, and the D-07
reporting split.
</objective>

  <action>
Add the refresh step to `internal/cli/upgrade.go`, keeping it at the CLI layer.
`internal/upgrade` today has zero dependency on `internal/agents`, and its own
tests drive the security-critical resolve→verify→swap sequence entirely through
injected fakes with no agents concept; adding an agents dependency to that package
for a config-refresh concern would blur a clean boundary for no correctness
benefit, and would make D-07's "separate warning, not a failed upgrade" harder to
express than two sequential steps in one `RunE`.

Add `refreshInstalledSkills(execPath string, out io.Writer) error`. It calls
`agents.ConfiguredSkillLocations(agents.Claude)` to get the set of locations that
already carry a manifest. For each, resolve the Claude target through the
existing registry seam (`agents.ResolveTargetFlag` with the `claude` id and that
location) and call `Install(loc, agents.InstallOptions{ExecPath: execPath})`,
joining every returned `WriteResult.Errors` into the returned error. When the
location set is empty, do nothing and return nil — an upgrade on a machine that
never ran `install` must stay silent, not print a confusing no-op line.

Pass `AutoAllow: false`. `--auto-allow` is a per-invocation choice the user made
at install time and is not recorded in the manifest; re-asserting it on every
upgrade would silently re-add a permission the user may have deliberately
removed. Removing it is equally wrong — `Install` with `AutoAllow: false` simply
skips the permission step rather than deleting anything, which is the correct
neutral behavior. Note this reasoning in the function's doc comment.

The refresh installs to exactly the locations that already had a manifest, never
to both by default and never to a location that had none. The manifest's presence
is the record of what the user consented to; upgrade is not an opportunity to
also configure something they never asked for (the prohibition recorded in this
plan's `must_haves.prohibitions`).

Add a package-level `var refreshInstalledSkillsFunc = refreshInstalledSkills`
following the exact injectable-seam idiom `upgradeRunFunc` and
`interactiveAllowed`/`runAgentPicker` already establish in this package, so
`upgrade_test.go` can assert the call without touching the real filesystem.

In `RunE`, capture `upgradeRunFunc`'s returned error into a variable rather than
returning it directly. If it is non-nil, return it immediately — a failed swap
means the binary did not change and there is nothing to refresh. If it is nil and
`check` is false, call `refreshInstalledSkillsFunc(target, cmd.OutOrStdout())`.
Skip the refresh entirely under `--check`: that invocation downloaded nothing,
swapped nothing, and must mutate nothing.

Report per-location outcomes through `cmd.OutOrStdout()` in the same
`<action>: <path>` shape `printAgentResults` already prints, so a user reading
upgrade's output recognizes it as the same reporting vocabulary `install` uses.
  </action>

  <action>
Implement D-07's reporting split in `RunE`. When `refreshInstalledSkillsFunc`
returns an error, write a warning to `cmd.OutOrStdout()` that states the binary
upgrade succeeded, states that refreshing the agent skill package did not, quotes
the underlying error, and names `codegraph install` as the command to re-run.
Then return nil — the value `RunE` would have returned had the refresh step not
existed.

The reason this is not a swallowed error is that the two outcomes are genuinely
independent. The binary swap is atomic and independently verified; reporting the
whole invocation as failed because a config file could not be rewritten would
tell the user their upgrade did not work when it demonstrably did, and would
likely prompt them to re-run the upgrade rather than the one command that would
actually fix the situation. The warning names that command explicitly for exactly
that reason.

Suppress the warning under `--check` for the same reason the refresh itself is
suppressed there: nothing was attempted, so there is nothing to warn about.

Keep the swap-failure path untouched — when `upgradeRunFunc` returns non-nil,
`RunE` returns that error directly with no refresh attempted and no wrapping, so
`errors.Is` against the original still holds for any caller or test that depends
on it.

Add the three tests in `<behavior>` to `internal/cli/upgrade_test.go`.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the newly swapped binary → the user's agent configuration | a freshly downloaded binary's embedded content is written into the user's `~/.claude/` without a second confirmation |
| manifest presence → refresh consent | the on-disk manifest is the only record of what the user previously agreed to configure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-02 | Tampering | post-swap refresh scope | medium | mitigate | Refresh runs only for locations that already carry a readable manifest, discovered by two fixed `os.Stat`-class probes rather than a filesystem walk. Asserted by a test proving a global-only fixture produces no local tree. |
| T-07-09 | Elevation of Privilege | refresh runs with the freshly downloaded binary's embedded content | medium | mitigate | The refresh runs strictly after `internal/upgrade`'s existing cosign-keyless signature and provenance verification has passed and the atomic swap has succeeded — the embedded content it writes is by construction the content of a binary that already cleared the release verification gate. No new trust is extended. |
| T-07-10 | Repudiation | conflating swap success with refresh failure | medium | mitigate | D-07 splits the two outcomes: the swap's own reporting is unchanged and the refresh failure is a distinct warning naming the remedial command. Reporting a successful swap as failed would misdirect the user into re-running the wrong command. Asserted by a test requiring a nil return alongside the warning text. |
| T-07-04 | Spoofing | `ExecPath` written into the refreshed MCP entry | low | mitigate | Uses `os.Executable()`'s resolved path — the same source `codegraph install` already uses — never a `$PATH` lookup. |
| T-07-SC | Tampering | npm/pip/cargo installs | low | accept | No package-manager install in this plan; Go standard library and already-vendored internal packages only. |
