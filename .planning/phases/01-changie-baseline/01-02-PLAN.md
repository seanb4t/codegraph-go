## Flagged Assumptions

**A-01. Edge probe CHG-04/unclassified.** Status: unresolved and flagged, not auto-resolved. These are fragment-file assumptions that downstream phases must not silently inherit. Owners: Phase 2 (CAP-03) and Phase 4 (GATE-01) planning.

1. changie v1.26.0 silently overwrites an existing fragment path instead of refusing to write. This was measured at planning time: under the default seconds-resolution fragmentFileFormat, a second same-kind `new` in the same second replaced the first. This phase sets a sub-second format, and leg 9 guards it. Uniqueness still rests on timestamp resolution: two writers on different machines producing the same Kind with identical sub-second timestamps would meet as a git add/add conflict at merge. That is loud, but it is not prevented.
2. A written fragment stores `custom.PR` as a quoted string (`PR: "1"`), although the config declares type int (01-RESEARCH.md Pitfall 4). Phase 2's capability and Phase 4's gate must not parse it as a YAML integer.

TestChangieConfigShape's exact top-level key set keeps it that way. If a later phase adds envPrefix, the missing-PR refusal can be satisfied from the environment.
