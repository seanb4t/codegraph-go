<objective>
Build `internal/daemon`: the long-lived local process that owns the watcher plus the single
`GraphStore.Writer`, so multiple agent sessions share one indexer (SYNC-04), guarded by a
`.codegraph/` lockfile (pid + start timestamp) enforcing the single-writer invariant (INDX-05,
D-05); and `codegraph unlock`'s engine — remove a lock ONLY when it is genuinely stale after a
crash (SYNC-05), never stomping a live daemon.

Lifecycle is `context` cancellation + `sync.WaitGroup` join on shutdown (D-07): every goroutine
(watcher loop, debounce timer, sync worker) is owned by a cancelable context and joined before
`Run`/`Stop` returns — the discipline Plan 04-09's soak test proves leak-free. The in-process
fallback (a watcher inside `serve`) reuses the SAME lockfile so a daemon and an in-process watcher
can never both hold the writer.

Purpose: one shared, single-writer index server with a crash-safe lock and clean shutdown.
Output: `lock.go` (format + stale detection + acquire/release), `daemon.go` (lifecycle + `Unlock`),
and their tests. The thin CLI commands and the in-process serve fallback are wired in Plan 04-08.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| lockfile ↔ concurrent processes | A stale lock a naive unlock blindly removes could let a second writer start alongside a live daemon (two-writer corruption) |
| daemon goroutines ↔ shutdown | Un-joined goroutines leak / late-fire after Run returns |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-07-01 | Tampering / DoS | unlock stale-lock detection | high | mitigate | Unlock removes ONLY when isStale (dead pid via Signal(0)); a live lock returns ErrLockLive and is never removed — prevents a second concurrent writer corrupting the store (single-writer INDX-05) |
| T-04-07-02 | Tampering | PID reuse (containers) | medium | mitigate | Corroborate pid liveness with the lockfile's StartedAt timestamp to reduce the residual PID-reuse false-negative (RESEARCH A3); document the residual risk where the pid-only check is used |
| T-04-07-03 | Denial of Service | goroutine leak / late-firing timer | medium | mitigate | context cancellation + sync.WaitGroup join before Run returns; debounce timer.Stop() on shutdown (D-07) — soak-verified in Plan 04-09 |
| T-04-07-04 | Elevation of Privilege | lockfile path confinement | low | accept | Lockfile is created inside the resolved .codegraph/ dir only; no attacker-controlled path component beyond the repo the user already trusts |
| T-04-07-SC | Tampering | dependencies | low | accept | Lockfile uses only stdlib os/syscall (RESEARCH: no new dependency); daemon reuses fsnotify (already audited in 04-05); no [ASSUMED]/[SUS] packages |
</threat_model>
