<objective>
Make staleness visible (SYNC-02) and make MCP reconnect reconcile offline changes (SYNC-03) — both
reusing existing single-formatter / single-Sync paths (Phase-3 D-08b, D-06: "no second
reconciliation code path").

SYNC-02: `StatusResult` already carries inert placeholder fields (`PendingChanges`,
`WorktreeMismatch`) that Phase 3 documented as "Phase-4 sync concept; present-but-inert" — this
plan makes them live. `explore`'s markdown (`RenderExplore`) gets a staleness banner prepended
while a sync is pending; `status` reports a live `stale`/`pendingSync` signal. The pending state is
a lightweight sidecar marker (`.codegraph/.sync-pending`) set by the watcher/daemon on first event
and removed on commit; when no daemon runs, the fallback signal compares the newest on-disk file
mtime against `Meta.last_sync_unix_ms`.

SYNC-03: `codegraph serve --mcp` startup runs one `indexer.Sync` reconcile before `server.ServeStdio`
blocks, so offline changes made while the watcher was down are caught and the first `explore` reads
a current graph — a cheap no-op when nothing changed (the stat pre-filter makes this true).

Purpose: agents see when the index is behind, and a reconnect never serves a stale graph.
Output: a live staleness banner threaded through the one explore/status formatter, plus a reconcile
call in serve.go.
</objective>
