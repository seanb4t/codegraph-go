<objective>
Collapse today's three-job, two-runner-class release pipeline — `build` (4-leg matrix) →
`assemble` (linux amd64) → `provenance` — into one job on one runner class that invokes
`goreleaser release` exactly once, and delete every hand-rolled shell step whose work GoReleaser's
own pipes now do.

Purpose: REL-06 and REL-07. The hand-rolled `sha256sum` step and `.goreleaser.yaml`'s `checksum:`
block must never both be live — that is the second-writer bug REL-07 exists to make structurally
impossible. Their deletion and activation are one atomic contract, not two independent changes.
Collapsing the jobs also removes the natural boundary that made "which job holds the OIDC token"
easy to eyeball, so this plan replaces the eyeball with a machine check (D-11).

**Why there is no commit-ordering criterion, and why splitting this from plan 01-02 is safe.**
`main` never observes a half-migrated state, so "which commit lands first" is not a property worth
asserting. Three facts compose to guarantee that: (1) `release.yml` triggers ONLY on
`push: tags: v[0-9]*` — nothing fires on a branch push or on a merge to `main`; (2) tags are cut by
release-please from `main` and no human runs `git tag` (D-05/D-06R), so a tag exists only after the
phase's PR has merged; (3) this repository is squash-only with
`squash_merge_commit_title=PR_TITLE`, so the entire phase branch — plans 01-02 and 01-03 alike —
collapses into ONE commit on `main`. The interleaved state where the shell writer and the
declarative pipe are both live, or neither is, therefore exists only on the feature branch, where
no tag is ever pushed and the release workflow never runs.

What DOES need asserting is the joint END STATE, not the order: shell writer gone AND declarative
pipe live. Because that state straddles two plans' `files_modified` sets, neither plan may claim it
as a truth it can independently verify. Task 2 below carries it as a single two-sided acceptance
criterion evaluated against the working tree at wave-2 close, and plan 01-05 closes it
authoritatively against the published release. A future reviewer re-raising "these two plans must
be one commit" should read this paragraph first.

The `provenance:` job is deliberately left in place here and replaced in plan 01-04, which owns
the attestor swap and its one-way decision gate.

Output: one `release` job, a `release:goreleaser` Taskfile target, and three shape tests — one
rewritten, two new — each demonstrated RED.
</objective>
