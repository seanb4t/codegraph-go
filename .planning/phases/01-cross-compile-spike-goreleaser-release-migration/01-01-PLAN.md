Prove or disprove, on measured evidence, that the OSS single-runner release architecture is
reachable: that `zig cc` invoked from a macOS host cross-compiles this repository's CGo
tree-sitter dependency to linux/amd64 AND linux/arm64, and that the resulting binaries
actually RUN on real Linux hardware of their own architecture while indexing a real source
tree (REL-05).

This plan is the phase's tracer slice. It wires ONE path through every layer the phase will
later modify — `Taskfile.yml` target → `.goreleaser.yaml` build config → macOS runner →
cross-compiled artifacts → real-Linux execution → Go shape test — end to end, in production
quality, before any expansion work is trusted. Every later plan in this phase (the
`goreleaser release` migration, the archives/checksum/sign/SBOM activation, the attestor
swap, the live release) is contingent on the answer this slice produces.

Purpose: the milestone's single unproven claim. If it fails, the architecture changes to the
costed GoReleaser Pro fallback with three named gate repairs entered as scope — and that
branch must be reached by exhausting an enumerated list written down in advance (D-04), not
by open-ended debugging.

Output: a permanent, dispatchable canary workflow; two new Taskfile targets; a zig-cross
override on the linux/amd64 build id; one new Go shape test file; and a recorded PASS/FAIL
decision backed by a re-inspectable CI run URL.
