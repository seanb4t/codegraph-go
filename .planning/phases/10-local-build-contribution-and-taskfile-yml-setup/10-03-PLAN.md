<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Namespace runner -> release artifact | Released, signed, SLSA-attested binaries are produced on third-party runner infrastructure |
| Cache volume -> release build | Restored Go module/build cache contributes to the bytes users download |
| Reusable SLSA workflow -> provenance | The provenance attestation is produced by an external reusable workflow this repo cannot configure |
| Cross-toolchain (zig) -> darwin binaries | If darwin were cross-linked, its DNS resolution path would change relative to a native build |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-03-01 | Tampering | Release build executed on third-party (Namespace) runner infrastructure | high | mitigate | The runner class changes but every integrity control stays: `.goreleaser.yaml`'s `-trimpath`/`-buildid=`/`SOURCE_DATE_EPOCH` reproducibility flags, `ci.yml`'s independent double-build hash-diff gate, per-binary cosign signing, per-binary Syft SBOM, and SLSA provenance produced by a job that does NOT run on the moved runners. A tampered build on any runner is detectable by re-running the deterministic build elsewhere. |
| T-10-03-02 | Tampering | Silent substitution of a cross-linked darwin build for a native one | high | mitigate | `TestDarwinLegsBuildNatively` asserts both darwin matrix entries carry `needs_zig: false` and a macOS-class runner label, demonstrated red against a mutated matrix. Without this, a runner-label edit would produce still-signed, still-attested binaries with different DNS-resolution behavior and no failing gate. |
| T-10-03-03 | Spoofing | Restored cache on a shared Cache Volume feeding a release build | medium | mitigate | `cache: go` restores only checksum-verified module/build cache content; no prebuilt release artifact is restored from cache. The double-build reproducibility gate in `ci.yml` independently detects a build whose output depends on cache state. |
| T-10-03-04 | Repudiation | Provenance job moved or its generator reference weakened | high | mitigate | `TestProvenanceJobUsesTaggedSLSAGenerator` asserts the tag reference and the absence of a caller `runs-on`. `slsa-verifier` requires the tag form; a SHA reference would break verification for every downstream consumer. |
| T-10-03-05 | Tampering | Incidental version-pin drift during the runner edit | medium | mitigate | Acceptance criteria assert `GORELEASER_VERSION` still reads `v2.17.0` and that the set of `run:` bodies is byte-identical before and after, so a pin bump cannot ride along unnoticed. |
| T-10-03-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no npm, pip, or cargo package and adds no new Go module dependency. |
</threat_model>
