<recorded_divergence>
## D-08 file location: dedicated workflow instead of a job inside `ci.yml`

**D-08 says:** "Add a lightweight PR-title conventional-commit check to `ci.yml`."

**What ships:** the same hand-written check, in a dedicated `.github/workflows/pr-title.yml` with its own narrowly-scoped `pull_request: types: [opened, edited, synchronize, reopened]` trigger.

**Why (RESEARCH Pitfall 1, which explicitly hands this tradeoff to the planner):** `ci.yml`'s single shared `pull_request:` trigger uses GitHub's default event types, which exclude `edited`. A contributor who fixes only the PR title gets no re-run, so the gate is stale exactly when it matters. Making the check correct inside `ci.yml` requires widening that shared trigger, which re-runs the `test`, `govulncheck`, `reproducibility` (double CGo build plus a zig cross-build) and `perf-regression` (120k-file synthetic corpus) jobs on every title *or description* edit. The alternative — widening the trigger and adding `if:` guards to skip the heavy jobs on `edited` — introduces GitHub's skipped-required-check semantics as a new footgun on a repo that will plausibly gain branch protection.

**What is preserved:** D-08's substance in full — a blocking PR-title Conventional-Commits gate, hand-written `grep -E` rather than a new pinned action, `env:` indirection for the title. The delivered gate is strictly stronger than a literal `ci.yml` placement without trigger widening, because it actually re-fires on a title-only edit.

**What diverges:** the file the job lives in. Recorded here and in `docs/RELEASE-PROCEDURES.md` §10 (plan 09-04) rather than resolved silently — this repo's documented-divergence-over-silent-drift convention.
</recorded_divergence>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| contributor-supplied PR title -> lint step shell | the title is fully attacker-controlled text from any fork PR author |
| PR title -> merged commit message -> release-please's parser -> the published changelog | garbage in the title becomes garbage or silence in the release notes users read |
| workflow YAML -> GitHub Actions runner | schema errors and untyped expressions become runtime failures or injection surfaces |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-03-01 | Tampering | script injection via the PR title into the lint step (ASVS V5) | high | mitigate | The title reaches the shell only through an `env:` binding and is never placed in command text; an adversarial table row with a command-substitution payload asserts no side effect occurs; `actionlint`'s injection checks run over the file |
| T-09-03-02 | Repudiation | a lint that accepts everything (guard present, never fires) | high | mitigate | The test executes the shipped step across at least four reject rows; a manual break-observe-restore run against a non-conformant title is an explicit acceptance criterion |
| T-09-03-03 | Elevation of Privilege | over-granted workflow permissions on a fork-PR-triggered workflow | high | mitigate | Top-level `permissions:` grants read on contents only; the job needs no checkout, no token, and no write scope. The `pull_request` (not `pull_request_target`) trigger keeps fork PRs on the read-only, base-repo-secret-free path |
| T-09-03-04 | Denial of Service | trigger widening re-running the heavy CI suite on every title or description edit | medium | mitigate | The lint lives in its own workflow file with its own narrow trigger; `ci.yml`'s `pull_request:` block is asserted unchanged by a diff-scope acceptance criterion |
| T-09-03-05 | Tampering | supply chain — a new linting dependency | medium | mitigate | actionlint is installed via `go install` at an exact pinned tag re-resolved live, not floating and not a new pinned Action; the PR-title check adds no third-party action at all (asserted by a zero-`uses:` criterion) |
</threat_model>
