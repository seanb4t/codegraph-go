<objective>
Ship BLD-03: a drift guard that proves the committed `web/build/` matches the SPA source it was
built from, reports how many source files it hashed, and has been watched fail before it is
trusted green — plus the CI plumbing (BLD-01's frozen-lockfile install at the pinned pnpm
version) that the guard and every later JS gate run on top of.

Purpose: `web/build/` is committed, which means a developer whose build diverges from CI's
silently ships a different app than the one the source describes. This is ROADMAP criterion 3.
The shape matters as much as the existence: the obvious imitation of `task proto:drift` —
regenerate and byte-compare — is provably wrong here, and this plan implements the shape that
works instead.

Output: `task web:deps`, `task web:build`, `task web:drift`, a committed source digest marker,
and three new steps in the existing `test` CI job.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer machine build → committed `web/build/` | Whatever a developer commits here is what every user's browser runs; a divergent local toolchain is the threat |
| CI runner's Node/pnpm resolution → installed dependency tree | A version-resolution difference produces a different `node_modules` and therefore a different build than the committed one |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06-01 | Tampering | A stale committed `web/build/` shipping code that no longer matches its source | high | mitigate | `task web:drift` compares a source-tree digest against a committed marker, reports the hashed count first, and has been watched RED against a real staleness. |
