<objective>
Stand up the SPA toolchain and prove the whole build-to-browser path end to end with the
thinnest possible slice: a pnpm-managed SvelteKit app at `web/` (D-01, D-02), built by `adapter-static`
into a committed `web/build/`, embedded into the Go binary through `web/embed.go`, and served
by a new `internal/uiserver/spa.go` handler mounted at `"/"` on Phase 1's existing mux inside
`originHostGuard`.

Purpose: this is the tracer. Every later plan in Phase 2 expands outward from a path that is
already proven to work — the codegen client (02-03), the full fallback/cache semantics (02-02),
the design system and the live `GetStatus` render (02-05), the drift guard (02-06) and the
supply-chain gates (02-07) all assume the seam this plan establishes. If the architecture is
wrong (embed placement, output directory, gitignore, mux precedence), it is wrong after one
commit rather than after six.

Output: a running `codegraph ui` that serves the real app shell from bytes inside the binary,
with no JS toolchain required at `go build` time.
</objective>
