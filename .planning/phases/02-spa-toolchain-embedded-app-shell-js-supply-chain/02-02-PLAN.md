    Implement the complete rule inside `internal/uiserver/spa.go`'s `ServeHTTP`, using
    `fs.ReadFile` and `fs.Stat` against the `fs.Sub`-derived sub-filesystem. Do NOT delegate to
    `http.FileServer`, `http.FileServerFS` or `http.ServeFileFS` — their automatic redirect for
    paths ending in `/index.html`, plus directory-index and trailing-slash behavior, is more
    machinery than this rule needs and fights D-04's literal-fallback requirement (RESEARCH
    Pitfalls 3 and 6). `http.ServeContent` is acceptable for byte-serving a resolved file once
    the branch has already been decided and the headers already set.

    Order of operations in `ServeHTTP`:
    1. Reject any method other than `GET` and `HEAD` with 405 and an `Allow` header.
    2. Set `X-Content-Type-Options` to `nosniff` unconditionally, before any branch, so no branch

    3. Normalize the request path: strip the single leading slash, then `path.Clean`. If the
       result fails `fs.ValidPath`, treat it as a non-file and take the fallback branch — an
       `embed.FS` cannot be escaped by `..`, so this is defense in depth, not the only barrier.
    4. Empty path means the fallback file.
    5. If the normalized path has `spaAssetPrefix` as a prefix: `fs.Stat` it; on success serve it
       with `spaCacheControlImmutable`; on any error write 404 and RETURN — never fall through to
       the fallback. Give the 404 a short plain-text body naming the missing asset path so the
       failure is self-explanatory in devtools.
    6. Otherwise `fs.Stat` the path; if it resolves to a regular file, serve it with
       `spaCacheControlDefault`.
    7. Otherwise serve `spaFallbackFile` with status 200 and `spaCacheControlNoStore`.

    Set `spaAssetPrefix` to the literal `_app/immutable/` — the explicit prefix D-10 names, not a

    which are not content-hashed, so revalidation is the only value that keeps the post-upgrade
    stale-shell failure impossible). Resolve `Content-Type` with `mime.TypeByExtension` on the
    resolved path's extension, falling back to `application/octet-stream`; set
    `text/html; charset=utf-8` explicitly on the fallback file.

    `internal/uiserver/degrade.go` uses. Extend `spa.go`'s existing file doc comment to state
    that the immutable-prefix branch returns 404 by design and why serving HTML there would be
    worse than the 404.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → SPA handler | Arbitrary request paths, including traversal attempts and paths crafted to look like assets |
| browser cache → shipped binary | A stale cached shell is a correctness failure that presents as a broken UI, not as an error |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02-01 | Tampering | MIME-sniffing on served static assets | medium | mitigate | `X-Content-Type-Options: nosniff` set unconditionally before any branch in `ServeHTTP`, asserted table-driven across all four response shapes including the 404. |
| T-02-02-02 | Information disclosure | Path traversal into the host filesystem | low | mitigate | Serving is confined to an `fs.Sub` over an `embed.FS`, which has no host-filesystem parent; `path.Clean` plus `fs.ValidPath` rejects malformed paths as defense in depth. |
| T-02-02-03 | Spoofing | New static routes reachable via DNS rebinding | high | mitigate | The SPA handler is registered on the mux that `originHostGuard` wraps; `TestSPAInheritsOriginHostGuard` is the regression test for a future refactor that moves it outside. |
