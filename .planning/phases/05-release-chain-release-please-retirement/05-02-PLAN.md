<objective>
Build the tag half of the chain, RED first. When a release PR merges, a push to `main` that changes `CHANGELOG.md` mints the GitHub App token, and `release:tag` pushes tag `changie latest`, or skips with success when that tag already exists. That tag push is what starts the unchanged `release.yml` (REL-11, D-06, D-07). Then prove GRD-16: release:tag is the only tag-creating command anywhere a workflow can reach, and its credential is the App token.

Decisions recorded for the maintainer (two-way doors, not gated):
- **Trigger (D-06).** `on: push: branches: [main], paths: [CHANGELOG.md]`, changie's documented release trigger. The milestone merge also changes CHANGELOG.md and brings 15 already-tagged seeds; release:tag skips the existing `changie latest` tag, so that merge is a no-op (C3). Do not add a "tag must point at the commit that added the file" assertion (D-06).
- **Lightweight tag.** `git tag "${tag}"` without `-a` matches every historical tag (`git cat-file -t v0.14.1` is `commit`) and needs no committer identity in CI. post-release-verify resolves the peeled commit either way.
- **C8, new and named:** `release:tag` declares a precondition that GITHUB_ACTIONS is `true`. Forcing constraint: D-06R's standing "no human `git tag`" rule (REQUIREMENTS standing rules). Without it, `task release:tag` on a laptop would push a tag to origin with the maintainer's own credentials. It is one precondition line.
- **No version-shape validation and no notes-file check in release:tag.** `changie latest` derives the version from `.changes/v*.md` filenames, so the file exists by construction, and `set -euo pipefail` fails on any changie error. These checks are not forced by a locked constraint, so per D-01 they are not added (RESEARCH's sketch had them).
- **GRD-16 scan scope.** Every workflow run body, every local action run step, and every executed Taskfile command, not only the targets workflows reach. A Taskfile target is itself a human-runnable entry point, so a tag-creating command in any target is a D-06R hazard. The scan does not need reachability resolution, and it is strictly stronger than "follow `task` from the workflows". Stated boundary: a script invoked by path (e.g. `python3 scripts/x.py`) is not opened, which mirrors resolveReleasePathClosure's recorded boundary 1.
- **GRD-16 test placement.** The new assertion lives in changie_release_shape_test.go, beside the tag workflow's shape test. tag_authority_test.go stays untouched here (GRD-16: TestGsdTagCreationIsDisabled "passes unchanged"); 05-05 rewords only its prose, under D-09, which lists the D-06R prose in tag_authority_test.go among the census rewordings.
