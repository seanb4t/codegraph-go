Decisions recorded for the maintainer (two-way doors, not gated):
- **Tests live in scripts/test_fragment_policy.py.** It already imports pr_template_policy for the marker-mirror test, and check:fragment-policy already gates it with an executed-count guard. A new test file would need a new target and CI step, which adds ceremony without adding a binding (D-01).
- **Grammar decision (RESEARCH Pitfall 7).** A reason that starts with `-` after strip does not exempt, in either policy. That was the old pattern's evident intent (`[^->]` as its first character class); the old leading-space path that accepted `- ` and `--x` was accidental. This matches 04-REVIEW.md's proposed fix, and a test states it.
- **require-issue-link.yml and WR-01.** The orchestrator note lists require-issue-link.yml under WR-01. Its marker check is one `grep -qiE` with no nested quantifier, and 04-REVIEW.md names WR-01's subjects as fragment_policy.py:49 and pr_template_policy.py:83. So require-issue-link.yml changes here only for D-05, its allowlist arm. Its grep is not a Python backtracking regex, and claiming anything about grep's matcher would be third-party behavior (rule eyva2svrcz). Recorded as a deliberate reading; the maintainer can override.
- **The `.changes/` prefix also exempts a fragment-only PR** from the template and issue-link checks. That is housekeeping by any reading, and consistent with D-05. fragment-required is unaffected (no cmd/** or internal/**).
- **Residual.** A body of many unterminated openers is still scanned once per opener (O(openers × length)). At GitHub's ~65k-character body limit that is about a second, down from hours. Accepted (T-05-18).
