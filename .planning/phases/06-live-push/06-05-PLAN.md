    republished — authoritatively write each surviving node's captured position back.

    Enable ELK's interactive strategies by extending the existing `elk` options object (a plain
    pass-through merged into ELK's own layout options) with the interactive layering,
    cycle-breaking and semi-interactive crossing-minimisation settings, so NEW nodes are placed
    knowing where the survivors are. cytoscape-elk already sends every node's current position
    to ELK, so ELK does have that knowledge. But the interactive strategies only approximate;
    the exactness comes from the write-back. Keep `LAYOUT_OPTIONS` a single shared
    configuration — do not fork a second layout config for live updates.

    Write back positions for NON-PARENT nodes only. In cytoscape a compound's position is
    derived from its children; setting a parent's position moves its children and would undo the
    exact restoration. Restoring every leaf makes each unchanged compound follow its children
    exactly, while a compound that genuinely gained a child moves — which is correct.

    SERIALIZE OVERLAPPING LAYOUTS with a generation token. This is not optional polish: today
    `runLayout` registers a one-shot `opts.cy.one('layoutstop', ...)` and starts an
    asynchronous layout, and `start()`, `replace()` and `add()` each start one with no
    in-flight guard. A live refresh arriving while a user expansion's layout is still running
    leaves two pending callbacks, each holding a DIFFERENT captured survivor map, each racing
    to restore positions and republish geometry. Whichever lands last wins, and it may be the
    older one — reintroducing exactly the movement D-06's write-back exists to eliminate, in
    the ordinary interaction case of "expand a directory while a re-index lands".

    The shape:
    - a module-scoped monotonic `layoutGeneration` counter, incremented BEFORE every layout
      start (in `runLayout` itself, so `start`, `replace`, `add` and the new live-update path
      all inherit it — do not bolt it onto the call sites individually);
    - `runLayout` captures its own token and its own survivor map in the closure;
    - the `layoutstop` callback FIRST compares its captured token against the current counter
      and returns immediately if they differ — no `resize`, no metrics, no survivor
      restoration, no `onGeometry` publish;
    - only the current run restores survivors and republishes geometry.

    If cytoscape's layout object exposes a `stop()`, call it on the superseded run as well —
    but the token guard is the correctness mechanism and must stand on its own, because
    `stop()` is not guaranteed to prevent an already-queued `layoutstop` from firing.

    Do NOT write the identifier `LAYOUT_OPTIONS_LIVE`, or any other `LAYOUT_OPTIONS`-prefixed
    identifier, anywhere in `GraphCanvas.svelte` — including inside a block comment. The
    acceptance criteria negative-grep for that shape, and the grep strips only `//` lines, so a
    `/* ... */` or JSDoc mention would self-invalidate the guard. Name the rule in prose without
    spelling the forbidden identifier.

    Verifying ELK option names: `elkjs` resolves to 0.9.3 and is a transitive dependency that
