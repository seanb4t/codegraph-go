<objective>
Put the stream on the wire: a per-request middleware that clears the absolute write deadline
for exactly one path, a handler that registers a subscriber and sends until the client goes
away, and the end-to-end proof that the whole path delivers message by message.

Purpose: two traps decide whether this works at all. The server's `writeTimeout` is an
ABSOLUTE deadline on a whole response, so an untouched stream dies at 60 seconds; and
connect-go's `checkServerStreamsCanFlush` REJECTS a streaming handler whose response writer
does not implement the flusher interface, so a middleware that wraps the writer in a custom
type does not merely lose flushing — it stops the handler being served at all.

Output: the transport half of live push, and the phase's tracer assertion.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> loopback listener | The streaming request crosses the origin/host guard like every other rpc |
| http.Server timeouts -> handler | A per-request deadline change is a deliberate relaxation of a documented safety property |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-19 | Denial of Service | write deadline cleared beyond its intended scope | high | mitigate | The middleware matches the generated streaming procedure constant only; a paired negative test proves a different path on the same server is still cut off at the small deadline. The four server timeout constants are unchanged and their existing set-equality guard still passes. |
| T-06-20 | Denial of Service | a slow client holding a goroutine forever | high | mitigate | The request context is cancelled when the client disconnects; the deferred unsubscribe removes the subscriber and ends the send loop, asserted by test and by goleak. The cleared deadline is per-request, not a licence to hold a goroutine past the client's life. |
| T-06-21 | Denial of Service | connect-go refusing the handler because the writer was wrapped | high | mitigate | The middleware passes the original writer through unwrapped, modelled on the existing guard; a test asserts the inner handler's writer satisfies the flusher interface. |
| T-06-22 | Spoofing | a cross-origin page opening a long-lived stream | high | mitigate | Unchanged and inherited: the middleware composes so the exact-match Origin/Host guard still runs before any handler is reachable; the security boundary does not move. |
| T-06-23 | Elevation of Privilege | the streaming method as a write vector | high | mitigate | The handler opens no store, holds no writer, and accepts only a resume cursor; the read-only method-set guard and the mutating-verb guard both cover it automatically. |
| T-06-24 | Repudiation | a client disconnect classified as an internal server error | low | mitigate | Vanished-client errors route through the existing `mapContextError`, so a closed tab reports as a cancellation rather than an operator-visible failure. |
| T-06-25 | Denial of Service | unbounded concurrent subscribers | medium | accept | The listener is loopback-only, same-origin-guarded and single-user by design (the v1 threat model); per-subscriber memory is already O(1) and each subscriber is released on disconnect. A global subscriber cap adds a failure mode without closing a reachable vector here. |
| T-06-26 | Tampering | resume cursor as an unvalidated input | low | mitigate | The cursor is a typed integer field on a generated message; it selects nothing and indexes nothing server-side (there is no history to replay), so no hand-rolled parsing or bounds logic is introduced. |
</threat_model>
