## Local toolchain note — read before the first Go command in this phase

This plan is in wave 1 and runs the first Go build/test of the phase, so the workaround
lands here rather than in a later plan that would find it already broken.

`go.mod` declares `go 1.26.5`, and `GOTOOLCHAIN` defaults to `auto`, which resolves UP to
whatever newer toolchain is installed. On a host with go1.27.0 that breaks the build
before any of this phase's code is reached: `cockroachdb/swiss` (indirect, via
`cockroachdb/pebble/v2`) fails to compile with `undefined: hashFn`, `undefined:
getRuntimeHasher`, `undefined: fastrand64`. Reproduced during this revision —
`go build ./internal/graphstore/` exits 1 under the default and exits 0 under
`GOTOOLCHAIN=go1.26.5`.

**Workaround: prefix local Go invocations with `GOTOOLCHAIN=go1.26.5`, or export it for
the session.** CI is unaffected: `.github/workflows/ci.yml` pins with
`go-version-file: go.mod`, so it gets 1.26.5 already. This is an environment fact, not a
plan defect and not something to "fix" by editing `go.mod` — do not change the declared Go
version to make a local build work. It applies to every Go `<verify>` block in this phase,
including plans that do not repeat this note.
