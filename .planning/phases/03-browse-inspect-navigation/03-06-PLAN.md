<objective>
Build the search surface: symbols and files as you type, a natural-language question on
Enter, and full keyboard drivability.

The trigger split is forced by the wire, not chosen for taste. `Search` returns bare
`Location`s. `Explore` attaches a bounded source blob per matched file for up to five
files and reads them off disk — roughly an order of magnitude more work. So typing
narrows and Enter asks a question. The interaction teaches itself, and it degrades
honestly: if `Explore` is slow, the live results are already on screen.

The section split is likewise forced. `Location` and `FileEntry` carry no comparable
score, so a merged list would need an invented heuristic that disagrees with the server's
own ordering and has nothing to be tested against. Two labelled sections, each in its own
RPC's order, and keyboard selection walking across them in visual order — the merged
FEEL costs nothing.

Purpose: this is the entry point to everything else in the phase. BRW-02's node view,
BRW-03's click-through and BRW-05's picker are all reached from here.

Output: a shared search controller module, a `SearchPanel` component built on the
vendored `Command` primitive, and the keyboard bindings.
</objective>

  <behavior>
    - A query of one character issues no RPC.
    - A query of two characters, after the debounce interval elapses, issues exactly one `Search` and one `Files`.
    - Three keystrokes within the debounce interval issue exactly one pair of RPCs, for the final value.
    - When a second query starts while the first is in flight, the first request's abort signal is aborted.
    - When the first query's response nevertheless resolves AFTER the second's, the controller's final state holds the SECOND query's results — asserted by value, not merely by call count.
    - `Explore` is issued only on an explicit submit, never by a value change; a test that types without submitting asserts the explore call count is zero AND that the live call count is non-zero, so the zero is proven to be a real absence rather than a controller that did nothing.
    - An `Explore` response with `empty` true yields the empty outcome; an `Explore` rejection yields the failed outcome; the two are different values.
    - A `Files` response is read according to its own `format` field.
    - Results are exposed in exactly the order the RPCs returned them.

  <action>
Create `web/src/lib/search.ts` exporting `SEARCH_DEBOUNCE_MS = 150` and
`SEARCH_MIN_CHARS = 2` as named constants (150ms because this server is on loopback, so
the low end of the 150-300ms range applies — the higher figures in general guidance are
for queries crossing a network; 2 characters because symbol search is a names case).

Export `createSearchController(client)` returning an object with a method to set the
current query value (live path) and a method to submit (explore path), plus a subscribable
state.

Cancellation is non-negotiable and independent of the delay. Debouncing alone does not fix
out-of-order responses: without aborting the superseded request, a slow response to a
shorter prefix can land after the response to a longer one and push the UI backward. Give
every dispatch an `AbortController` passed into the Connect call's own signal option, abort
the previous one before starting a new one, AND back that with a monotonically increasing
request identity that a resolving handler compares against the current value before
committing state. The abort handles the common case; the identity guard handles the race
the abort loses.

Expose the two live result lists separately, each holding exactly what its RPC returned,
in that order. Do not merge, re-rank, re-order, deduplicate or score them: `Location` and
`FileEntry` have no comparable field to rank on, and any ordering this module invented
would disagree with the server's own and be untestable against anything.

Keep `Explore` on a separate method with its own state slot so a submit never clears the
live results — BRW-08's word is "alongside".

Map every rejection through the shared error classifier from plan 03-04; add no second
error vocabulary here.

Write `web/tests/search.test.ts` first, covering every case in `<behavior>`, using
