<objective>
Wire the full migration pipeline in `migrate.Run(from, to, opts)`: resolve and open the read-only source, detect+guard it, create a sibling temp store, resume from the durable cursor if present, stream `files`→`nodes`→`edges` through `graphstore.Writer` in bounded batches (nodes-first so `PutEdge` gets the D-04 ownerPath), recompute per-file edge counts, run the D-09 validation pass, stamp a healthy `Meta`, and atomically swap the temp store into place — all fail-loud, never swallowing an I/O error.

Purpose: this is MIGR-01 (one-step convert) and MIGR-02 (resumable, version-stamped, validated) end-to-end. It is the highest-criticality plan: the I/O + partial-recovery profile where green suites historically missed real bugs, so its integration tests exercise happy/resume/source-unmodified/aged-DB explicitly.

Output: `internal/migrate/migrate.go` (Run + Options + Result) with fixture-driven integration tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted SQLite → new-format store | The whole one-shot transform from an arbitrary user's aged index into the target store |
| partial run → target directory | A crash mid-migration must not leave a fake-complete `.codegraph/` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-06-01 | Tampering | Source SQLite mutated during migration | high | mitigate | Source opened read-only end-to-end (reader.go); a before/after sha256 test asserts byte-identity and no sidecar. |
| T-07-06-02 | Tampering / Denial of Service | A crash leaving a half-written `.codegraph/` that looks complete | high | mitigate | Write into a sibling temp store; Meta.Healthy set only after validate; atomic swap only on success (D-07/D-10); a failed/aborted run leaves source + prior target untouched and the temp store for resume. |
| T-07-06-03 | Tampering | Silent I/O truncation / swallowed Commit or rename error producing a short graph reported as success | high | mitigate | Every error surfaced and wrapped (SQLite open, rows.Err, Commit, progress write, validate, rename); count reconciliation is a second backstop; tests assert non-zero exit on injected failures. |
| T-07-06-04 | Denial of Service | Unbounded Pebble batch on a monorepo-scale index exhausting memory | medium | mitigate | Bounded batches (batchSize puts per Commit) rather than one giant batch; the durable cursor advances per batch. |
| T-07-06-05 | Repudiation | A TS-id graph silently causing a surprising full re-index on first sync | low | mitigate | HealthMessage documents the first-sync full-reindex behavior (D-01 accept-and-document); no id recomputation, no silent Meta marker. |
