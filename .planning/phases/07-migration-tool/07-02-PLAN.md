<objective>
Add an additive `Writer.PutMigration([]byte)` / `Reader.GetMigration() ([]byte, error)` pair to the `graphstore` interfaces (RESEARCH §Writer Integration, Option A), backed by a new `m/migration` meta-namespace record. This is the storage door for the D-06 resumable migration progress cursor, keeping the progress record inside the D-04a boundary and cleanly distinct from the real `m/schema` Meta record.

Purpose: MIGR-02 resumability needs a durable, store-wide progress cursor. `metaKey(name)` already length-prefix-encodes an arbitrary name, so a second meta record is representable with zero key-format change — but the interfaces only expose `PutMeta`/`GetMeta` for the fixed `"schema"` name. This adds the minimal additive surface.

Output: `PutMigration`/`GetMigration` on the interfaces + pebble impls + a `migrationRecordName` const, with round-trip and absent-record tests.
</objective>

  <behavior>
    - Round-trip: Open store → NewWriter → PutMigration([]byte{...cursor bytes...}) → Commit → Snapshot → GetMigration returns the identical bytes.
    - Absent: a fresh store (no PutMigration ever committed) → GetMigration returns ErrNotFound (graphstore.ErrNotFound sentinel), never a nil-success or panic.
    - Isolation: after PutMeta(schema) AND PutMigration(cursor) in the same store, GetMeta returns the schema Meta unchanged and GetMigration returns the cursor bytes — the two records do not clobber each other (distinct keys m/schema vs m/migration).
    - Overwrite idempotency: PutMigration twice (different bytes) then GetMigration returns the last-written bytes (last-write-wins on the single key).
  </behavior>
  <action>
    In `keys.go` add `const migrationRecordName = "migration"` (documented as the additive second meta-namespace name; SchemaVersion stays 1 per the file's own additive-namespace precedent). In `store.go` add `PutMigration(data []byte) error` to the `Writer` interface (next to PutMeta) and `GetMigration() ([]byte, error)` to the `Reader` interface (next to GetMeta), with doc comments noting the payload is an opaque blob owned by the caller. In `batch.go` implement `func (w *pebbleWriter) PutMigration(data []byte) error` as a raw `w.batch.Set(metaKey(migrationRecordName), data, nil)` (NO deterministicMarshal — it is not a proto message). In `pebble_store.go` add a small raw-bytes getter alongside `getProto` (e.g. `getRaw(g getter, key []byte) ([]byte, error)` that returns a COPIED []byte and maps `pebble.ErrNotFound` → `graphstore.ErrNotFound`, closing the value's closer), and implement `func (r *pebbleReader) GetMigration() ([]byte, error)` via `getRaw(r.snap, metaKey(migrationRecordName))`. Copy the value bytes before returning (Pebble reuses the backing buffer after closer.Close). Keep any in-package test doubles / mock Writer-Reader implementations in graphstore tests compiling by adding the new methods to them.
    Create `internal/graphstore/migration_record_test.go` covering the four behaviors above.
