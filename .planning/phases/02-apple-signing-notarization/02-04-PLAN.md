<objective>
Rehearse the one path that cannot be rehearsed — and measure the ordering claim
instead of trusting it.

Purpose: D-08 locks rehearsal to the maintainer's Mac before any tag push, because
the release pipeline runs exactly once per tag and a wrong answer cannot be
withdrawn. D-09 requires that rehearsal to hard-fail by name on a missing
certificate or API key rather than after a network round-trip — the rule this
repository wrote after a signing pipe hung for five minutes and then failed on an
expired token. D-07 declines a permanent ordering regression test in favour of a
one-time recorded mutation, and the D-18 ruling hands that mutation an obvious,
cheap subject: configure cosign the pre-ruling way, record which bytes the bundle
then authenticates, revert.

**Two review findings reshaped this plan and are worth stating up front, because
both were cases of a plan asking for something no mechanism could deliver.** First,
the pre-notarize hash cannot be captured between two pipes of one release run —
GoReleaser owns those transitions and exposes no hook — so the baseline now comes
from a separate notarize-disabled build, with the build-reproducibility assumption
that licenses the substitution written down rather than assumed. Second, what
cosign signed cannot be recovered by re-hashing the path in the artifact metadata:
that metadata names the signature file, not its subject, and under the mutation
quill has already rewritten the file at that path. The subject is now determined
cryptographically, by verifying the bundle against both candidate files and
recording which one it authenticates. Gatekeeper assessment in this plan uses the
D-19 oracle (`-t install`, verdict by exit status), like everywhere else in the
phase.

The accepted consequence, stated plainly rather than glossed: a local rehearsal
does not exercise the CI environment, so first execution in CI remains genuinely
first execution.

Output: a guarded maintainer-only rehearsal target, and the measured SIGN-04
ordering evidence.
</objective>
