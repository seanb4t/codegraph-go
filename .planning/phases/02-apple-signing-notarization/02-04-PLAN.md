<objective>
Rehearse the one path that cannot be rehearsed — and measure the ordering claim
instead of trusting it.

Purpose: D-08 locks rehearsal to the maintainer's Mac before any tag push, because
the release pipeline runs exactly once per tag and a wrong answer cannot be
withdrawn. D-09 requires that rehearsal to hard-fail by name on a missing
certificate or API key rather than after a network round-trip — the rule this
repository wrote after a signing pipe hung for five minutes and then failed on an
expired token. D-07 declines a permanent ordering regression test in favour of a
one-time recorded mutation, and the D-18 ruling hands that mutation an obvious,
cheap subject: configure cosign the pre-ruling way, record the divergent hashes,
revert.

The accepted consequence, stated plainly rather than glossed: a local rehearsal
does not exercise the CI environment, so first execution in CI remains genuinely
first execution.

Output: a guarded maintainer-only rehearsal target, and the measured SIGN-04
ordering evidence.
</objective>

1. **SIGN-01 / idempotency / unresolved** — "What happens if this runs twice on
   the same input?" Genuinely applicable and engaged rather than passed through.
   Two distinct re-run surfaces exist. Locally, this rehearsal target can be run
   repeatedly; `--clean` wipes `dist/` each time, so the second run rebuilds and
   re-submits rather than reusing a stale artifact — cheap, but it means every
   rehearsal is a fresh Apple submission, and Apple's own history will accumulate
   entries that must not be mistaken for evidence about the shipped release. In
   CI, a re-run of `goreleaser release` against an already-published tag is
   governed by the release block's replace-existing-artifacts setting, and no pipe
   added in this phase introduces a second writer of an existing asset name — but
   a second notarization submission of an already-signed binary has not been
   exercised, and D-12's patch-forward rule means the recovery path for a partial
   release is a re-run rather than a delete-and-retry. Consequence if wrong: a
   patch-forward re-run could fail on an already-notarized input at exactly the
   moment recovery is needed. Carried into plan 02-07, where the real release is
   the only place it can be observed; the backstop truth in this plan's
   `must_haves` records the local half.
