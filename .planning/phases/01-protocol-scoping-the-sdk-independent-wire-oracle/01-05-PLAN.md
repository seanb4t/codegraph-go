<objective>
Freeze the multi-era Legacy handshake baseline: what today's `mark3labs`-backed server actually
answers when a client offers each of the four protocol revisions it supports, plus one revision it
does not recognize, plus a request that omits the version entirely.

Purpose: REQUIREMENTS.md names dropping Legacy support as "the single highest-consequence mistake
available in this milestone." Phase 3's SPEC-06 must assert Legacy compatibility against a real
pre-migration baseline instead of writing its first multi-era test against the SDK that already
claims to handle five eras. This baseline cannot be recaptured after Phase 2.

Output: six frozen era transcripts and the documented record that today's unsupported-version
behavior is silent coercion, not rejection.
</objective>
