<objective>
Prove the wire oracle can actually fail, and keep proving it. D-07 requires both halves: a one-time
mutation matrix run against the real binary and reverted, and a permanent in-suite guard set.

The permanent guards deliberately attack the **harness**, not the payload. A byte-exact comparator
is near-impossible to make vacuous on content — the real vacuity risks are structural: a scenario
list that silently shrinks, an empty transcript that compares equal, and a normalization rule that
quietly swallows more than its intended field.

Purpose: this repository's standing decision is that a gate is not trusted until demonstrated red
against a confirmed-applied mutation, and it has already shipped an inverted gate and a
never-firing regression check. The oracle is the gate every later phase in this milestone leans on.

Output: three permanent structural guards, per-rule normalization self-defeat cases, and a recorded
mutation matrix.
</objective>

    - `TestEmptyTranscriptNeverMatches`, three cases: comparing a real captured transcript against a zero-length expected value fails; comparing a zero-length capture against a real frozen transcript fails; and a frozen file that exists but is zero bytes fails loudly naming the file rather than being treated as a trivially satisfied comparison.
    - `TestNormalizationRulesMatchOnlyTheirOwnField`, one positive and **two** negative cases per rule in `Rules`. The second negative case is the one that actually tests D-04: it places **the exact same unstable value** in a field that must NOT be normalized. A negative case that merely uses a *different* value passes even against a value-wide substitution rule, so it proves nothing about field anchoring.
      - repoDir rule — positive: the capture-time fixture path as the value of a `"path"`-family field is replaced. Negative A: a *different* absolute path in a `"path"` field is left verbatim. Negative B: **the same fixture path** appearing inside a markdown `"text"` content value is left verbatim.
      - serverVersion rule — positive: the `version` value inside the `serverInfo` object is replaced. Negative A: a `"version"` key with a different value outside `serverInfo` is left verbatim. Negative B: **the same version string** as a `"version"` key inside a `clientInfo` object is left verbatim.
      - timestamp rule — positive: an RFC3339 value in a timestamp-named field is replaced. Negative A: a date-like string that is not valid RFC3339 is left verbatim. Negative B: **the same valid RFC3339 string** as the value of a non-timestamp field such as `"text"` or `"name"` is left verbatim.
      The negative half is the load-bearing half — a rule that over-matches quietly erases exactly the evidence the transcript exists to preserve. Addresses review concern: "the normalization tests do not enforce D-04 for timestamps" and "the repo-path rule is similarly positionality-blind."
    - `TestEveryDeclaredFiringRuleActuallyFires`: run a real capture for a representative scenario set, accumulate the per-rule ledgers returned by `NormalizeWithLedger`, and assert that every rule whose `ExpectFires` is true has a total hit count of at least one, and every rule whose `ExpectFires` is false has a non-empty `Why`. This is what distinguishes "the `serverInfo` anchor silently stopped matching because the SDK changed key order or spacing" — which otherwise surfaces as a misleading generic transcript diff — from a genuine byte change. Hand-constructed positive/negative cases cannot catch a dead rule; only a real capture can. Addresses review concerns: "the normalizer's `serverInfo` anchor fails silently" and "the timestamp normalization rule may be vacuous today."
    - `TestRuleTestCoverageScalesWithRules`: the number of distinct rule names exercised by `TestNormalizationRulesMatchOnlyTheirOwnField` equals `len(Rules)`, so adding a fourth rule without adding its cases fails rather than being silently untested.
    - `TestNormalizeIsIdentityWhenNothingMatches`: for input containing none of the three patterns, `Normalize` returns bytes byte-identical to its input, including key ordering, whitespace, and the presence or absence of every field.
    - `TestNormalizeHelpersFailLoudly`: each parsing or classification helper `normalize.go` introduces returns a non-nil error, or a documented false, on empty and malformed input.
    - Each guard is observed red before being trusted: temporarily break the property it guards (drop a scenario from the list, empty one transcript, widen one rule), confirm the specific guard fails, revert.
