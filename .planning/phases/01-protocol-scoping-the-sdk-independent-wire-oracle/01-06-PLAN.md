<objective>
Make D-03's anti-regeneration rule structural rather than conventional: a CI check that fails when
one pull request both changes a frozen transcript and changes something that could have caused the
diff.

Purpose: PITFALLS Trap C names "goldens regenerated from current behavior" as the way a wire oracle
stops being an oracle. Phase 2 must be frozen with no exceptions; Phase 3 legitimately regenerates,
but as its own separate, reviewable pull request. The rule is not "never regenerate" — it is
"never regenerate in the same change that could have caused the diff."

Output: a unit-tested classifier, a Taskfile target, a pull-request-only CI job, and the fixture
updates that keep the repository's single-definition property intact.
</objective>

    both, call `ParseChangedList` then `Classify`. Exit 0 when clean. Exit 1 with the verdict's

    `TRANSCRIPT_FREEZE_BASE` to be set, failing loudly with a message when it is not; verifies that
    ref resolves with `git rev-parse --verify`; computes `mb=$(git merge-base "$TRANSCRIPT_FREEZE_BASE" HEAD)`;
    writes `git diff --name-only "$mb" HEAD` to a temp file; writes `git diff "$mb" HEAD -- go.mod`
    to a second temp file; and runs `go run ./tools/transcriptfreeze` against both. Using the
    merge-base diff is what makes this pull-request-granular and therefore squash-merge-safe — a
    per-commit check would be defeated by the squash this repository uses. Do not add `status:` or
    `platforms:` to this target: both silently skip a task instead of failing it, and the
    Taskfile shape guard rejects them by name.

    `if: github.event_name == 'pull_request'`. Its checkout step must set `fetch-depth: 0` so the

    `Anti-regeneration guard (D-03, blocking)`, carries a step-level
    `env: TRANSCRIPT_FREEZE_BASE: origin/${{ github.event.pull_request.base.ref }}`, and its `run:`
    body is exactly `task check:transcript-freeze`. Passing the base ref through a step-level `env:`

    stale exception would silently widen the allowlist.
  </action>

## Notes for Phase 3

Transcripts legitimately change in Phase 3 — `resultType`, `_meta` server info, and the cache-control
fields are deliberate wire additions. This guard does not forbid that; it forbids doing it in the
same pull request as the change that could have caused it. Phase 3 regenerates as its own separate,
reviewable pull request. Phase 2 is frozen with no exceptions.
</verification>
