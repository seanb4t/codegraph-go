  <action>
    Build `tools/mcpaudit`, a standalone Go program an agent launches in place of
    `codegraph serve --mcp`. It **proxies, never terminates** — the developer's agent must keep
    working for the whole audit (CONTEXT `<specifics>`).

    `proxy.go`: define
    `type Observation struct { PID int; StartedAt string; Argv []string; Method string; ProtocolVersion string; ClientName string; ClientVersion string; Capabilities json.RawMessage; PreInitializeProbe bool; RawFrame string }`.
    Write `ParseFirstFrame(line []byte) (Observation, error)` decoding only into a generic
    `map[string]any` / anonymous struct — never into an MCP SDK type (VRFY-01's discipline applies
    to every measurement instrument in this milestone). Write
    `Run(cfg Config) error` where `Config` carries `RealBin string`, `RealArgs []string`, and
    `LogPath string`: append a process-start record to `LogPath` immediately; spawn
    `exec.Command(cfg.RealBin, cfg.RealArgs...)` with piped stdin/stdout/stderr; read the caller's
    stdin line-by-line with a `bufio.Scanner` sized `scanner.Buffer(make([]byte, 0, 64*1024), 10*1024*1024)`,
    writing every line verbatim (plus its newline) to the child's stdin and, for the first line
    only, also passing it to `ParseFirstFrame` and appending the resulting `Observation` as one JSON
    line to `LogPath`; concurrently `io.Copy` child stdout to os.Stdout and child stderr to
    os.Stderr. Propagate the child's exit code. A `ParseFirstFrame` error is logged as an
    `Observation` with the error text and the raw frame — it must never abort the proxy, because
    aborting would break the developer's agent mid-session.

    `main.go`: flags `-real` (path to the real `codegraph` binary, required), `-log` (observation
    log path, required), and `-args` (comma-separated args to pass to the real binary, defaulting
    to `serve,--mcp`). Fail loudly with a non-zero exit and a message on stderr if `-real` or
    `-log` is missing — a silently-misconfigured shim would produce an empty log that reads like
    "the client sent nothing".

    Open `LogPath` with `os.OpenFile(..., os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0o600)` — append-only
    so a second process spawn adds records rather than truncating the first spawn's evidence, and
    `0o600` because the log carries client identity (T-02-01).

    `proxy_test.go`: table-driven tests for every behavior above, including the `FailLoudly` table
    and a `_IsError` companion following the repo conventions
    (`TestWorkflowSourceHelpersFailLoudly` and the `Test<Name>_<WhatIsWrong>IsError` family under
    `internal/upgrade/`). The byte-exactness test uses a fake child (`go run`-free: a small
    `exec.Command("cat")`-equivalent or a test helper binary built by `TestMain`) so no network or
    real index is required.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent client → `tools/mcpaudit` stdin | Untrusted JSON-RPC frames carrying self-reported client identity |
| `tools/mcpaudit` → observation log file | Client identity and capabilities written to disk |
| audit procedure → developer's real agent configuration files | A measurement instrument temporarily inserted into the developer's working setup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `tools/mcpaudit` observation log | high | mitigate | Log file opened `0o600`, append-only; only the first frame is recorded, never subsequent traffic or process environment; the audit doc transcribes the eight declared columns and never pastes raw frames |
| T-02-02 | Tampering | developer's agent MCP configuration files | high | mitigate | One client at a time; byte-for-byte backup taken before edit and restored after; the blocking checkpoint verifies each client still connects and no backup file survives |
| T-02-03 | Spoofing | `tools/mcpaudit` sits inside the agent's trust path | medium | mitigate | Byte-exact passthrough in both directions, asserted by `TestProxyIsByteExactInBothDirections`; the tee is non-destructive and a parse failure never alters or drops a frame |
| T-02-04 | Denial of Service | a `ParseFirstFrame` error aborting the proxy would break the developer's live agent session | medium | mitigate | Parse errors are logged as an `Observation` carrying the error text and the raw frame; the proxy loop continues unconditionally |
| T-02-SC | Tampering | package-manager installs | high | accept | No package-manager install occurs in this plan; `tools/mcpaudit` uses only the Go standard library and `go.mod` is unchanged |
</threat_model>
