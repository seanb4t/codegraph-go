  <behavior>
    - `ParseClientFrame` given a real `initialize` request returns an `Observation` carrying `Method="initialize"`, `ProtocolVersion` (the OFFERED value), `ClientName`, `ClientVersion`, the raw `Capabilities` JSON, and the request `ID`, with `PreInitializeProbe=false`.
    - `ParseClientFrame` given a frame whose `method` is anything other than `initialize` returns an `Observation` with that method recorded and, when it is the FIRST client frame of the session, `PreInitializeProbe=true` — this is D-11's probe column, per PITFALLS Pitfall 8.
    - `ParseServerFrame` given the server's `initialize` response, matched to the recorded request `ID`, returns the NEGOTIATED `result.protocolVersion` and the server's `serverInfo`. Decoding only those fields out of the raw line, never through an SDK type.
    - A session whose first client frame is a probe (`server/discover` or anything else) and whose SECOND frame is `initialize` yields ONE observation set carrying both `PreInitializeProbe=true` and the full initialize request fields — the two facts are recorded together, not traded off against each other.
    - `ParseClientFrame` / `ParseServerFrame` given empty input, a non-JSON line, or a JSON object with no `method` and no `result`/`error` key return a non-nil error naming what was wrong (`FailLoudly` table, per the `TestWorkflowSourceHelpersFailLoudly` convention in `internal/upgrade/release_workflow_shape_test.go:583`).
    - `Run` proxying a scripted byte stream in both directions yields caller-visible output bytes byte-identical to what the child wrote, and child-stdin bytes byte-identical to what the caller wrote — including CRLF line endings and a final frame with no trailing newline. The tee must be non-destructive and must not normalize line terminators.
    - Every invocation of the shim appends exactly one process-start record (pid + RFC3339 timestamp + argv) to the observation log, so a client that spawns the server a second time is visible as two records (D-11's second-process-spawn column).
  </behavior>

  <action>
    Build `tools/mcpaudit`, a standalone Go program an agent launches in place of
    `codegraph serve --mcp`. It **proxies, never terminates** — the developer's agent must keep
    working for the whole audit (CONTEXT `<specifics>`).

    `proxy.go`: define
    `type Observation struct { PID int; StartedAt string; Argv []string; FirstMethod string; PreInitializeProbe bool; InitializeID json.RawMessage; OfferedProtocolVersion string; NegotiatedProtocolVersion string; ClientName string; ClientVersion string; ServerName string; ServerVersion string; Capabilities json.RawMessage; ParseError string; FrameDigest string }`.

    **The shim observes BOTH directions, and keeps observing until the initialize exchange is
    complete.** The pre-review draft parsed only the first client frame and `io.Copy`-ed the child's
    stdout straight through, which makes two of D-11's required columns unfillable: the NEGOTIATED
    version lives only in the server's `initialize` response on child stdout, and a session whose
    first frame is a probe would record the probe and never inspect the subsequent `initialize`.
    Addresses review concerns: "the shim cannot measure the negotiated version as designed" and
    "capturing only the first frame loses initialize after a probe."

    Write `ParseClientFrame(line []byte) (ClientFrame, error)` and
    `ParseServerFrame(line []byte) (ServerFrame, error)`, both decoding only into a generic
    `map[string]any` / anonymous struct — never into an MCP SDK type (VRFY-01's discipline applies
    to every measurement instrument in this milestone).

    Write `Run(cfg Config) error` where `Config` carries `RealBin string`, `RealArgs []string`, and
    `LogPath string`:
    - Append a process-start record to `LogPath` immediately, then spawn
      `exec.Command(cfg.RealBin, cfg.RealArgs...)` with piped stdin/stdout/stderr.
    - **Forward with a byte-preserving reader, not `bufio.Scanner`.** Use
      `bufio.Reader.ReadBytes('\n')` in both directions and write back exactly the bytes read,
      including the terminator when one was present and nothing extra when the stream ended without
      one. `Scanner` strips the terminator, and re-appending `'\n'` silently rewrites CRLF input and
      invents a trailing newline on a final unterminated frame — which contradicts the byte-exact
      passthrough this shim's whole trustworthiness rests on. Size the reader's buffer to 10 MB to
      match the oracle's cap. Addresses review concern: "the proxy is not byte-exact."
    - Tee each forwarded line to an observer that runs until the initialize exchange is complete:
      record the FIRST client frame's method and set `PreInitializeProbe` when it is not
      `initialize`; keep inspecting subsequent client frames until one IS `initialize`, then record
      its `ID`, offered `protocolVersion`, `clientInfo` and `capabilities`; and inspect server
      frames until one carries a `result` whose `id` matches that recorded `ID`, then record its
      `result.protocolVersion` as `NegotiatedProtocolVersion` and its `serverInfo`. Once both
      halves are recorded, append the single completed `Observation` as one JSON line to `LogPath`
      and stop observing — subsequent traffic is forwarded and never inspected.
    - Propagate the child's exit code. If the process exits before the exchange completes, append
      the partial `Observation` so an incomplete measurement is visible as incomplete rather than
      absent.
    - A parse error is recorded in `ParseError` and **never aborts the proxy** — aborting would
      break the developer's agent mid-session.
    - **Never store a raw frame verbatim.** The pre-review draft wrote the offending raw frame into
      the log on a parse error; a malformed frame can carry arbitrary unrelated content, which
      contradicts this plan's own minimization goal (T-02-01). Record `FrameDigest` — the SHA-256 of
      the frame — plus the first 64 bytes with non-printable bytes `%q`-escaped, and nothing more.
      Addresses review concern: "raw parse errors are written to the audit log despite the stated
      minimization goal."

    `main.go`: flags `-real` (path to the real `codegraph` binary, required), `-log` (observation
    log path, required), and `-args` (comma-separated args to pass to the real binary, defaulting
    to `serve,--mcp`). Fail loudly with a non-zero exit and a message on stderr if `-real` or
    `-log` is missing — a silently-misconfigured shim would produce an empty log that reads like
    "the client sent nothing".

    Open `LogPath` with `os.OpenFile(..., os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0o600)` — append-only
    so a second process spawn adds records rather than truncating the first spawn's evidence, and
    `0o600` because the log carries client identity (T-02-01).

    `proxy_test.go`: table-driven tests for every behavior above, including the `FailLoudly` table
    and a `_IsError` companion following the repo conventions
    (`TestWorkflowSourceHelpersFailLoudly` and the `Test<Name>_<WhatIsWrong>IsError` family under
    `internal/upgrade/`). The byte-exactness test uses a fake child (`go run`-free: a small
    `exec.Command("cat")`-equivalent or a test helper binary built by `TestMain`) so no network or
    real index is required.
  </action>
