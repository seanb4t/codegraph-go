(VRFY-04's hard ordering constraint).

**Signal:** `chosen` — a value previously *derived* from the SDK (`mcp.LATEST_PROTOCOL_VERSION`)
becomes a value this repo *chooses* (`internal/mcp.ProtocolVersion`). Secondary `pluralization`
signal: `internal/mcp.Server` admits a second backend implementation (Phase 2's official go-sdk)
where `*server.MCPServer` admitted exactly one.

**Primary noun:** "the protocol version this server declares" is now owned by
`internal/mcp.ProtocolVersion`.

**Decision: `promote`.** The repo-owned literal is promoted to the primary source of truth; the
SDK's own constant is demoted to an implementation detail of one backend and is forbidden
tree-wide by plan 03's archtest. This is deliberately *not* add-alongside: leaving both live is
exactly the drift PITFALLS Pitfall 2 names, where a dependency bump silently moves wire behavior.

**Invariant test (accepted):** plan 03's `TestNoExternalProtocolVersionConstantReferences` is the
invariant that goes red the instant a future phase reintroduces an SDK-owned protocol-version
constant reference anywhere in the tree, including `_test.go` files.
