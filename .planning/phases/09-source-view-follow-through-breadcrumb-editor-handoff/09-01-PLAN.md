<objective>
Land the editor-handoff wire slice end to end on one thin path: `GetEditorLink` (UIService's 15th
rpc) from a real Connect client, through the real listener, through the ONE repo-root confinement gate,
through a scheme-allowlisted URI template, out to a BUILDABLE `vscode://` URL — and then the
operator's way of setting that template, `codegraph ui --editor-url` with its env-var twin and its
off switch, failing fast on a malformed value before the port is ever bound.

Purpose: this is the phase's tracer, and it is the editor-link slice rather than the breadcrumb on
purpose. The ROADMAP sequences BRW-10 first inside the phase because it is the smallest demonstrable
item; that ordering is honored at the UI level — plan 09-03 (wave 2) makes the breadcrumb the first
thing verified in a live browser after the shared per-line restructure, before any editor-link UI
lands in wave 3. But the phase's hardest constraint (Constraint Analysis) is the security boundary:
confinement and the positive scheme allowlist at the RPC boundary, plus a wire shape that lives under
the repo's additive-only proto discipline. A wrong call there is the costliest thing in the phase to
undo, so it is proven on the agent's best early-context tokens, after one commit rather than ten.
The breadcrumb has no proto, no Engine and no CLI surface — a tracer through it would prove nothing
about the layers this phase actually risks.

Output: `GetEditorLink` on the wire with its closed enums and presets; `internal/uiserver/editorlink.go`
as `permalink.go`'s structural twin; `codegraph ui --editor-url` / `--no-editor-url` /
`CODEGRAPH_EDITOR_URL` / `CODEGRAPH_NO_EDITOR_URL` resolved once at startup into
`uiserver.Options.EditorLink`; every read-only and field-number guard moved in the same commit as the
proto.

**Commit discipline (TDD mode, Phase 8 precedent).** Both tasks are `tdd="true"`. GSD's
`tdd-red-evidence` check parses TAP only and misreads `go test` output, so do NOT bend Go tests to
it: carry RED→GREEN through this plan's own Go-native verify gates and paste the RED transcript into
the SUMMARY. To make the RED an assertion failure rather than a compile error (a compile error is
INVALID_RED per tdd.md #3770), the `test(09-01): …` commit lands the proto, the regenerated code, the
fixtures and the DECLARED signatures whose bodies return `connect.CodeUnimplemented` (handler) or zero
values (resolver) — the target tests then fail on their own assertions. The `feat(09-01): …` commit
replaces those bodies with the real implementation.
</objective>
