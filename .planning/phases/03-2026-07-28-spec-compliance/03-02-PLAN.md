<objective>
Decide, and then implement, what the anti-regeneration guard does when Phase 3's
own pull request arrives — before that pull request exists, not at PR time.

Purpose: 03-RESEARCH.md Q6 proved by git simulation that `task
check:transcript-freeze` returns a hard Violation (exit 1) for a normal Phase 3
diff. 02-02's self-expiring exemption is keyed to a `go.mod` diff that removes
mark3labs and adds go-sdk — a shape Phase 3 cannot reproduce, by design. And the
guard's own remedy, "split this into two pull requests," was proven structurally
unavailable in Phase 2. So the phase has exactly two possible PR-time outcomes
today, and **both are bad**:

- If the PR base still predates Phase 2's `go.mod` swap, `sdkSwapExemption` fires
  and the run exits 0 — but the exemption notice says "this is SDK-01's one-time
  mark3labs-to-go-sdk transition," which is the wrong reason. Phase 3's own
  regeneration passes silently, laundered under Phase 2's waiver.
- If the base postdates that swap, the run exits 1 and the PR is blocked with no
  achievable remedy.

A guard whose only two outcomes are "wrong reason" and "no way forward" needs a
decision, and that decision belongs to the maintainer, not to the planner.

Output: one recorded decision plus its implementation, its stated stance, and
proof that whatever the exit code becomes, the detection still fires.
</objective>

  <context>
    The guard exists to stop PITFALLS Trap C: a golden file regenerated in the same
    change as the behavior it was supposed to catch, so the regression and its
    cover-up land together and no gate ever fires. That is a real failure mode this
    project takes seriously.

    But the guard's remedy — split into two PRs — cannot be executed here. PR-1
    (server change, no transcripts) fails `TestFrozenTranscriptsMatch`, a required
    PR leg. PR-2 (transcripts only) would be green, but PR-1 can never merge to
    create PR-2's base. Phase 2 hit this and answered it with a one-time,
    self-expiring exemption keyed to a `go.mod` diff shape that can occur exactly
    once in this repository's history. Phase 3 has no equivalent shape. Phase 5
    (SPEC-09) will have the same problem again.

    Meanwhile the mitigation that actually worked in Phase 2 was not the guard: it
    was D-01/D-03's reviewed-diff pass — capture before and after, read every changed
    line, name every cause in the commit message. That pass caught a ninth,
    unpredicted semantic regression (`edge-call-before-initialize` flipping from
    success to rejection) that no automated comparator and no prior research
    document had found. 03-CONTEXT.md's calibration section reaffirms that mechanism
    and forbids adding ceremony on top of it.

    Note that a decision is required even if the phase's PR happens to merge from a
    base that still predates Phase 2's `go.mod` swap: in that case the guard exits 0
    for the wrong reason, printing an exemption notice that misattributes Phase 3's
    regeneration to SDK-01's dependency transition. Doing nothing is not one of the
    outcomes on the table.
  </context>

    - Given a changed-file list containing a transcript path and an `internal/mcp`
      Go path, and an empty go.mod diff, `run()` returns the exit code the chosen
      option specifies (0 under option-advisory, 1 under option-exempt when the

      and writes nothing about a collision.

      code is not collapsed into the collision code by this change.
    - Given a malformed changed-file record, `run()` returns 2.
    - The report text for a detected collision names both offending sides, so a
      reviewer reading only the CI log knows which transcripts moved alongside which
      server files.

    `run()` writes to `os.Stderr` today; introduce the narrowest seam needed to
