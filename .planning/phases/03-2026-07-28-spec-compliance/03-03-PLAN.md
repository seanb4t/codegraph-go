<objective>
Close SPEC-02 by proving it, not by building it.

Purpose: 03-CONTEXT.md called SPEC-02 "the least understood item in the phase" and
recorded an observed `-32601` where the requirement demands `-32022`. 03-RESEARCH.md
root-caused that observation completely: the probe offered `"1999-01-01"`, which
sorts lexically *before* `"2026-07-28"`, and go-sdk's unexported
`validateRequestMeta` uses a plain string comparison to decide whether a request
"uses the new protocol" at all. Anything lexically smaller is reclassified as
not-modern before the unsupported-version check ever runs, and `server/discover`
is a Modern-only method, so the request falls to the ordinary method-availability
gate — whose message is then further overwritten by the transport's generic
`errors.Is(ErrMethodNotFound)` rewrite. Both halves of SPEC-02 are **already
correct** for every shape a real Modern client constructs, confirmed empirically
against the built binary across six distinct `_meta` shapes.

So this plan writes no server code. It freezes the two answers SPEC-02 actually
demands, anchors both against hand-authored literals, and records the `-32601`
finding in-file so nobody re-opens it as a bug six months from now.

Output: two new scenarios, one new hand-authored error-code constant, two new
anchors, two new frozen transcripts, and `ExpectedScenarioCount` at 26.
</objective>

| MCP client → per-request `_meta` → go-sdk's `validateRequestMeta` | The trust boundary this plan asserts on. Every field is attacker-shapeable. It is wholly owned by go-sdk and runs before any codegraph-go code, which is why this plan's only correct move is assertion. |
| Wire-oracle capture → committed `.golden` | Captured error responses become repository artifacts. Error `data` payloads echo the requested version back, so whatever the scenario sends lands in the repo. |
