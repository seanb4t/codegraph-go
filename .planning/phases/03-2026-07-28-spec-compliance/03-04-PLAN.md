<objective>
Make the tool catalog tell the truth about the index that exists right now, rather
than the one that existed when the process started.

Purpose: today `hasIndex` is a `bool` parameter snapshotted at `BuildServer` time,
so an agent that starts a codegraph MCP session in an unindexed repository and
then runs `codegraph init` sees zero tools until it restarts the client. SPEC-04's
`ttlMs: 0` + `cacheScope: "private"` pairing is a promise that the catalog is
always current; SPEC-05 is the half that makes the promise true. STATE.md locks
the two as "two halves of one correctness property, not independent options."

D-05 locked the mechanism: `Server.AddTool` / `Server.RemoveTools` mutation rather
than per-call filtering, chosen because mutation is faithful to "the catalog
changed" and pre-builds most of SPEC-09's substrate. D-05 also flagged two things
the planner had to resolve with evidence. Both are now resolved and **must not be
re-opened**: 03-RESEARCH.md traced every mutator and reader through the same
`s.mu` and confirmed calling `AddTool` from inside the existing middleware closure
can neither deadlock nor race a concurrent `tools/call`; and the fsnotify watcher
is explicitly, in its own doc comment at `internal/cli/serve.go:71-78`, a no-op for
exactly this scenario, so the trigger is a per-request re-check.

Output: a factored registration seam driven by a per-request re-check, a
mutation-safe tool count, two new Go-level set-equality assertions, one new
wire-oracle scenario driving a real mid-session `codegraph init`, and
`ExpectedScenarioCount` at 27.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client request → the per-request index re-check | New this phase. The re-check runs as a side effect of handling an untrusted request. Whatever it reads from the request becomes attacker-influenceable. |
| Filesystem state (`.codegraph/` presence) → the advertised tool catalog | New this phase. A process outside the server's control now changes what the server advertises mid-session. |
| Construction-time `repoPath` → `confineToRepoRoot` | The pre-existing CR-02 trust boundary. This plan must leave it exactly where it is. |
| Wire-oracle `Capture` → a spawned `codegraph init` subprocess | The harness now runs a second subprocess mid-capture against a temp directory it owns. |

Mitigated structurally: the re-check takes only the server's construction-time `startPath` and reads nothing from `req`.
