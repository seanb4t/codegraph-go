<objective>
Deliver WRK-02: select several files at once and see what they affect.

D-15 chose search-and-add with removable chips, reusing two things that already
exist rather than inventing either. The interaction model is `search.ts`'s
controller — a ~150ms debounce, one `AbortController` per dispatch, and a
monotonically increasing request identity, because debouncing alone does not fix
out-of-order responses: a slow response to a shorter prefix can still land after
the response to a longer one. The affordance is 03-06's vendored `Command`
primitive, already proven to traverse group boundaries in visual order.

This plan is the reason 04-02 exists. Live file search against the `Files` rpc
returned zero matches for any nested path, because the glob never crossed a `/` —
found live in Phase 3's UAT, not assumed. 04-02 fixed that at the source for the
CLI, MCP and UI at once. The nested-result assertion in this plan's tests is the
observable proof that the dependency is real rather than nominal.

Purpose: WRK-02, and the fourth of four Workbench tabs.
Output: a reusable file-search controller, a chip-based multi-file picker, the
Affected column definition, and a `/workbench` where every tab is live.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| typed search term → `FilesRequest.pattern` | User text is interpolated into a glob pattern sent to the server |
| chip set → repeated `file=` URL keys → `AffectedRequest.files` | User-selected, user-editable path strings cross into an RPC argument |
| `Files` results → rendered picker list | Server-provided repo-relative paths are rendered |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-22 | Denial of Service | a typed term containing glob metacharacters producing a pathological pattern | medium | mitigate | `Engine.Files` refuses a malformed pattern at its pre-scan sanity check before any store iteration begins (unchanged by 04-02), the matcher is a glob engine with no catastrophic-backtracking class, and the result set stays capped at `MaxLimit`. The controller additionally enforces a minimum term length and a debounce, so a single keystroke cannot fan out into a request storm (ASVS V5) |
| T-04-23 | Denial of Service | rapid typing issuing overlapping `Files` queries | medium | mitigate | One `AbortController` per dispatch plus a monotonic request identity, imported from `search.ts` rather than reimplemented; Task 1 asserts the aborted signals and the out-of-order-discard directly |
| T-04-24 | Spoofing | a shared `?mode=affected&file=…` link reproducing a different selection than its sender made | medium | mitigate | Repeated `file=` keys are what `URLSearchParams` natively models, read with `getAll`; Task 2 asserts both directions of the round trip AND the comma-containing-path case that a delimiter encoding would corrupt. 04-01's `parse(serialize(p))` assertion binds the two functions together |
| T-04-25 | Tampering | an arbitrary path string typed directly into a `file=` URL parameter reaching `AffectedRequest.files` | low | accept | `Affected` resolves paths against the indexed record set — it performs no filesystem read and no path-confined open, so there is no traversal sink here. The confined surfaces (`GetNodeDetail`, `GetPermalink`) go through `(*query.Engine).ValidateRepoRelativePath` (SRV-05) and are untouched by this plan |
| T-04-26 | Information Disclosure | rendered repo-relative paths in the picker and the chips | low | accept | Repo-relative only; the same class of value Browse already renders; the listener is loopback-bound with exact-match Origin/Host validation |
</threat_model>
