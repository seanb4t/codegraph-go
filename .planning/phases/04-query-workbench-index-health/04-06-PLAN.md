<objective>
Deliver WRK-02: select several files at once and see what they affect.

D-15 chose search-and-add with removable chips, reusing two things that already
exist rather than inventing either. The interaction model is `search.ts`'s
controller — a ~150ms debounce, one `AbortController` per dispatch, and a
monotonically increasing request identity, because debouncing alone does not fix
out-of-order responses: a slow response to a shorter prefix can still land after
the response to a longer one. The affordance is 03-06's vendored `Command`
primitive, already proven to traverse group boundaries in visual order.

This plan is the reason 04-02 exists. Live file search against the `Files` rpc
returned zero matches for any nested path, because the glob never crossed a `/` —
found live in Phase 3's UAT, not assumed. 04-02 fixed that at the source for the
CLI, MCP and UI at once. The nested-result assertion in this plan's tests is the
observable proof that the dependency is real rather than nominal.

Purpose: WRK-02, and the fourth of four Workbench tabs.
Output: a reusable file-search controller, a chip-based multi-file picker, the
Affected column definition, and a `/workbench` where every tab is live.
</objective>
