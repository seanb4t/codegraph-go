<objective>
Put the file rollup on the wire as one new additive read-only rpc — the twelfth —
and close by measurement the wire-size question RESEARCH left as an estimate.

`internal/query.FileGraphResult` already carries everything the graph view needs
after 05-01. The gap is the wire, so this plan is a mapping layer following the
`healthToProto` convention that 04-03 established, not new engine work.

Two things make this plan non-mechanical. First, proto field numbers on this project
are additive-only and are never renumbered or reused (D-02a), so the message shape is
a one-way door and earns the same `blocking-human` freeze `GetPermalink` (03-05) and
`GetHealth` (04-03) both earned before codegen. Second, `internal/uiserver/readonly_test.go`
carries a nineteen-substring `mutatingVerbs` fixture applied with a bare
`strings.Contains` over every method name — the guard that rejected `GetIndexHealth`
in Phase 4 because the fixture contains the literal `Index`. `FileGraph` clears all
nineteen, and that must be re-verified at freeze time rather than trusted from a
research document.

RESEARCH estimated the guava-scale response at 5-6 MB against a 16 MiB ceiling and
explicitly flagged the estimate as unverified. This plan measures it. An estimate
presented as a measurement is the failure GRF-01 exists to prevent, and it would be
incoherent to permit it one layer down.

Purpose: nothing in the browser can be built until this data crosses the wire.
Output: a twelfth read-only rpc, its messages, its handler and named mapper,
regenerated Go and TypeScript clients, the two load-bearing test literals updated in
the same commit, and a recorded response-size measurement against the pinned corpus.
</objective>
