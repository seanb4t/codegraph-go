<objective>
Wire the eleven new Cobra commands into the existing tree (D-01): `query`, `node`, `search`, `callers`, `callees`, `impact`, `affected`, `files`, `status`, `explore`, and `serve`. Each command is thin (D-01) — it resolves `-p/--path` (D-01a) and per-command flags, delegates to `internal/query.Engine` (or, for `serve`, `internal/mcp`), and writes to `cmd.OutOrStdout()`. `--json` toggles JSON on the structured commands; `explore`/`node` emit markdown text only (D-01b). This is the user-facing surface for success criteria 1 and 2, and it exposes the MCP server via `serve --mcp` (MCP-01 command surface).

Purpose: All engine logic already exists and is tested (03-03..03-07); this plan is glue (`type: execute`) that exposes it. A blocking human-verify checkpoint confirms the live stdio MCP handshake (tool visibility) that can't be scripted as a Go unit test.

</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI user flags → engine | `-p`, `-f`, `--depth`, `--limit`, `--max-files`, `--kind`, `--pattern` untrusted |
| CODEGRAPH_MCP_TOOLS → serve | operator allowlist; garbage names must not crash serve |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-08-DoS | Denial of Service | numeric flags | high | mitigate | Commands pass flags through the engine's `clampDepth`/`validate*` (03-02) — no command bypasses the shared bounds |
| T-03-08-Path | Tampering / Information Disclosure | -p/-f path flags | high | mitigate | Path flags resolve through `query.OpenAt`/`ResolveCodegraphDir` + the confined disk read (03-06); no raw user path reaches an unbounded read |
| T-03-08-Warn | Information Disclosure | serve allowlist warnings | low | mitigate | Unknown-name warnings go to `cmd.ErrOrStderr()`, never stdout (JSON-RPC transport) |
| T-03-SC | Tampering | package installs | low | accept | No new dependency here (mcp-go added in 03-07) |
</threat_model>
