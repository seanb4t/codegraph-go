## Pre-Audit Repair (recorded, not hidden)

This audit was preceded by a bookkeeping repair committed as `1a19b22`. Two defects were found during
milestone-close pre-flight and fixed **before** this audit ran, because both would have corrupted the
audit's own scope:

1. **`### Phase 3:` detail heading was missing from ROADMAP.md.** Deleted by commit `4d3e4d7`
   (`docs(02): create phase 2 ... plan`), which replaced the heading line in place with Phase 2's last
   plan bullet. `init.manager` consequently reported a **five-phase** milestone with Phase 3 absorbed
   into Phase 2's section, and `roadmap get-phase 3` returned `malformed_roadmap`. Notably
   `roadmap validate` returned `{"warnings":[]}` — green — throughout. Restored verbatim.
2. **Phase 3's plan checkboxes and FIXT-03 / FIXT-07 were never flipped.** Root cause is the same
   defect that stranded Phase 5's bookkeeping a day earlier: Phase 3 has no UAT file, so
   `phase uat-passed 3` returns `passed: false` with an **empty `blockers` array**, and the transition
   step never runs. Repaired with the tool's own verbs (`roadmap update-plan-progress 3`,
   `phase complete 3`, then `phase complete 6` to restore the state pointer).

**Method note for future audits:** to prove a ROADMAP is readable, iterate `roadmap get-phase N` over
every phase in the summary list. `roadmap validate` does not check heading↔summary correspondence and
will not catch this class of defect.

### Two claims corrected during re-verification

- **"The scenario count is derived from authoritative sources, not hand-maintained."** Inaccurate as
  stated. `goldenTotal` is summed from `expectedGoCaptures`, a hand-written Go slice in
  `testdata/golden/golden_test.go:170`. What makes the count trustworthy is the **pairing**:
  `TestGoldenScenarioCountIsExact` pins the enumeration to the `ExpectedGoldenScenarioCount` constant
  (with both legs fatal at zero), and `TestReFrozenGoldensValid` pins the same enumeration to the
  filesystem via `os.ReadFile` (fatal on a missing file, reporting `verified/expectedTotal`). Neither
  test alone is sufficient; together they are sound, and they are the positive-assertion shape rule
  `84d1gfpywd` requires. The conclusion stands; the reasoning is restated correctly here.
- **A 26-vs-24 file discrepancy that is not a discrepancy.** `testdata/golden/corpus/` holds 24
  capture files, while the enumeration asserts 26. The remaining two live at repo-root
  `corpus/behavioral/` (`go-explore-multi.json`, `go-node-multi.json`) because
  `golden_test.go:255-258` special-cases the `behavioral` slug. 24 + 2 = 26. Verified by execution.
