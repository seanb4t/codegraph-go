# Add the SHA-pinned cosign-installer step to post-release-verify.yml's `self-upgrade` job

## Objective

`post-release-verify.yml`'s `self-upgrade` job must install cosign before it
runs `task verify:self-upgrade`, using the exact same SHA pin the two sibling
jobs in that file already use — and the invariant must be pinned by a test so
the next Taskfile target that grows a cosign precondition cannot silently ship
the same defect.

## Origin — the measured defect

Release v0.9.0, `post-release-verify.yml` run 31549287269:

```
self-upgrade proof (linux/amd64):  failure
self-upgrade proof (darwin/arm64): failure
resolve-tag, verify-supply-chain, gatekeeper (x2), notarized-suite: success
```

Failing log, verbatim:

```
task: cosign not found. This target verifies the downloaded prior release binary's cosign
bundle with it BEFORE making the file executable. CI installs it via
sigstore/cosign-installer; locally: brew install cosign.
task: precondition not met
Process completed with exit code 201
```

Phase 4 plan 04-05 (commit 59bc137) added a cosign verify-before-execute step
and a fail-closed `command -v cosign` precondition to `verify:self-upgrade`
(Taskfile.yml:2583-2584), but never added the installer step to the job that
invokes it. The precondition is correct and load-bearing — it failed closed
exactly as designed. The bug is a **missing installer**, never an over-strict
guard.

## The invariant this defect violated (verified against the tree, 2026-08-11)

Every `verify:*` target with a `command -v cosign` precondition, mapped to the
job that invokes it:

| Taskfile target | `command -v cosign` precondition | Invoking job | cosign-installer steps |
|---|---|---|---|
| `verify:release-assets` (L2383) | yes | `verify-supply-chain` | 1 (L225) |
| `verify:self-upgrade` (L2583) | yes | `self-upgrade` | **0 — the defect** |
| `verify:notarized-suite` (L3103) | yes | `notarized-suite` | 1 (L428) |
| `verify:gatekeeper` | **no** | `gatekeeper` | 0 — correct, needs none |

So the property is exact and already holds for three of four jobs: **a job whose
`run:` body invokes a `task` target that declares a `command -v cosign`
precondition must contain exactly one `sigstore/cosign-installer` step, pinned
to a 40-hex SHA with a trailing version comment, and every such pin in the file
must be byte-identical.** Adding the installer to `self-upgrade` makes the
property universally true; the Task 1 test makes it enforced.

The one pin, already used twice in this file (lines 225 and 428):

```yaml
      - name: Install cosign
        uses: sigstore/cosign-installer@6f9f17788090df1f26f669e9d70d6ae9567deba6 # v4.1.2
```

Task 1 writes the guard and demonstrates it RED against the **real, unfixed

## Tasks

### Task 1 — Pin the invariant with a shape test (RED)

**Files:** `internal/upgrade/taskfile_shape_test.go`

**Why this file:** it already owns the cross-file workflow↔Taskfile machinery
this guard needs — `workflowRunStep`/`workflowJobYAML`/`workflowFileYAML`
(L1230-1241), `stripRunBodyNoise` (L1275), `gatekeeperTaskfileRoot` /
`gatekeeperPrecondition` (L1629-1648), and the `taskfilePath` const (L31).
`postReleaseWorkflowPath` (declared in `release_workflow_shape_test.go`) is
package-visible from here. Reuse all of these; do not reimplement any of them.

**Action:**

1. One additive field on the existing `workflowRunStep` struct:
   `Uses string \`yaml:"uses"\``. Additive only — `checkStepInvokesTask` and
   `TestWorkflowRunBodiesInvokeTask` read `Name`/`Run` and are unaffected.

2. Add a new section, `// --- quick 260811-s5o: cosign-installer coverage guard ---`,
   containing three pure `parseX(src) (T, error)` cores following this file's
   established discipline — every core returns a non-nil error, never a usable
   zero value, when its target is absent:

   - `parseCosignRequiringTaskTargets(src string) (map[string]bool, error)` —
     decode Taskfile source with `gatekeeperTaskfileRoot`; collect every task
     name whose `preconditions:` list contains an entry whose `sh:` equals
     `command -v cosign` after `strings.TrimSpace`. Error when the YAML fails
     to parse, when `tasks:` is empty, or when **zero** targets match.
   - `parseWorkflowJobsAllSteps(src string) (map[string][]workflowRunStep, error)` —
     decode with `workflowFileYAML`; error on parse failure or zero jobs.
   - `taskTargetsInRunBody(body string) []string` — run `stripRunBodyNoise`
     first (so a `#`-prefixed comment line can never masquerade as an
     invocation — this file's existing house rule), then capture the target
     from each line matching a capturing variant of `taskCallLineRe`
     (`^task\s+([A-Za-z0-9:_.-]+)$`). Pure helper, no error return.

   Plus the raw-source pin regex:
   `var cosignInstallerPinRe = regexp.MustCompile(`uses:\s*(sigstore/cosign-installer@[0-9a-f]{40})\s+#\s*(v\d+\.\d+\.\d+)\s*$`)`
   — the trailing version comment is stripped by the YAML decoder, so pin-shape
   is checked against raw source, exactly as this package already does for
   `actions/attest-build-provenance` (`release_workflow_shape_test.go` L786-792).

3. `TestCosignRequiringJobsInstallCosign` reads both real files off disk and
   asserts, in this order:

   - `cosignTargets` is non-empty (`t.Fatalf` on the parser error).
   - For each job id in `post-release-verify.yml` (iterate **sorted** ids for
     deterministic output): union the `taskTargetsInRunBody` results across its
     steps; the job *requires cosign* iff any invoked target is in
     `cosignTargets`. Count its steps where
     `strings.HasPrefix(step.Uses, "sigstore/cosign-installer@")`.
   - **Positive assertion (the point of this guard):** for every
     cosign-requiring job that count MUST equal exactly 1 — `t.Errorf` naming
     the job id, the observed count, and the specific target that requires
     cosign. Not "no job is missing an installer"; an exact count per job.
   - **Non-vacuity floor:** if the derived cosign-requiring job set is empty,
     `t.Fatalf` — a broken run-body parse must go red, never pass silently.
   - **Pin uniformity:** collect every `cosignInstallerPinRe` match from the raw
     source. Assert the match count equals the total installer-step count found
     via YAML across all jobs (an unpinned, branch-pinned, or comment-less
     installer decodes as a step but matches no line, so the two counts diverge
     and the test goes red). Assert exactly one distinct SHA and exactly one
     distinct version comment across all matches.
   - `t.Logf` the derived job→target mapping so a future reader sees what the
     guard actually covered.

   Do **not** hardcode a job list, and do not hardcode which targets need
   cosign — both are derived from the two files at runtime. A future
   cosign-requiring target is covered automatically; that is the whole point.

4. `TestCosignInstallerGuardParsersFailLoudly` — the non-vacuity companion,
   modelled on the existing `..._MissingTargetIsError` / `...FailLoudly` tests
   in this file. Table of cases, each expecting a non-nil error:
   `parseCosignRequiringTaskTargets("")`; `parseCosignRequiringTaskTargets` fed
   synthetic Taskfile source with a `tasks:` map whose only task declares
   preconditions that do **not** include cosign; `parseWorkflowJobsAllSteps("")`.

**Verify:** the new guard goes RED against the unfixed tree, naming the
offending job, and the companion passes:

```bash

rg -q '^--- FAIL' "${TMPDIR:-/tmp}/cosign-red.log" \

```

**Done:** `RED-CONFIRMED` printed, and the recorded failure message names the

## Must not

- **Touch `Taskfile.yml`.** The `command -v cosign` precondition on
  `verify:self-upgrade` is correct and load-bearing; it failed closed exactly
  as designed. Do not weaken it, remove it, make it conditional, or downgrade
  it to a warning.
- **Add an installer to the `gatekeeper` job.** `verify:gatekeeper` declares no
  cosign precondition (verified above) — it needs none, and the Task 1 guard
  correctly does not require one there.
- **Use a different cosign-installer SHA or version comment** than the two
  siblings already use.
- **Hardcode a job list or a target list in the Task 1 test.** The guard must
  derive both from `Taskfile.yml` preconditions and workflow `run:` bodies at
  runtime; a hardcoded list is one refactor away from being silently untrue.
- **Ship a negative-only assertion.** The guard asserts an exact per-job
  installer count of 1 and single-pin uniformity — never merely "no job is
  missing one," which passes vacuously the moment its anchor stops matching
  (repo rule 84d1gfpywd).
- **Put `[ci skip]` or `[skip ci]` in any commit message** (repo rule
  f18zrdsgx5). Ruleset `protect-main` requires 6 status checks; a skipped
  commit as PR head permanently blocks the PR.

## Scope of proof

This guard reads workflow and Taskfile **source**. It proves the installer step
is declared, pinned, and unique per cosign-requiring job. It cannot prove the
action resolves or that `cosign` lands on `PATH` at runtime — that evidence
comes from the next real `post-release-verify.yml` run, where the two
`self-upgrade proof` legs must go green.
