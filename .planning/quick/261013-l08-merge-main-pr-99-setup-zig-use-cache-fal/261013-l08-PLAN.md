The orchestrator asked for ONE `git merge --no-ff origin/main` commit. This plan runs the merge as
`git merge --no-ff --no-commit origin/main` and then `git commit -F <message file>`. That produces the same single
two-parent merge commit (MERGE_HEAD is set when the commit runs), but it lets the executor assert the staged path
set while `git merge --abort` is still safe, which is the 261013-esj shape. The merge command runs as its own Bash
call with no `cd` and no chained commands, as the git-merge-guard hook requires.
