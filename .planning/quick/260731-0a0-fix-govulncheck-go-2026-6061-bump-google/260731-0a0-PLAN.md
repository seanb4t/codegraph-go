<decision_record>
## Version selection: v1.82.1, not v1.83.0

**Decision: take `google.golang.org/grpc@v1.82.1`.**

Rationale: v1.82.1 is the minimum version that carries the fix for GO-2026-6061 (GHSA-hrxh-6v49-42gf),
and it is a patch release on the line already in the build list — so it changes the fewest things that
could ripple into the reproducibility gate, the SBOM, or the CGo build. v1.83.0 is available and also
fixed, but a minor bump buys nothing here and widens the blast radius on a repo whose CI is already
red in two other places. No other `go.mod` requirement forces a floor above v1.82.1 (grpc is pulled in
transitively via `sigstore-go` -> `rekor-tiles/v2`, and `grpc-gateway/v2 v2.29.0` / `otel v1.44.0` are
both satisfied by the v1.82 line).

Live `go list -m -versions` confirms v1.82.1 is published. Go's MVS takes the maximum across all
requirements, so raising this single `// indirect` line raises the floor for the whole build.

## Reachability finding: treated as real, not dismissed

The triage note flagged the govulncheck reachability trace as SUSPECT (an over-broad call edge through
`sync.Once.Do`). That does not change the action, and this plan does not attempt to re-litigate it.
`go mod why -m google.golang.org/grpc` confirms an independent, unambiguous chain:
`internal/upgrade` -> `sigstore-go/pkg/verify` -> `rekor-tiles/v2/pkg/generated/protobuf` -> `grpc`.
The bump is warranted regardless of which specific edge the tool drew.
</decision_record>
