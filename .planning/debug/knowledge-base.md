## perf-gate-throughput-regress — CI perf gate reported a stable ~10.6% throughput regression that did not exist
- **Date:** 2026-07-31
- **Error patterns:** throughput regressed, regression gate failed, files/s below baseline, perf regression gate PERF-02 INDX-06, stable reproducible regression, verdict oscillates near threshold, benchmark slower than baseline
- **Root cause(s):** AND-gate, both required. (1) data/config — `tools/bench/baseline.json` was recorded on darwin/arm64 while the gate job runs on ubuntu-latest (linux/amd64); a same-platform control across the accused commit range measured +0.73%, i.e. no code regression at all; (2) code — `internal/bench/regression.go` `CheckRegression` compared only `FilesPerSec`/`PeakRSSBytes` and never read the `GOOS`/`GOARCH` the runner faithfully recorded, so it accepted a cross-platform comparison silently. Neither alone is visible: a matching baseline would have made the missing check a latent defect, and the check alone would have had nothing to reject.
- **Fix:** Reject a GOOS/GOARCH mismatch in `CheckRegression` before any numeric comparison (platform validity precedes numeric validity; unattributed on both sides still matches). Add a dispatchable `rebless` job to `bench.yml` that records a candidate baseline on ubuntu-latest — the gate's own runner class — self-verifies it with a second independent measurement, and publishes it for a human to commit (`-rebless` stays the sole writer, D-05). Add `-trials N` (default 3) so neither the baseline nor the gating measurement is a single sample, with `median_of_trials` recorded as provenance.
- **Files changed:** internal/bench/regression.go, internal/bench/regression_test.go, internal/bench/metrics.go, tools/bench/runner/main.go, tools/bench/runner/main_test.go, .github/workflows/bench.yml, .github/workflows/ci.yml, tools/bench/BASELINE.md
- **Why not caught:** No gate existed for this class. All 8 existing `CheckRegression` subtests asked "is the tolerance arithmetic right?"; none asked "are these two numbers about the same thing?" — provenance is invisible to tests written against the happy shape of the data. Typecheck/lint/vet/review could not have caught it: the code was well-formed and did exactly what it was written to do. `tools/bench/BASELINE.md` had documented the requirement in prose since the baseline was captured ("tolerance bands assume a consistent measurement host across baseline and gate runs") and stopped nothing, because there was simultaneously no mechanism to record a baseline on the CI runner class. Worse than a missing gate: the gate did not fail, it produced a confident wrong number, costing three rounds of triage and two superseded conclusions before anyone questioned the yardstick.
- **Recurrence guard:** Regression test `internal/bench/regression_test.go:TestCheckRegression` — 6 platform cases (fully-mismatched, each single-field neighbour, the matching pair so an always-reject guard cannot pass, both unattributed), verified by killing 3 mutants of the guard. Sampling floor pinned by `tools/bench/runner/main_test.go:TestDefaultTrialsIsAtLeastThree` and `TestParseFlags_Defaults`. Mechanism: `bench.yml`'s `rebless` job makes recording on the correct runner class possible for the first time and refuses to publish a candidate that is not reproducible on it. Provenance surfaced via `Metrics.median_of_trials` and the rebless job's delta table, which flags platform and corpus changes explicitly.
- **Transferable lesson:** A tight, reproducible measurement proves the signal is *systematic*, not that the accused caused it. Stability discriminates signal from noise; it does not discriminate between competing explanations of the signal — "the code got slower" and "the yardstick came from a different machine" predict the identical tight cluster. Before bisecting for a cause, confirm the measurement is capable of detecting that cause, and run a control that varies only the accused. Applies to any threshold gate comparing a live measurement against a recorded artifact: check the artifact's provenance is commensurable *before* trusting the delta.
- **Known gap (not fixed):** `CheckRegression` still does not compare `Metrics.Repo` (corpus identity). A baseline reblessed with a different `-count`/`-seed` would reproduce this exact bug in a different field. Guarded only by convention and by the rebless summary table today.

## resume-matcher-not-firing — a correctly-registered SessionStart `resume` hook appeared never to fire; it was firing all along
- **Date:** 2026-08-13
- **Error patterns:** hook does not fire, matcher not firing, SessionStart:resume missing, zero hook events in transcript, silent non-dispatch, no error and no crash, `claude --resume` / `--continue` / `/resume`, nudge text absent from resumed context, hook registered but inert, `${CLAUDE_PROJECT_DIR}` suspected, hooks.json vs settings.json shadowing, NUDGE-01, D-07
- **Root cause(s):** AND-gate, both required, neither visible alone. (1) environment/tooling — Claude Code 2.1.229 suppresses a SessionStart hook's context injection AND its transcript `hook_success` record when the hook's stdout is byte-identical to context already injected in that session; `session-nudge.sh` emits one constant line for every source, so its `resume` dispatch is always the suppressed case, and the resulting transcript is byte-indistinguishable from "the matcher never fired"; (2) data/observation — the verification oracle was a grep of the resumed session's transcript for SessionStart hook events, which is structurally blind to a suppressed dispatch and returned a false negative that the evidence artifact then hardened into "a real, reproducible gap, not a rehearsal methodology error." With per-source stdout the suppression never engages and the same oracle reports correctly; with a context-based oracle the suppression is present but harmless. The registration, the script, and the requirement on the resume path were never broken.
- **Fix:** No change to `session-nudge.sh` or the matcher registration — neither is defective and the runtime behavior is upstream and benign (it suppresses a redundant re-injection of text already in context). Retracted the false finding in `NUDGE-live-session.md`, documenting the mechanism, both oracles, the ruled-out alternatives, and an explicit note that transcript grep is NOT a valid oracle for SessionStart dispatch under ANY matcher (including `startup`); marked the follow-up resolved-and-not-a-gap rather than deleting it so the retraction stays legible; replaced STATE.md's false blocker with the resolution; added `TestSessionStartRegistersBothDocumentedEntryPoints` pinning the matcher SET.
- **Files changed:** .claude/skills/codegraph/verification/NUDGE-live-session.md, .planning/STATE.md, internal/agents/hookpackage_test.go
- **Why not caught:** No gate existed for this class, and the one gate that looked relevant was structurally incapable. `TestHookRegistrationMatchesFragmentAndScript` asserted that settings.json equals the hooks.json fragment and that every command resolves to an existing executable — but never WHICH matchers are present, so deleting the entire `resume` entry from both files keeps every assertion satisfied (verified: that mutant PASSED the pre-existing suite). Typecheck/lint/vet/build could not have caught it — nothing was malformed. Code review could not have caught it — the registration is correct and the reviewer would have had the same false evidence artifact in hand. The failure was in the *verification method*, and the artifact recording it explicitly pre-empted the correct diagnosis by asserting it was "not a rehearsal methodology error."
- **Recurrence guard:** Two tests in `internal/agents/hookpackage_test.go`. `TestSessionStartRegistersBothDocumentedEntryPoints` pins the matcher set to exactly {startup, resume} — killing the deletion the false finding invited, plus its boundary neighbors (duplicate entry, widened set with `clear`, matcher-less catch-all). `TestNudgeLiveSessionEvidenceRetractsResumeFailureClaim` pins the corrected evidence artifact — it fails if any of the four retracted claims is re-inserted verbatim, or if the mechanism word "suppress" is stripped (a retraction without its explanation reopens the door). 6/6 mutants killed, zero survivors; RED-then-GREEN confirmed (7 assertion failures pre-fix).
- **Transferable lesson:** Before concluding a component does not run, prove your oracle can observe it running. Absence of evidence in a log is a claim about the log, not about the world — and the transcript is the runtime's own artifact, so a runtime that suppresses output suppresses the evidence of suppression too. The discriminating move was an oracle *outside* the suspect instrument: an append-only log written by the hook itself, plus asking the resumed model what it could see. Second lesson: when a symptom needs two conditions, every single-variable probe against one condition comes back "refuted" and looks like progress while the diagnosis stalls — three correct-and-useless refutations (`${CLAUDE_PROJECT_DIR}`, hooks.json shadowing, settings scope) preceded the real one. Third: an evidence artifact that asserts its own methodology is sound ("not a rehearsal methodology error") is the highest-value claim to attack first, not the one to accept.
- **Known gap (not fixed):** The dedup's exact scope is uncharacterized — whether it compares against the whole context or only prior SessionStart injections, and whether a compacted-away startup nudge would let an identical resume nudge through. All seven probes used headless `-p` mode on Claude Code 2.1.229/darwin; interactive `/resume` and `--continue` were never exercised (the human-verify spot-check was waived), and the behavior may be version-specific. n=1 per probe configuration.

## skill-discovery-not-listing — a project skill reported missing from a fresh session's catalog was listed all along, with its description silently dropped
- **Date:** 2026-08-13
- **Same class as `resume-matcher-not-firing` (directly above), same reporting session, same rehearsal, same invalid oracle: a grep of a session transcript producing a false negative about a mechanism that was working.** Read both together — the shared lesson is restated at the end of this entry.
- **Error patterns:** skill not listed, skill not surfaced, not in skill catalog, project skill not discovered, `.claude/skills/*/SKILL.md` ignored, correctly placed and committed but absent, skill listing system reminder missing entry, no error and no warning, silent absence, skill never triggers, skill has no trigger signal, bare catalog entry, description missing from listing, SKILL-03, agentskills.io description limit
- **Root cause(s):** AND-gate, both required, neither sufficient alone. (1) environment/tooling — Claude Code renders the available-skills catalog into an attachment capped near 45,000 characters (measured 44,976–45,014 across four independent sessions, admitting **exactly 173** descriptions in every one) and emits every entry past the cap as a **bare name with no description**; this operator's ~238-skill installation saturates the cap, and project-scoped `.claude/skills/` entries are appended after all personal and plugin skills, so a repository's own skill is degraded by construction. (2) data/observation — the verification oracle was a grep of the rehearsal session's transcript, and a degraded entry renders as `- codegraph` (no colon, no description text) rather than `- name: description`, so every natural spelling of that grep matched nothing and returned a false negative, which `SKILL-03-rehearsal.md` then hardened into "the session's own skill catalog … does not list the `codegraph` skill at all." The cap alone would have produced a degraded-but-listed entry a correct oracle would have described accurately; the oracle flaw alone would have had nothing to misreport. Together they named the wrong subsystem. Project-skill discovery was never broken — that same transcript contains the entry.
- **Fix:** Cut `.claude/skills/codegraph/SKILL.md`'s frontmatter description from 299 to 110 bytes, kept trigger-shaped and pure-ASCII (byte-counted, so an em dash costs three), landing inside the measured admission band (65 and 100 admitted; 130/160/200/250 degraded). The upstream cap is not ours to fix; description length is the only lever this repository holds. Retracted the false finding in place — not deleted — at all three sources carrying it (`SKILL-03-rehearsal.md`'s claim and the Verdict caveat restating it, `NUDGE-live-session.md`'s follow-up item, `.planning/STATE.md`'s blocker entry), each stating what was actually observed and why the grep missed it.
- **Files changed:** .claude/skills/codegraph/SKILL.md, .claude/skills/codegraph/verification/SKILL-03-rehearsal.md, .claude/skills/codegraph/verification/NUDGE-live-session.md, .planning/STATE.md, internal/mcp/skill_claims_drift_test.go
- **Why not caught:** No gate existed for this class, and the one that looked relevant was calibrated to the wrong number. `TestSkillFrontmatterIsSpecCompliant` checked the description against agentskills.io's **published** 1024-character maximum — ~8x looser than the real operative ceiling — so a 299-char description was comfortably legal by the documented contract while losing its description in practice. A gate calibrated to a documented limit cannot catch a violation of an undocumented one. Typecheck/lint/vet/build could not apply: nothing was malformed. Code review could not apply: a reviewer holding the same hardened artifact would have gone looking upstream for a discovery bug, which is exactly what happened. Deeper cause: SKILL-03's acceptance criterion was behavioral ("the session picks codegraph_explore first") and passed, while the property that actually mattered — the skill reaching the session with a usable trigger signal — was never a criterion at all.
- **Recurrence guard:** `TestSkillDescriptionSurvivesSkillListingCap` in `internal/mcp/skill_claims_drift_test.go` pins the description at <=120 bytes (`skillDescriptionListingMaxChars`, measurements documented inline so the next person to loosen it must argue with data). Three anti-decay properties: it reads the same field the spec-compliance test reads so the two cannot drift; it `t.Fatalf`s unless its bound is strictly tighter than `skillDescriptionMaxChars`, so it can never silently become a restatement of the looser gate; and it `t.Fatalf`s on an empty description, killing the degenerate fix (delete the description) that would satisfy a maximum-length bound while reproducing the exact defect. Bound pinned between the nearest observed admit (100) and nearest observed degrade (130). RED-then-GREEN confirmed, no test weakened. The retractions guard the observation failure.
- **Transferable lesson:** *Same as `resume-matcher-not-firing`, earned a second time in the same rehearsal — which is the point.* A transcript grep is a claim about the grep, not about the world. Both findings were false negatives from the same oracle: the first blind to a **suppressed** hook dispatch, the second blind to a **degraded** catalog entry rendered in a different shape (`- name` instead of `- name: description`) than the one the grep was written against. Before recording "X did not happen" from a transcript search, demonstrate the same search can find X when X *does* happen, or use an oracle outside the transcript entirely. Second lesson, specific to this one: when a published spec limit and an unmeasured runtime budget both constrain a value, the spec limit is the one you will write a test against and the runtime budget is the one that will bite — a passing gate against a documented maximum is not evidence the value works. Third: "absent" and "present but degraded" are different diagnoses pointing at different subsystems; a symptom report should say which was observed, because a report of absence sends the next reader upstream to the wrong component.
- **Known gap (not fixed):** The upstream selection algorithm is uncharacterized — 173 admitted descriptions is stable across every measured session, but why that count rather than a pure character budget is unknown, and selection order is provably not display order (bare and described entries interleave). Admission is greedy competition for leftover budget, so **no length guarantees admission** — headroom depends on the operator's installed-skill count, which this repository does not control; the guard enforces competitiveness, not success. All measurements are one machine, Claude Code 2.1.229/2.1.231, darwin. On a normal ~30-skill installation the cap is never reached and the original 299-char description would have rendered fine, so this fix trades trigger detail for survival on loaded machines.

## codegraph-skill-not-listed — a skill reported absent from the listing after two working fixes; the listing was stale and the block read was not the listing
- **Date:** 2026-08-13
- **THIRD instance of the class recorded by `resume-matcher-not-firing` and `skill-discovery-not-listing` (both above), in the same repository on the same day.** All three: a claim about what an observation instrument showed, mistaken for a claim about the world; all three, the mechanism was working. Read the three together — the class, not the instances, is the finding.
- **Error patterns:** skill still not listed after the fix, absent from skill listing entirely, not even a bare name, listing shows exactly one entry, only one skill in the catalog, skill listing did not update after settings change, restarted the binary and nothing changed, skillListingBudgetFraction raised but no effect, fix not visible after restart, silent absence, no error and no warning, `isInitial` / `skillCount` / delta skill_listing, SessionStart:resume, stale catalog, SKILL-03
- **Root cause(s):** AND-gate, two contributing causes, neither sufficient alone, and NO surviving product defect — both prior fixes (description 299→110 bytes; `skillListingBudgetFraction` 0.015→0.03) work, and the second eliminated the degradation class entirely (a fresh `claude-sonnet-5` session in this repo renders all 232 entries with descriptions, **zero bare**). (1) environment — `SessionStart:resume` does not recompute the skill catalog; the user's genuine binary restart RESUMED conversation 67ab93a5 (resume hook 14:06:53.154Z), replaying the `isInitial: true` attachment recorded 00:32:49Z, 13h before the description fix and 13.5h before the settings change, in which codegraph is BARE (1 of 61 degraded of 234). A resumed session is structurally incapable of observing this class of fix no matter how genuine the restart. (2) data/observation — the block actually read ("exactly one entry, engram:curating-spine") is an `isInitial: false` DELTA carrying `skillCount: 1`, emitted 3.4s after the resume hook; Claude Code renders deltas under the byte-identical header the full catalog uses, so the most recent such block in a session is routinely a one-entry delta. Together they produced "absent entirely" — a state neither the stale listing (bare) nor the fresh listing (described) exhibits, which is why the symptom looked *stronger* than the prior session's and matched no known mechanism.
- **Fix:** No product change — shipping one would have been the real defect. Corrected the hardened false invariant instead: the prior session's "~45,000 characters / exactly **173** descriptions" was recorded in three places as a property of Claude Code, and direct measurement refutes it. The budget is `skillListingBudgetFraction` × the model's **context window**, exactly as that setting's schema text says — measured at three values on one installation in one day (23,984 chars on `claude-haiku-4-5`, 85 of 232 degraded; ~45,000 pre-change, 61–67 degraded; 59,681 at 0.03, **0 of 232** degraded and nothing truncated at all, since the budget then exceeds the full catalog). Relabelled as a measurement with the tier table in `SKILL-03-rehearsal.md`, plus a Method note recording both invalid oracles, the only valid check (new conversation → read `isInitial: true` from its own transcript → classify against the attachment's `names` array, not a regex, which mis-parses plugin names containing a colon), and the two-disjoint-instruments rule. Doc comment on `skillDescriptionListingMaxChars` and `TestSkillDescriptionSurvivesSkillListingCap`'s failure message corrected. The 120-byte bound is KEPT, rationale sharpened: it must hold at the **default** fraction on an ordinary machine, which this operator's raised setting no longer represents.
- **Files changed:** .claude/skills/codegraph/verification/SKILL-03-rehearsal.md, internal/mcp/skill_claims_drift_test.go
- **Why not caught:** No gate existed for this class, and no gate in this repository could have. The failure is in a *verification method*, not a program state: nothing was malformed (typecheck/vet/lint/build inapplicable), every test passed before and after because the product was never broken, and code review could not apply — a reviewer holding the same false artifact draws the same conclusion, which is exactly how this session began. `TestSkillDescriptionSurvivesSkillListingCap` was passing throughout, correctly. The deeper gap: the prior session shipped one operator's measurements into a doc comment, a failure message and an evidence artifact **as invariants**, and nothing required a measured environmental figure to be labelled as a measurement. Hardened false evidence is this repository's recurring defect and nothing was watching for it.
- **Recurrence guard:** `TestSkillListingEvidenceRecordsBudgetIsNotFixed` in `internal/mcp/skill_claims_drift_test.go` (verified passing 2026-08-13; RED-then-GREEN with 6 pre-fix assertion failures; 7 mutants, 7 killed, 0 survivors). It pins three properties of `SKILL-03-rehearsal.md` at once so no single edit restores the false model: the retracted phrasings must be **absent**; the replacement model must be **present** (both `skillListingBudgetFraction` and `context window`, which is what makes the fix non-deletion-only — removing the false claim without recording what the budget varies with is rejected); and the oracle traps (`isInitial`, `delta`, `resume`) must be **named**. Secondary: `skillDescriptionListingMaxChars = 120` still bounds the description at the default fraction. Tertiary: this entry, so a future Phase-0 recall surfaces all three invalid oracles before instance four is investigated.
- **Transferable lesson:** *Confirm with a second, disjoint instrument — not a second look through the first.* The investigation's own decisive probe read a transcript file it selected, parsed with a script it wrote, from a session it launched; one wrong assumption anywhere in that chain reproduces the two prior false findings exactly. What closed the session shared none of those links: a separate fresh `claude` process, started by a different actor through a different mechanism, asked with **no tools** what its *own* injected context showed — it quoted the description byte-for-byte. Second lesson: the rendered surface is **lossy by construction** — suppressed, degraded, stale and delta states all render as text indistinguishable from healthy, so "read more carefully" prevents nothing and the method must leave that surface entirely (read the attachment record, where `isInitial`/`skillCount` live). Third: interrogate the *axis* of a ruled-out hypothesis, not just its answer — "was it a real restart?" was answered honestly and correctly ("I restarted the binary") and still settled nothing, because the axis that mattered was new-conversation vs resumed-conversation. Fourth: a symptom that is *stronger* than a known mechanism predicts ("absent, not merely bare") is more often an artifact of the observation than a new mechanism — this session's own Symptoms section reasoned the opposite and was wrong.
- **Known gap (not fixed):** The exact budget formula is **bounded, not derived**. Three measurements are consistent with fraction × context-window, but the fraction was never varied under controlled conditions, and the prior 0.015 value is taken from the debug record rather than measured — do not cite the formula as established. Why the runtime emitted a codegraph delta at 14:00:00.601Z (file-change rescan? periodic?) is uncharacterized. What an interactive `/clear` does to the listing, as distinct from `--resume`, was never tested. All measurements are one machine, darwin, one day, one installed skill set.
