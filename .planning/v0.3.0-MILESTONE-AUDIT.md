## Cross-phase integration

Six questions, each answered by running rather than reading:

1. **VRFY-01 survives five phases** — the harness's SDK-independence is the
   milestone's central methodological claim and the easiest thing to break by
   accident. Zero go-sdk lines in the harness dependency graph.
2. **Legacy promise end to end** — REQUIREMENTS names dropping Legacy support
   "the single highest-consequence mistake available in this milestone." Zero of
   the 8 roster clients speak `2026-07-28`, so this is the clause protecting real
   users. Verified at both ends of the era range.
3. **The one genuinely cross-phase mechanism composes** — Phase 3's per-request
   `hasIndex` re-check drives `AddTool`/`RemoveTools` → `changeAndNotify` → an
   opted-in Modern listen stream (Phase 5). No single phase could verify that
   chain. `modern-listen-catalog-change` proves it on the wire, and was built
   `NoInitialize` + Modern `_meta` specifically so it cannot pass with a dead
   subscription.
4. **Scenario-count gate is live, not decorative** — `ExpectedScenarioCount = 28`
   matches 28 transcripts on disk and 28 enumerated subtests. The corpus grew
   23 → 24 → 26 → 27 → 28, stated deliberately at each step.
5. **No unowned regressions** — full suite clean at `GOMAXPROCS=4`.
6. **Accepted limitations honestly recorded** — all three read as
   accepted-and-surfaced, not resolved.

## Accepted limitations (carried, not gaps)

Recorded in STATE.md Blockers/Concerns:

- **Daemon extreme-load timeout tail.** The structural cause is fixed and proven
  (zero data races unconditionally; 6/6 clean at `GOMAXPROCS=4`; 52/52 real CI
  runs show no daemon failure on the actual runner class). Under pathological
  workstation load (~22 concurrent agent processes) one plain-timeout failure
  remains. CI load was ruled the governing standard for MAINT-02.
- **Daemon feedback-latency tradeoff.** The raised test budget buys contention
  tolerance at the cost of feedback speed (~65s clean, ~250s to fail under
  extreme load).
- **`GO-2026-5932`** — a real, accepted, **unmitigated** exposure in release
  tooling. `goreleaser`'s binary reaches `golang.org/x/crypto/openpgp` through
  `pipe/ko → google/ko → sigstore/cosign/oci → sigstore/rekor/pkg/pki/pgp`;
  upstream is unmaintained. Phase 4's advisory job surfaces it. Reported, not
  resolved.

## Decisions reversed mid-milestone (both by the maintainer, both recorded)

- **The byte-identity bar → reviewed diff** (Phase 2 D-01). Byte-identity cannot
  distinguish a cosmetic `omitempty` change from a `protocolVersion` change. The
  relaxed bar then caught a semantic regression on its first use —
  `edge-call-before-initialize` flipping from success to rejection — that a
  comparator would have buried among 22 transcripts of key-order churn.
- **The tool-modfile scan: blocking → advisory** (Phase 4 D-04). Implementation
  found `goreleaser` carries a permanently-unfixed vulnerability, so a blocking
  gate would have been red from its first run. The shipped design keeps
  *findings* advisory while still failing the job if **detection itself**
  regresses.
