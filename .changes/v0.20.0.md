## [v0.20.0](https://github.com/seanb4t/codegraph-go/releases/tag/v0.20.0) — 2026-11-19

### Features

- node, codegraph_node and the graph UI list the readers and writers of a data symbol with their access role, and the value that its initializer holds.
- C and C++ calls now resolve across files through quoted includes, and a call through a header prototype reaches its one definition in another file.

### Fixes

- The C and C++ extractor now indexes the functions, structs, typedefs and includes inside an extern "C" block or single declaration.
- A C++ function or method that returns a reference, such as `int &get(int i)`, `int &&get(int i)` or `int &Foo::get(int i)`, now gets a node with its parameters, arity and return type, and calls in its body resolve through its parameters and class.
- A store reached through a symlinked directory now uses the same swap and writer lock files as the store's real path, so two processes of this release that name one store differently exclude each other. A process from an older release and one from this release do not exclude each other on such a store until both run this release.
- codegraph sync now adds the call edges into a TypeScript or JavaScript function that becomes reachable from other files when it gains an export, or when a JavaScript file loses its last export, as a fresh index does.
- Sync now removes a package node when no file imports that package any more, so the store matches a fresh index.
- Commands that read or build the index now stop with an error when .codegraph or .codegraph/store is a symlink that leads outside the directory that holds .codegraph.
- Commands that open or rebuild the index now stop with an error when the store directory holds a symbolic link or holds files but no store, and codegraph opens its lock files, the .sync-pending marker and .codegraph/.gitignore without following a symbolic link.
- A running watcher stops, and writes nothing, when a pull turns .codegraph or its store into a link that leads elsewhere.
- Indexing, the file watcher and the staleness check of codegraph status skip the index when .codegraph or its store is a link to a directory with a plain name, together with the lock files and scratch directories beside the store, so no store file is indexed or marks the graph stale.
- A full index refuses a store path that is a symbolic link, also one that appears while the index builds, instead of putting the new store in place of the link and leaving the old store behind it.
- With --color=auto, a non-empty NO_COLOR now turns color off in piped or redirected output even when CLICOLOR_FORCE is also set.
- Colored output, path messages and prompts now show format and other invisible characters, such as bidi overrides, zero-width spaces and variation selectors, as <U+XXXX> escapes, path messages and prompts also show control characters as escapes, and invalid UTF-8 shows as U+FFFD.
- Claude Code hook commands are now shell-quoted, so a home directory or project directory with spaces no longer breaks them, and install, reinstall and uninstall still recognize entries written without quotes.
- The Codex install target now writes its global config.toml, AGENTS.md, hooks.json and PreToolUse guard under CODEX_HOME when it is set and not empty, and under ~/.codex otherwise; CODEX_HOME must be an existing absolute directory, `--target codex` stops with an error when it is not, `--target auto` and `--target all` skip Codex with a warning line and a skipped row (uninstall adds a note when Codex is still a requester of the shared skill), and anyone who sets CODEX_HOME should re-run `codegraph install -t codex -l global` because upgrade does not move files from ~/.codex.
- Installing or removing the Claude Code or Codex hooks no longer drops a hook of your own that shares a hook group with codegraph's hook, and Codex asks you to review that hook once.
- Installing the Claude Code or Codex hooks now stops with an error that names the key when the hooks value, a hooks event value that is not an array, or the permissions or permissions.allow value in settings.json or hooks.json has the wrong JSON type, and leaves the file unchanged, instead of overwriting the value.
- Install and uninstall now report failed or partial as an agent's status when its result has errors, and kept when nothing changed and some file was kept in place, an instructions file that holds nothing of codegraph's counts as not found so an agent that was never installed still reads not-configured, and install --print-config-style prints an error= field for an agent whose paths do not resolve, with no --target, --target all or --target auto, instead of stopping.
- Installing the Codex PreToolUse nudge now refuses a global guard path with a single quote, a backslash, a control character or invalid UTF-8, because Codex may run the hook under a shell that does not read the quoting as one word; set CODEX_HOME to another path or install with --location local.
- Global installs and uninstalls now refuse a relative HERMES_HOME, and a relative home directory with an error that says codegraph cannot find its global files, a relative XDG_CONFIG_HOME is ignored with a note as the XDG specification says, and the Claude Code hook install refuses a global hook path that is not valid UTF-8 and tells you to install with --location local, because JSON cannot hold such a path and the registration would not match on uninstall.

### Dependencies

- Move the embedded graph UI to SvelteKit 3.3.1 to fix two SvelteKit security advisories (GHSA-3r8g-jcqq-3p5j and GHSA-6cf5-gc4q-fm3x).
