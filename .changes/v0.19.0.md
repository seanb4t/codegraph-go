## [v0.19.0](https://github.com/seanb4t/codegraph-go/releases/tag/v0.19.0) — 2026-11-14

### Features

- The first codegraph sync after upgrading rebuilds an older index once, to add variables, fields, their references and the calls through function-valued variables.
- Index core-language variables and fields with scoped references and conservative callable bindings.

### Fixes

- An install or uninstall for Codex or Hermes stops with an error when it cannot read the existing configuration file, and no longer writes over it.
- A sync no longer counts a removed overload set twice, so the node count that `codegraph status` prints stays equal to the stored nodes.
- The worktree notice and the `status` worktree warning now advise `codegraph init`. They named `codegraph init -i`, which fails because `init` has no `-i` flag.
- A Python call to a name that a `from` import binds now has a `calls` edge to the declaration in the imported module, and a Python tree with no `pyproject.toml` or `setup.py` resolves its imports. Run `codegraph index --force` to add the edges to an existing index.
- A Go or TypeScript call to a parameter or a local no longer gets a `calls` edge to a package or imported function of the same name. Run `codegraph index --force` to remove the false edges from an existing index.
- One process now uses one store handle when it reaches the index through a symbolic link and through the real path. It opened the store twice before, with no error.
- callers, callees and impact answer for every definition of a name and say which definitions exist. The new --file flag selects the definitions in one file.
